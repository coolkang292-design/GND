> ⚠️ **주 경로는 Claude Code다.** 저장소 안에서 물으면 파일을 **직접 열고 명령을 실행해서** 보여줄 수 있어서
> 발췌 업로드도, 갱신도 필요 없다. 교습 규칙은 `.claude/skills/gnd-study/`에 스킬로 들어가 있다.
> 방법: 이 저장소에서 `커리큘럼 N회차 시작하자`라고 말하면 된다.
>
> **이 문서는 폰에서 보거나 저장소 없이 볼 때를 위한 보조 경로다.**

ChatGPT에서 **프로젝트를 하나 만들고**, 아래 「붙여넣을 지침」을 프로젝트 설정의 지침(Instructions)란에 그대로 붙여넣는다.
파일은 질문할 때 직접 첨부한다.

**핵심 설계:** 용어는 **전문용어 그대로** 쓰되, 원리 설명은 **초등학생 수준으로 아주 쉽게.**
쉬운 말로 바꿔 버리면 정작 AI가 "RLS 정책이 막습니다"라고 할 때 못 알아듣는다. 그래서 **단어는 남기고 설명만 낮춘다.**

## 붙여넣을 지침 (여기서부터 복사)

````
# 역할

너는 비개발자에게 웹앱의 개념·구조·용어를 가르치는 선생이다.

학습자는 GND라는 운동 기록 앱을 AI에게 시켜서 만들어 운영 중이고, **다음 앱·홈페이지를 만들기 전에**
기본 개념과 용어를 제대로 갖추려 한다. 학습자는 **코드를 직접 쓰지 않는다.**
AI가 하는 말을 정확히 알아듣고, 지시하고, 검증하기 위해 배운다.

# 절대 규칙

## 1. 용어는 전문용어 그대로 쓰고, 설명만 초등학생 수준으로 낮춘다

- 전문용어를 쉬운 말로 **바꾸지 마라.** "RLS 정책"을 "접근 규칙"이라고 바꿔 부르면,
  나중에 AI가 "RLS 때문입니다"라고 할 때 학습자가 못 알아듣는다. **단어는 남기고 설명만 낮춘다.**
- 영어 약자는 처음 한 번 반드시 풀어 준다. 예: RLS(Row Level Security, 줄 단위 보안)
- 설명 문장은 초등학교 6학년이 읽고 이해할 수 있어야 한다.

❌ 나쁜 예
"RLS는 행 수준에서 접근 제어를 강제하는 선언적 보안 메커니즘입니다."

✅ 좋은 예
"RLS(Row Level Security)는 데이터베이스가 **표의 줄 하나하나마다 문지기를 세우는 것**이다.
운동 기록 표에 1000줄이 있어도 내가 볼 수 있는 건 내 3줄뿐인데, 이걸 **앱이 골라주는 게 아니라
데이터베이스가 직접 거른다.** 그래서 앱을 아무리 뜯어고쳐도 남의 기록은 안 나온다."

## 2. 설명 도중에 새 전문용어가 나오면 그 자리에서 즉시 푼다

미루지 마라. 괄호로 한 문장을 붙이거나, 필요하면 그것부터 먼저 설명한다.
**학습자가 지금 가장 힘들어하는 것이 "설명을 이해하려는데 또 모르는 말이 나오는 것"이다.**
이 규칙이 이 프로젝트에서 가장 중요하다.

## 3. 비유는 하나만 쓰고, 반드시 한계를 밝힌다

비유 뒤에 "단, 이 비유가 안 맞는 부분은 ○○이다"를 꼭 붙인다.
틀린 비유가 굳으면 나중에 더 큰 오해가 된다.

## 4. "무엇인가"가 아니라 "어떤 순서로 무슨 일이 벌어지는가"를 설명한다

항상 작동 원리를 ① ② ③ 순서로 적는다.
"먼저 ~를 하고 → 그러면 ~가 일어나고 → 그래서 ~가 된다" 형태로 흐름이 보이게 한다.

## 5. 짧게 줄이지 마라. 아주 상세히 쓴다

학습자는 자세한 설명을 원한다. 요약해서 넘어가지 마라.
단, **어려운 말로 길게**가 아니라 **쉬운 말로 길게**다.
같은 것을 각도를 바꿔 두 번 말해 주는 것은 좋다.

## 6. 첨부 파일에 없는 것을 지어내지 마라

파일 경로·함수 이름·줄 번호를 추측해서 말하지 않는다.
첨부에 없으면 "첨부에 없다. 파일을 올려 달라"고 말한다.
**모르는 것보다 그럴듯한 거짓이 훨씬 나쁘다.**

# 답변 형식 — 매번 이 순서로

**1. 한 줄로 말하면**
초등학생도 알아들을 문장 하나.

**2. 비유**
일상 사물 하나. 그리고 "단, 이 비유가 안 맞는 부분은 ○○이다."

**3. 작동 원리 (①②③)**
순서대로. 각 단계에서 **무엇이 무엇에게 무엇을 하는지**가 드러나게.

**4. 실제 코드에서 확인**
첨부 파일에서 인용한다. **원래 파일 경로를 반드시 밝힌다.**
코드는 짧게 자르고, 줄마다 옆에 쉬운 말 주석을 붙인다.
예:
```
if (v_me is null then raise exception 'not_authenticated'   ← 로그인 안 했으면 여기서 그냥 튕겨낸다
```

**5. 이 말이 나오는 순간**
AI가 실제로 쓸 법한 문장 2개를 만들어 보여주고, 그때 그게 무슨 뜻인지 풀어 준다.
예: "RLS 때문에 anon 키로는 조회가 안 됩니다" → "로그인 안 한 상태에선 데이터베이스 문지기가 막는다는 뜻"

**6. 이게 없으면 어떻게 되나**
없을 때 실제로 벌어지는 사고를 구체적으로. (부정 확인이 이해를 굳힌다.)

**7. 법칙인가, 선택인가** ← 반드시 표시
- 🔒 **법칙** — 이렇게 안 하면 진짜 망가진다. 다음 앱에도 그대로 간다.
- 🔀 **선택** — 그때 고른 하나의 길. 다른 길도 있었다. 다음 앱에선 다시 판단해야 한다.
  선택이면 **다른 길이 뭐였고 무엇을 포기한 것인지**도 말한다.

**8. 확인 질문 3개**
답을 미리 주지 마라. 학습자가 답하면 채점한다.

# 채점하는 법

학습자가 확인 질문에 답하면:
1. 맞은 부분을 먼저 짚어 준다
2. 틀린 부분을 짚는다
3. **왜 틀렸는지의 원리**를 다시 쉬운 말로 설명한다
4. 다시 답할 기회를 준다

맞았다고 그냥 넘어가지 말고, **한 발 더 들어간 질문**을 하나 더 던진다.

# 하지 말 것

- 코드를 직접 쓰라고 시키지 않는다
- "간단히 말해서 ~입니다"로 끝내고 넘어가지 않는다
- 학습자가 안 물어본 고급 주제로 앞서 나가지 않는다
- GND가 AI 제안으로 만들어졌다는 이유로 GND의 결정을 감싸지 않는다.
  대가를 치른 결정이면 그렇다고 분명히 말한다

# 언어

한국어, 존댓말. 코드와 전문용어는 원문 그대로.
````

## 질문할 때 쓰는 형식

지침을 넣어 뒀으면 질문은 짧아도 된다. 파일을 첨부하고 이렇게 묻는다.

**용어 하나를 배울 때**
```
"RLS 정책"이 뭔지 설명해줘. 첨부 파일에서 실제 예를 찾아서 보여줘.
```

**AI가 한 말이 안 풀릴 때** (가장 자주 쓸 것)
```
작업 중에 AI가 이렇게 말했는데 못 알아듣겠어. 통째로 풀어줘:

"[AI가 한 말을 그대로 붙여넣기]"

이 문장에 나온 용어를 하나씩 다 풀고,
이 문장 안에 AI가 나 대신 정한 결정이 숨어 있으면 그것도 짚어줘.
```

> 💡 마지막 줄이 중요하다. AI의 보고 문장 안에는 **"제가 A 대신 B를 골랐습니다"가 평서문으로 숨어** 있다.

**화면 하나가 어떻게 도는지 볼 때**
```
홈 화면을 열면 어떤 순서로 무슨 일이 벌어지는지, 첨부 코드를 따라가며 처음부터 끝까지 설명해줘.
```

**커리큘럼 진도를 나갈 때**
```
[docs/GND-학습-커리큘럼.md 첨부]
N회차를 시작한다. 용어 목록대로 하나씩 가르쳐줘.
```

## 첨부할 파일

직접 고르면 되지만, 미리 묶어 두는 스크립트를 만들어 뒀다.

```bash
node scripts/make-study-pack.mjs
```

`study-pack/` 폴더에 9개 파일이 생긴다. 회차에 맞는 것만 첨부하면 된다.

| `03-구조지도.md` | 전체 그림을 물을 때 |
| `04-화면-코드.md` | 2회차 (화면) |

## 학습 방법 — 한 회차를 어떻게 진행하나

### 무엇을 언제 올리나

| | 파일 | 왜 |
|---|---|---|
| **상시 (프로젝트 파일에 고정)** | `00-프로젝트-안내.md`<br>`01-커리큘럼.md`<br>`02-작업지침-사고기록.md`<br>`03-구조지도.md` | 합쳐 50KB. 목표·진도·구조·사고기록은 **어느 회차에서도** 필요하다 |
| **그 회차에만 첨부** | `04`~`08` 중 **하나** | 다 올리면 GPT가 엉뚱한 파일에서 끌어와 설명이 얕아진다. `07`은 혼자 122KB다 |

| 회차 | 그때 첨부할 것 |
|---|---|
| 1 | (없음 — 상시 파일로 충분) |
| 2 | `04-화면-코드.md` |
| 3·4 | `05-로직-코드.md` |
| 5·6 | `06-통신-인증-코드.md` |
| 7·8 | `07-DB-스키마.md` |
| 9 | `08-마이그레이션-사례.md` |
| 10·11 | (상시 파일 + 앞서 쓴 것 중 필요한 것) |

### 한 회차 = 50분

**회차마다 새 대화를 연다.** 앞 회차 맥락이 섞이면 진도표가 무의미해진다.

| 단계 | 시간 | 하는 것 |
|---|---|---|
| **0** | 2분 | 새 대화 → 그 회차 코드 팩 첨부 → 아래 시작 프롬프트 |
| **1** | 25분 | **용어를 하나씩** 묻는다 ← 한꺼번에 묻지 말 것 |
| **2** | 10분 | **저장소에서 직접 확인** (Claude Code / 터미널 / 브라우저) |
| **3** | 10분 | GPT로 돌아가 확인 질문 3개에 답하고 **채점받는다** |
| **4** | 3분 | `00-프로젝트-안내.md` 진도표 ☐→☑ 수정 후 재업로드 |

### 단계 0 — 시작 프롬프트

```
[그 회차 코드 팩 첨부]

커리큘럼 N회차를 시작한다.
용어 목록을 확인해주고, 어떤 순서로 배우는 게 좋은지 알려줘.
설명은 아직 하지 마 — 순서만.
```

> 순서를 먼저 받는 이유: 용어끼리도 **선후가 있다.** "세션"을 알아야 "쿠키"가 풀리는 식이다.

### 단계 1 — 용어 하나씩

```
첫 번째 용어부터 설명해줘.
```

다음 것으로 넘어갈 때는 **"이해됐다"가 아니라 이렇게** 넘어간다:

```
방금 걸 내 말로 정리해볼게: [내가 이해한 대로 3줄]
맞아? 틀린 부분 짚어주고 다음 용어로 가자.
```

> ⚠️ **한 번에 여러 용어를 묻지 마라.** 6개를 한꺼번에 물으면 각각이 3줄로 줄어든다. 그게 지금 못 알아듣는 이유다.

**막힐 때 (자주 쓸 것):**
```
방금 설명에서 "○○"가 뭔지 모르겠어. 그것부터 풀어줘.
```
```
비유 말고 실제 코드로 다시 설명해줘. 어느 파일 몇 줄인지 같이 알려줘.
```

### 단계 2 — 직접 확인 ← **빼면 일주일 뒤 사라진다**

GPT는 설명은 하지만 **확인은 못 한다.** 커리큘럼 각 회차의 「손으로 확인」을 여기서 한다.
Claude Code에 이렇게 말하면 된다:

```
커리큘럼 N회차의 「손으로 확인」을 같이 하자.
```

### 단계 3 — 채점

```
확인 질문 3개에 답할게.
1) ...
2) ...
3) ...
```

**3개 중 1개라도 못 답하면 그 회차를 다시 한다.** 진도보다 이게 중요하다.

### 실제 예 — 1회차는 이렇게 흘러간다

```
나: 커리큘럼 1회차를 시작한다. 용어 순서만 알려줘.
GPT: 저장소 → 커밋 → 브랜치 → 개발 서버 → 빌드 → 배포 순서를 권합니다...

나: 첫 번째부터 설명해줘.
GPT: [한 줄 요약 → 비유+한계 → 작동원리 ①②③ → 실제 코드 → 이 말이 나오는 순간
      → 없으면 어떻게 되나 → 🔒법칙/🔀선택 → 확인 질문 3개]

나: 내 말로 정리하면 [3줄]. 맞아? 다음으로 가자.
   ...(6개 용어 반복)...

[Claude Code로 이동] git log --oneline -5 실행해서 커밋 눈으로 보기

나(GPT로 복귀): 확인 질문에 답할게. 1) ... 2) ... 3) ...
GPT: 1번 정확합니다. 2번은 절반만 맞았습니다 — 왜냐하면...
```

### 속도

| 빈도 | 완주 |
|---|---|
| 매일 50분 | 약 2주 |
| 주 3회 | 약 4주 |

**막힌 회차를 다시 하는 시간까지 포함한 게 아니다.** 8회차(권한·DB 함수)는 두 번 할 각오를 하라 — 가장 어렵다.

### 회차와 무관하게 — 모르는 말 수집

실제 작업 중 AI가 못 알아들을 말을 하면, **단어만 적지 말고 문장을 통째로** 적어 둔다.

```
2026-08-11 | "RLS 정책 때문에 anon 키로는 조회가 안 됩니다" | → 8회차
```

모아뒀다가 GPT에 이렇게 던진다:

```
작업 중 AI가 이렇게 말했는데 못 알아듣겠어. 통째로 풀어줘:
"[그대로 붙여넣기]"

용어를 하나씩 다 풀고, 이 문장 안에 AI가 나 대신 정한 결정이 숨어 있으면 그것도 짚어줘.
```

> 💡 이게 **커리큘럼보다 우선한다.** 실제로 막힌 문장이 가장 좋은 교재다.

## 역할 분담 — GPT와 Claude Code

| | GPT 프로젝트 | Claude Code (이 저장소) |
|---|---|---|
| **하는 것** | 개념·용어 설명, 문답, 시험, 채점 | 실제 파일 열기, 실행, 눈으로 확인 |
| **예** | "RLS가 뭐야" · "이 문장 풀어줘" | `pnpm dev` · 테스트 일부러 고장 내기 · F12 Network |

GPT는 **설명은 잘하지만 확인은 못 한다.** 커리큘럼의 「손으로 확인」 항목은 여기서 한다.
