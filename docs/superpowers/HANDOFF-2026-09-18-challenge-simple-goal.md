## 6. 화면 확인에서 나온 것 — 판단이 필요한 것

### 6-1. 고쳤다 — 같은 목표를 두 이름으로 부르고 있었다

설정 화면은 `총 운동량`, 상세·참가자 줄은 `총볼륨`이었다. 사용자가 "총 운동량"으로
세운 목표를 상세에서 다른 이름으로 읽게 된다. `GOAL_TYPE_META.volume.label`을
**`웨이트 총 운동량`** 으로 통일했다(`src/lib/challenge.ts`).

안전한 이유: 이 세션 전까지 운영 `volume` 목표는 **0건**이었고(D2가 근거),
`총볼륨`을 단언하는 테스트도 없었다. 화면에서 `웨이트 총 운동량 20,000kg`로 바뀐 것을 확인했다.

### 6-2. ⛔ 화면 확인을 **못 한** 2건 — 원인은 이번 작업 밖이다

| 못 본 것 | 왜 |
|---|---|
| 완료 화면 기여 카드 `운동한 날 +1일` | 카드가 **아예 안 그려진다** |
| 피커의 `챌린지 미반영` 경고가 안 뜨는가 | 경고가 0건이지만 **근거가 되지 못한다** |

원인은 `src/app/(tabs)/record/page.tsx`의 목표 적재 이펙트다(2026-08-04, **이번
작업에서 한 줄도 안 바뀌었다**):

```ts
const active = (await getMyChallenges(userId)).find(
  (c) => c.status === "active" && c.myStatus !== "invited",
);
if (!active) return;
setChallengeGoals(goals.filter((g) => g.user_id === userId));
```

- **active 챌린지 중 맨 처음 한 개만** 읽는다(정렬이 없어 물리 순서다)
- `invited`만 빼고 **`dropped`는 통과시킨다**

A·B의 첫 active 챌린지는 `4주 챌린지`(2026-09-01~09-28, 진행 중)이고 둘 다 거기서
**`dropped`**(목표를 못 세워 빠졌다) · 그 방 목표는 **0개**다. 그래서
`challengeGoals = []` 이 되고,

1. `result.challengeGains.length > 0`이 false → **기여 카드가 통째로 안 뜬다**
2. `countsTowardChallenge`는 `categories === null`이면 **true를 돌려준다**(모를 때
   경고하지 않는 설계) → 경고 0건이 "`workout_days`가 전 분류를 덮어서"인지
   "목표를 못 읽어서"인지 **구분되지 않는다**

⚠️ **그래서 "경고가 안 떴다"를 확인으로 쓰지 마라.** `goalCategories`가 `any`에서
`ALL_CATEGORIES`를 돌려주는 것은 코드와 단위 테스트로만 확인됐다.

**이건 이번 범위가 아니다.** `record/page.tsx`는 안 바꿨고, 실사용자 중 영향받는
사람은 **0명**이다(진행 중 챌린지의 `dropped` 2행이 곧 픽스처 A·B다). 고치려면
`myStatus === "joined"` 로 좁히는 한 줄인데, 그래도 **`workout_days` 목표는 여전히
안 보인다** — 그때 골라지는 것은 `개발 확인용 챌린지`(웨이트 목표)다. 근본은
**기록 화면이 active 챌린지를 하나만 본다**는 것이고, 그건 별도 작업이다.

#### 확인하려면 (사용자 결정 필요)

active 챌린지가 **하나뿐인** 계정이 필요하다. `dev-fixture-c@gnd.local`(닉네임

### 6-4. 넣었다 — 시안 ④의 **진행 예시** 카드 (사용자 결정 D8)

`내 목표 확인` 화면 아래에 시안 그대로 넣었다 — `진행 예시` / `2 / 3 완료` /
월~일 동그라미 7칸 / `한 번만 더 하면 이번 주 목표 달성!`.

⚠️⚠️ **실적이 아니다. 실적을 끌어오지 마라.** 여기는 목표를 **세우는** 자리라
이번 챌린지 기록이 아직 없다. `weekPreview(주 N회)`가 채워진 칸을 **`N - 1`로
고정**한다 — 그래야 아래 문구가 항상 참이고("한 번만 더 하면"), 주 1회면
`0 / 1` + "한 번만 하면"으로 말이 바뀐다. 실제 세션 수를 쓰려면 챌린지 기간
조회가 필요한데, 그러면 **저장 전 시트가 네트워크를 한 번 더 때리고** 늦으면
카드가 빈 채로 깜빡인다. `goal-setup-flow.test.tsx`가 이 선을 단언으로 막는다.

- 순수 함수 `weekPreview`·`WEEK_LABELS` — `src/lib/domain/challenge-simple-goal.ts`
- 칸은 월요일부터(시안 순서), 앞에서부터 채운다. 특정 요일을 지목하지 않는다
- `<ul aria-hidden>` — 스크린 리더에는 `2 / 3 완료`와 아래 한 줄이면 충분하다
- **①(기본 목표) 화면에는 없다** — 시안이 ④에만 뒀다
- 화면 확인: 주 3회 → `2 / 3 완료`(월·화 금색), 주 4회 → `3 / 4 완료`(월·화·수).
  375px 가로 스크롤 없음

### 6-6. 세부 목표 3개 · 유산소 하루 기준 (사용자 결정 D9·D10)

**세부 목표 3개** — `MAX_DETAIL_GOALS` 2 → 3.

⚠️ 점수 성질은 **안 바뀌었다.** 결정 전에 사용자에게 설명한 두 가지를 여기 남긴다:
- 완료 목표 보너스는 **3개까지만** 인정된다(`COMPLETED_GOAL_BONUS_MAX`). 기본 1 + 세부 3 = 4라
  **네 번째 완료 목표는 보너스가 없다.**
- 달성률은 목표들의 **평균**이다(`achievementScore`). 목표를 더 걸수록 못 채운 줄이 평균을
  끌어내려 **점수가 낮아질 수 있다.** "많이 걸면 유리"가 아니다.

**유산소 하루 기준** — 목표 칸에 `주 / 하루` 토글이 붙는다(`basisChoicesFor`).
유산소는 **하루**로 열리고(`defaultBasisFor`), 그 밖은 주간 그대로다.
일수형(`*_days`)은 "하루에 몇 일"이 말이 안 돼서 토글이 아예 안 뜬다.

| 지킨 것 | 왜 |
|---|---|
| 저장은 **언제나 기간 총량** | `user_goals.target_value`의 뜻을 바꾸면 옛 챌린지 점수가 갈린다 |
| 기준을 바꾸면 **숫자도 환산** | "주 10km"에서 하루로 바꿨는데 10이 남으면 목표가 4배가 된다. 사용자는 단위만 바꿨다고 생각한다 |
| 하루 기본값을 따로 둔다(`perDay`) | 주간 기본을 주 N회로 나누면 `3.3km`가 첫 화면에 뜬다. 사람이 고를 법한 수여야 한다 |
| 목록 글자에 기준을 같이 적는다 | `10km`만으론 주간인지 1회인지 모른다 |
| 힌트는 **반대쪽**을 말한다 | 하루로 넣는 사람에게 1회 값을 되돌려 주면 아무 말도 아니다 |

#### ⚠️⚠️ `lockedTotal` — 편집만 해도 목표가 바뀌던 것을 막는다

전수 왕복 테스트가 **기존 버그**를 찾았다(하루 기준과 무관, 그전부터 있었다).
30일 챌린지의 40km는 화면에 `주 9.3km`로 뜨는데, 그대로 저장하면 **39.9km**가 된다 —
사용자는 아무것도 안 건드렸는데 목표가 깎인다. 소수 첫째 자리까지만 쓰기 때문이다.

그래서 `splitGoalsForEdit`가 **원래 총량을 `lockedTotal`로 들려 보내고**,
숫자를 안 고쳤으면 `buildGoalDrafts`가 그 값을 그대로 쓴다.
⛔ 숫자를 고치면 **반드시 지운다** — `goal-setup-flow.tsx`의 `setGoal`이
`perWeek`가 patch에 있으면 지운다. 안 지우면 이번엔 사용자가 바꾼 값이 무시된다.
`"어떤 기간·주 N회 조합에서도 왕복이 목표를 바꾸지 않는다"` 테스트가 7×5×4 조합을 돈다.

또 하나 — 편집으로 다시 열 때 **되돌린 값이 같은 총량으로 돌아오는 경우에만** 하루로 연다
(`prefillBasisFor`). 하루로 만든 목표는 언제나 여기 해당하고, 주간으로 만든 목표는
주간으로 열린다.
