## 1. 문제와 제1원칙

사용자는 유산소 운동 중 시계의 시작 버튼을 누르지 않으면 운동을 끝낸 뒤 수동 기록을 입력할 수 없다고 신고했다. 운동 중 오버레이에는 직접 시간 입력칸이 없고, 시간 증감 버튼과 시계만 있었다. 최소화된 기존 종목 카드에는 직접 입력 경로가 있었다. 이후 유산소뿐 아니라 시간을 잴 수 있는 모든 운동에 적용하도록 요청했다.

- 운동 기록의 필수 정보는 실제 운동량이다. 앱에서 시계를 시작했다는 사실은 수동 기록의 필수 조건이 아니다.
- 시계는 시간 측정의 선택 수단이다. 시계와 수동 입력 모두 기존 `durationSec`·`distanceKm` 초안으로 들어가게 한다.
- 별도 세션·저장 API·DB 열을 만들 필요가 없다. 기존 `finishTimedSet`은 시계가 멈췄거나 시작되지 않은 경우에도 세트 완료를 처리할 수 있다.
- 이번 범위는 **시간 측정 운동의 세트 시계 시작 생략**이다. 기록 화면의 **전체 운동 시작**은 기존처럼 필요하다.

`RecordNumberInput`은 입력 중의 문자열을 보관하므로 `5` → `5.` → `5.2`를 이어서 입력할 수 있다. 유효한 값은 매 입력 시 기존 변경 콜백으로 전달한다. 입력칸을 떠나지 않고 완료해도 최신 값이 저장된다. 빈 값은 0으로 처리하고, 음수·문자·무한값·초 60 이상은 이전 유효값을 유지하며 오류를 표시한다.

분 수정 시 기존 초를, 초 수정 시 기존 분을 유지한다. 시계가 돌 때 직접 입력칸은 숨기고, 정지하면 측정값을 수정할 수 있다. 기존 시간·거리 증감 버튼, 페이스, 휴식·다음 종목 흐름은 유지했다. 종목·세트가 바뀌면 입력 중 문자열도 해당 세트 값으로 교체한다. 기존 `field.timed` 표시를 기준으로 적용하므로 플랭크·매달리기·사이드 플랭크·핸드스탠드·월 싯 및 시간 측정으로 설정한 직접 만든 운동도 같은 경로를 따른다. 횟수형 운동의 입력은 기존대로다. 버티기 시계를 실제로 시작한 경우 마침이 세트 완료인 동작은 유지했다.

`record/page.tsx`, 저장 함수, DB, 인증·권한, 보상 계산은 수정하지 않았다. 기록은 기존 경로에서 초와 미터로 저장된다. 운영 함수 정의를 읽어 확인한 유효 운동 조건은 완료 세트의 시간 또는 거리가 양수인 경우다. **전체 세션 시간·보상은 서버 경과 시간을 따른다. 수동으로 32분을 입력한다고 전체 세션 경과 시간도 32분으로 바뀌지는 않는다.**
