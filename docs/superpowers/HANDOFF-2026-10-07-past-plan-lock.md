## 1. 지난 계획 잠금 (이번 배포)

**규칙 (사용자 지시 2026-10-07):** 어제 이전 계획은 수정·삭제·날짜 이동 모두 불가.
오늘 계획은 그날이 끝날 때까지 변경 가능. 이유 — 월간 완료율이
완료일 / (완료일 ∪ 계획일)이라, 놓친 계획을 지우거나 옮기면 완료율이 오른다.

### 무엇이 어디에 있나

| 층 | 내용 | 상태 |
|---|---|---|
| DB 트리거 `guard_past_workout_plan` | 사용자 요청(auth.uid() 있음)의 지난 계획 UPDATE·DELETE 거절. 원본 세션 삭제로 `source_session_id`만 비는 UPDATE는 통과 | 운영 적용됨(GPT 세션이 MCP로). 행동 확인함 |
| DB `cancel_program_enrollment` | 오늘 이후 회차만 지운다 | 운영 적용됨. 스냅샷으로 본문 확인 |
| 마이그레이션 파일 | `supabase/migrations/0116_lock_past_workout_plans.sql` — 운영 정의를 옮겨 적음 | ⚠️ 트리거 **이름** `[미검증]` |
| 달력 화면 | 지난 계획: 삭제·날짜 이동·「남은 일정 다시 잡기」 없음 + 잠김 안내 | 개발 서버 390px 확인 |
| 오류 문구 | `past_plan_locked` / `past_plan_date` → 사람 말 | 단위 테스트 |

### 남은 확인
- MCP 있는 세션에서 트리거 이름 확인 후 0116 파일 맞추기:
  `select tgname, tgtype from pg_trigger where tgrelid = 'public.workout_plans'::regclass and not tgisinternal;`
- 프로그램 그만두기 실화면 `[미검증]` — 지난 회차가 달력에 남는지(단위 테스트만 있음)
- 자정을 넘겨 운동을 끝내면 어제 계획 정리(삭제)가 트리거에 막힌다. 완료는 되고
  "예정표는 달력에서 직접 삭제해 주세요" 토스트가 뜨지만, 이제 그 삭제가 불가능하다.
  → 아래 2-1 결정과 함께 처리

## 2. 결정이 필요한 것

### 2-1. 놓친 프로그램 회차를 어떻게 이어가나 (사용자 결정 필요)
「남은 일정 다시 잡기」는 놓친 회차를 **미래로 옮기는** 기능이었다. 새 규칙과 정면으로
충돌해 운영 DB가 이미 거절하고 있었고, 이번 배포에서 버튼을 내렸다.
지금은 놓친 회차가 그대로 남고 프로그램은 다음 회차로 이어진다(회차 하나가 빈다).

| 안 | 내용 | 비용 |
|---|---|---|
| A. 지금대로 | 놓친 회차는 놓친 채로. 프로그램은 진행 | 없음 |
| B. 복제 이어가기 | 지난 회차는 '놓침'으로 남기고, 같은 처방을 미래에 **새 행**으로 깐다 | DB: `workout_plans_program_slot` 유니크(등록·주·회차) 때문에 새 RPC + 인덱스 변경 필요 |

추천: B. 기록(놓침)과 진행(완주)을 둘 다 지킨다. A는 18회 프로그램이 조용히 17회가 된다.

### 2-2. 자정 넘긴 운동 완료 처리
트리거 예외 추가 제안: "그 계획 날짜에 시작한 완료 세션이 있으면 삭제 허용" —
그날은 어차피 완료일로 세므로 완료율이 바뀌지 않는다. DB 변경이라 MCP 세션 필요.

## 3. 오늘 들어온 버그 신고 (2026-10-07 18:22·18:24, iPhone Safari 390×511~526, build 17:53)

### 3-1. "챌린지 생성자가 삭제를 할 수 없음" (5da574d7)
- 사실: 삭제(=취소) 기능은 있다. 방장 상세 머리의 ⚙(`aria-label="챌린지 관리"`) → 관리 시트 맨 아래
  「챌린지 취소하기」. 신고 동작흔적에 `cancel_challenge` 호출이 **없다** — 못 찾은 것으로 보인다.
- 가설: ① ⚙ 아이콘이 '설정'으로 읽혀 삭제를 떠올리기 어렵다 ② 관리 시트에서 취소가
  실시간 랭킹·초대 아래, 511px 화면에선 스크롤해야 보인다 ③ 사용자 말은 '삭제', 화면 말은 '취소'
  ④ 종료(completed)된 방은 취소 대상이 아니라 지울 방법이 없다
- 할 일: 픽스처로 방장 화면을 390×511에서 열어 ①~④ 중 무엇인지 확인 → 문구·위치 조정
  (예: 관리 시트 라벨 "챌린지 삭제(취소)", 목록 카드 ⋯에 삭제). ④면 '숨기기/보관' 범위를 사용자와 정한다

### 3-2. "중간 결과 공개 여부를 만들 때 선택 옵션에 넣기로 했는데 미구현" (c9a3c1d3)

  선택지 **아래** 「실시간 랭킹 공개」 스위치. 관리 시트에서도 시작 전까지 바꿀 수 있다.
- 가설: ① 이름 불일치(사용자 말 '중간 결과 공개' ↔ 화면 '실시간 랭킹') ② 511px 화면에서
