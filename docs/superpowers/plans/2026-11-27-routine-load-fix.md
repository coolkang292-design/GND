1. 퀘스트 카드가 떠 있으면 사용자가 루틴에 가는 길은 **퀘스트 아래 "내 루틴" 타일 하나뿐**이다
   ("운동 추가" 버튼은 접힌 목록 안에 숨어 화면 밖). 즉 **다음날 아침 실제 회원이 타는 길이 C 경로**다.

## 1. 문제의 본질 (제1원리)

**사용자가 "루틴 불러오기"를 누를 때 바라는 것 = "그 설계도대로 오늘 목록을 맞춰 줘"(교체).**
**코드가 하는 것 = "지금 목록에 없는 이름만 뒤에 붙여"(병합, 이름이 겹치면 지금 목록이 이긴다).**

뜻과 동작이 다르다. 버그는 저장 데이터가 아니라 이 **어긋남**에서 나온다.

그리고 "다음날"에 특히 잘 터지는 이유가 코드에 있다:

1. 다음날 기록 화면을 열면 **오늘의 퀘스트가 지난 운동을 목록에 자동으로 담는다**
   (`applySuggestion` → `repeat` → `addPastSession(recent.id)`, `suggestedForDayKey` 도장).
   이 목록은 **어제 실제로 한 값**이다 — 어제 루틴을 고쳐서 했다면 고친 값이다.
2. 사용자가 루틴을 부르면 `addRoutine` → `mergeImportedExercises(draft.exercises, imported)`.
   이름이 같은 종목(맨몸 스쿼트·힙 어덕션)은 **루틴 쪽이 버려지고 어제 값이 남는다.**
3. 토스트에 "중복 N개 제외"가 뜨지만 사용자는 "불러왔다"로 읽는다.

→ 시나리오 A(스쿼트 4세트 남음)·B(힙 어덕션 20회 남음)·C(다음날)가 **한 경로로 다 설명된다.**
DB 루틴 원본이 멀쩡했다는 사전 조사와도 맞는다 (원본은 안 바뀌었고, 화면에서 덮였다).

## 3. 코드에서 새로 찾은 것 (지시서에 없음)

1. **퀘스트 카드 아래 "내 루틴" 타일 경로는 더 나쁘다** `[미검증]`.
   `startCustomList("routine")`가 기존 키를 적어 두고 → `addRoutine`이 병합(겹치는 이름은 루틴 쪽 버림)
   → 효과(effect)가 **기존 키를 전부 걸러낸다.** 결과: 겹치는 종목이 **양쪽에서 다 빠져 목록에서 사라진다.**
   (스쿼트가 4세트로 남는 게 아니라 아예 없어질 수 있다.)
2. **불러온 루틴이 계속 "앱 제안"으로 취급된다.** `addRoutine`은 `suggestedForDayKey` 도장을 안 지운다.
   그래서 제안 위에 루틴을 부르면 ① 달력 계획에 안 써지고(`decidePlanPush`가 제안은 안 씀)
   ② 달력에 오늘 계획이 있으면 화면 복귀 때 `swap`으로 **계획에 덮이고** ③ 자정에 통째로 지워진다.
   → TASK 03의 "나중에 온 조회 응답이 덮는" 경로가 바로 이것이다.
3. **달력 계획과 합칠 때도 같은 병합 규칙**이다. 목록이 계획에 안 묶인 상태에서 오늘 달력 계획이 있으면
   `absorb` → `addToDayPlan` → `mergePlanExercises` — 이름이 겹치면 **달력 쪽 값이 이긴다.**
   처음 읽기(first pull)가 끝나기 전에 루틴을 부르면 이 길로 샌다 `[미검증]`.
4. P2 확인: `updateRoutineExercises`(기존 루틴 덮어쓰기)는 `exercises`만 바꾸고 **`tabata_minutes`를 안 바꾼다**
   — 일반↔인터벌 전환이 루틴에 반영되지 않는다 (코드로 확인됨).
   `toPlanExercises`는 `durationSec`를 버리고 `durationMin`만 싣는다 — 37초가 남는지는 소수 자릿수에 달렸다 `[미검증]`.

## 4. 지켜야 하는 사실 (바꾸면 안 되는 것)

- 진행 중인 운동(세션 있음·시작됨)의 목록은 어떤 불러오기로도 **교체하지 않는다**
- 운동 중 루틴에서 종목을 **더하는** 지금 동작은 그대로 둔다 (운동 중 추가는 정상 기능)
- `mergeImportedExercises`는 지난 기록 불러오기·달력에서도 쓴다 → **함수는 안 고친다**
- 인터벌 루틴은 지금처럼 인터벌 시트로 연다 (`tabataResumeFromSession`)
- 운동 탭 목록 = 오늘 계획 한 줄 (2026-10-05 결정). 교체하면 오늘 계획도 루틴 내용이 된다
- draft v7 구조·버전은 그대로

## 5. 해결 설계 (최소 범위)

### 5-1. 판정 함수 하나 (순수 함수, 테스트로 지킨다)

`src/lib/domain/routine-load.ts` (신규)

```ts
decideRoutineLoad({ draft }) →
  | "add-only"   // 운동 중(sessionId/startedAtMs 있음) — 지금 동작 그대로 병합
  | "replace"    // 목록이 비었거나, 앱 제안(suggestedForDayKey≠null)뿐 — 묻지 않고 교체
  | "ask"        // 사용자가 직접 담은 목록·달력 계획에 묶인 목록 — 선택 화면
```

### 5-2. 교체 전용 경로

`buildRoutineReplacement({ draft, routine, todayGeneralPlanId })` (같은 파일, 순수 함수)

- `exercises = toDraftExercises(routine.exercises)` — 루틴 순서·값 그대로, 새 키, 완료·체감 초기화
- `suggestedForDayKey = null` — 이제 사용자 것 (발견 2 해결)
- `effortMessage = null`, `sourceSessionId = null`
- 프로그램·인터벌에 묶여 있었다면 `program·tabataMinutes·intervalStartIndex·scheduledPlanId` 비움
- 일반 계획에 묶여 있으면 그 묶음 유지 → 다음 쓰기가 `update`로 **계획을 루틴으로 덮는다**
- 안 묶였고 오늘 일반 계획이 있으면 그 계획에 묶는다 → `absorb`(병합) 대신 `update`(교체) (발견 3 해결)

`page.tsx`의 `addRoutine`은 판정에 따라 갈라질 뿐, 병합 쪽 본문은 **한 줄도 안 바꾼다.**

### 5-3. 진입 경로별 동작

| 어디서 눌렀나 | 바뀐 뒤 |
|---|---|
| 운동 추가 시트 › 루틴 탭 (`onPickRoutine`·`onPickPreset`) | `decideRoutineLoad` 결과대로 |
| 퀘스트 카드 아래 "내 루틴" 타일 (`startCustomList("routine")`) | "내 방법으로 시작"이므로 **항상 교체**, 묻지 않음 (발견 1 해결) |
| 운동 중 | 지금처럼 추가만 |

### 5-4. 선택 화면 (TASK 05)

`src/components/record/routine-load-sheet.tsx` (신규, 작게)

- 제목 "루틴 불러오기"
- ● 저장된 루틴 그대로 불러오기 (기본) — 현재 준비 목록을 선택한 루틴으로 교체해요.
- ○ 현재 목록에 추가하기 — 기존 운동을 유지하고 새로운 운동만 추가해요.
- 취소
- 안내: "오늘 운동을 수정해도 저장된 루틴은 변경되지 않아요."
- "추가하기"는 기존 병합 경로 + 토스트 "중복 N개 제외(이미 있는 운동은 그대로 둬요)"

### 5-5. 흔적 남기기 (TASK 08, 축소)
