# 첫 로그인 직후 PWA 설치 안내 파이프라인 — 구현 계획

작성 2026-08-21 · 방법론: first-principles · 요청: *"처음으로 GND 링크를 받아서
로그인을 성공하면 바로 팝업을 띄워서 어플을 설치하도록 최대한 직관적이고 쉬운 안내"*

---

## 1. 문제의 본질

**핵심 문제:** 카톡 링크로 처음 온 사람이 **브라우저 탭에 머무른 채** 끝나서,
다음날 앱을 다시 열 방법이 없다(주소를 기억해야 한다). 게다가 iOS는 **설치본에서만
푸시가 온다** — 설치 안 한 사람에게는 응원·찌르기·아침 브리핑이 영영 안 간다.

**성공 기준(측정 가능):**
1. 첫 로그인한 사람 중 홈 화면 설치까지 도달하는 비율
2. 설치한 사람이 **같은 계정으로** 설치본에 들어오는 비율 ← 이게 빠지면 설치는 재앙이다(§3-5)
3. 안내 시트를 본 사람이 "무엇을 눌러야 하는지" 몰라 이탈하는 비율 0에 수렴

---

## 2. 도전한 가정

| 가정 | 왜 의심하나 | 판정 |
|---|---|---|
| "설치 팝업을 띄우면 된다" | iOS Safari에는 **프로그래매틱 설치가 없다.** 우리가 띄울 수 있는 건 팝업이 아니라 **그림 안내**뿐이다 | **수정** — 플랫폼마다 다른 물건이 필요 |
| "안드로이드도 같은 3단계 안내" | 안드로이드는 `beforeinstallprompt`로 **네이티브 설치 다이얼로그**를 띄울 수 있다. 3단계 안내를 보여주면 **틀린 안내**가 된다 | **폐기** |
| "링크를 열면 사파리/크롬이다" | GND 링크는 **카톡으로 온다.** 압도적 다수의 첫 진입은 **카톡 인앱 브라우저**이고, 거기서는 설치가 **아예 불가능하다** | **폐기** — 탈출 안내가 먼저다 |
| "로그인 성공 = 띄우기 좋은 순간" | 맞다. 계정이 브라우저 밖에서 **복구 가능해진 유일한 시점**이다(익명 계정 상태로 설치를 밀면 계정이 갈린다) | **유지** (조건부) |
| "설치하면 파이프라인 끝" | iOS는 설치본과 사파리의 **저장소가 갈린다.** 설치본은 **로그아웃 상태로 열리고**, 지금 코드는 세션이 없으면 **새 익명 계정을 발급**해 온보딩으로 보낸다 → 설치 유도가 곧 **계정 분리 유도** | **폐기** — 회수 단계까지가 파이프라인 |
| "한 번 닫으면 끝" | 설치율이 목표인데 1회 노출은 너무 약하다. 반대로 매번 띄우면 앱을 지운다 | **수정** — 유예 재노출 + 상시 진입점 |

### ⚠️ 이 저장소가 이미 알고 있던 사실

`docs/GND-크루-사용안내.md`는 **"⚠️ 반드시 이 순서대로! — 설치 먼저, 가입은 그다음"**
이라고 적고, *"가입은 홈 화면 앱에서 딱 한 번만 하세요… '이미 사용 중인 닉네임'
안내가 뜨면…"* 이라고 경고한다. 이건 **저장소가 갈리는 현상을 현장에서 이미 겪고
손으로 우회한 흔적**이다. 지금 하려는 것(가입 → 설치)은 그 수기 안내와 **정반대
순서**라, §3-5를 같이 하지 않으면 그때 겪은 사고를 그대로 재현한다.

## 3. 지반(ground truth)

1. **iOS Safari에 설치 API는 없다.** `공유 → 홈 화면에 추가`를 사람이 눌러야 한다.
   → 첨부 스크린샷 같은 **3단계 그림 안내가 유일하게 옳은 수단**이다.
2. **안드로이드 Chrome에는 있다.** `beforeinstallprompt`를 가로채 두었다가
   사용자 제스처 안에서 `prompt()` → 네이티브 설치 다이얼로그.
3. **인앱 브라우저(카톡·인스타·페북·라인)에서는 설치가 불가능하다.**
   먼저 기본 브라우저로 내보내야 한다. 그리고 **인앱 브라우저는 사파리와도 저장소가
   다르다** — 거기서 한 로그인은 사파리로 안 넘어간다. 그래서 탈출은 **로그인보다
   먼저**여야 한다(§5-1). 실물 확인: 하단 공유 버튼(⬆️) → `Safari로 열기` 1회.
4. **이미 `display-mode: standalone`이면 절대 띄우면 안 된다.** (`lib/bug-report.ts:25`가
   이미 이 판정을 쓰고 있다 — 판정 로직을 한 곳으로 모은다)
5. **iOS 설치본은 사파리와 저장소가 갈린다 → 세션이 없다.** 그리고 지금
   `auth-provider.tsx:115`는 세션이 없으면 **익명 계정을 발급**한다(`NO_ANON_ROUTES`는
   `/login`·`/auth/callback` 둘뿐). 설치본 첫 실행 = 새 사람 = 온보딩 →
   카카오를 누르면 `identity_already_exists`(`identity.ts:171`), 닉네임을 넣으면 중복.
   **막다른 화면이다.**
6. **사용자가 지목한 순간은 옳다.** 신원(카카오·구글·이메일)이 붙은 직후여야
   설치본에서 **로그인으로 되찾을 수 있다.** 익명 계정에 설치를 밀면 기록이 갈린다.

## 4. 지반에서 올라온 설계

```
지반5(저장소가 갈린다) ─→ 회수 경로가 없으면 설치 유도는 순손실
                       └→ ① 설치본 첫 실행을 /login으로 (선행)
지반1·2(플랫폼이 다르다) ─→ ② 환경 판정 순수 함수 → 3종 화면
지반3(카톡 인앱) ────────→ ③ 탈출 안내를 **로그인보다 먼저** (§5-1)
지반6(신원 붙은 직후) ───→ ④ 트리거 = 로그인/가입 성공 → 랜딩 도착 1회
```

### 단계 구성

| 단계 | 무엇 | 왜 |
|---|---|---|
| **0. 회수 안전망** | standalone + 세션 없음 → 익명 발급 대신 `/login` | 구멍을 막기 전에 물을 붓지 않는다 |
| **1. 트리거** | 로그인·가입 성공 시 플래그를 심고, 랜딩 도착 후 1회 소비 | 이동이 `window.location.assign` **전체 로드**라 리액트 상태로는 못 넘긴다 |
| **2. 판정** | `detectInstallEnv()` 순수 함수 | 화면 없이 테스트 가능해야 회귀가 잡힌다 |
| **3. 표시** | 플랫폼별 바텀시트 3종 | §5 |
| **4. 실행** | 안드로이드=`prompt()` · iOS=안내 · 인앱=탈출 | |
| **5. 재노출·측정** | 유예 재노출 + 내 정보 탭 상시 진입점 | 1회 노출로는 목표(설치율)에 못 간다 |

## 5. 화면 3종 (첨부 스크린샷 형식을 따른다)

### 5-1. ⚠️ 시트 C는 **로그인 전에** 뜬다 — 저장소가 세 겹이기 때문 (2026-08-21 정정)

당초 계획은 세 시트를 모두 *로그인 성공 뒤*에 띄우는 하나의 게이트에 두었다. **틀렸다.**

카톡 인앱 브라우저(WKWebView)는 **사파리와도 다른 저장소**를 쓴다. 즉 저장소가
`카톡 → 사파리 → 설치본` **세 겹**이고, 카톡 안에서 로그인한 세션은 사파리로
넘어가는 순간 사라진다.

| 안내 순서 | iOS 로그인 횟수 |
|---|---|
| 카톡에서 로그인 → 사파리 → 설치 | **3번** ← 당초 계획 |
| 카톡에서 **바로 탈출** → 사파리에서 로그인 → 설치 | **2번** ← iOS에서 가능한 최소 |

**규칙:** 인앱 브라우저로 판정되면 `/login`·`/onboarding`에 **닿기 전에** 시트 C를
띄운다. 시트 A·B만 "로그인 성공 직후" 게이트에 걸린다.

⚠️ 그래서 트리거가 두 곳으로 갈린다 — §6의 `InstallPromptGate`를 `(tabs)` 안에만
두면 시트 C는 영영 안 뜬다. 인앱 판정은 **루트 레이아웃**에 있어야 한다
(`AcquisitionTracker`와 같은 자리).

공통 골격: 앱 아이콘(64px) + `GND 앱 설치` + 부제 + **번호가 붙은 단계 카드** + 하단 버튼.
`bug-report-sheet.tsx`의 바텀시트 구조와 `brand/gold.tsx`의 금색을 재사용한다 — 새 디자인 언어를 만들지 않는다.

**A. iOS (Safari)**
```
🏋️  GND 앱 설치
    홈 화면에서 바로 실행

Safari에서 홈 화면에 추가하면 앱처럼 실행됩니다.
① Safari 하단 공유 버튼 탭      [⬆️ 위로 향한 화살표]
② "홈 화면에 추가" 선택          [목록을 스크롤해서 찾기]
③ 오른쪽 상단 "추가" 탭          [홈에 GND 아이콘 생성 완료]
                [ 확인 ]
```
⚠️ **"설치 후에는 다시 로그인해야 해요"를 반드시 적는다.** 안 적으면 설치본에서
로그인 화면을 보고 "가입이 안 됐나?" 하며 **다시 가입한다** — 그게 계정 분리다.

**B. 안드로이드 (`beforeinstallprompt` 수신됨)**
버튼 하나(`앱 설치`) → `prompt()`. 3단계 안내는 **그리지 않는다.**
이벤트가 안 왔으면 `⋮ 메뉴 → 홈 화면에 추가` 2단계 안내로 강등.

**C. 인앱 브라우저(카톡 등) — ⚠️ 로그인 화면보다 먼저 뜬다 (§5-1)**

실물 확인(2026-08-21, 사장님 아이폰 스크린샷). iOS 카톡 인앱 브라우저의 탈출은
**한 번**이면 된다:

```
🧭  사파리로 열어 주세요
    카톡 브라우저에서는 앱 설치가 안 돼요

① 화면 맨 아래 공유 버튼 탭        [⬆️ 네모에 위 화살표]
② "Safari로 열기" 탭               [나침반 아이콘 · 아이콘 줄 맨 왼쪽]
                [ 주소 복사하기 ]
```

⚠️ **공유 버튼(⬆️)이 사파리의 "홈 화면에 추가"에서 또 나온다.** 같은 버튼을 두 번
쓰는 구조라 안내를 이어 붙일 수 있다 — 시트 A의 ①을 *"아까 누른 그 공유 버튼,
사파리에서 한 번 더"* 로 쓴다. 새 조작을 가르치지 않는다.

안드로이드: `크롬으로 열기` 버튼(`intent://…#Intent;scheme=https;package=com.android.chrome;end`).
어느 쪽이든 **주소 복사**를 탈출구로 함께 둔다.

## 7. ⚠️ 코드보다 먼저 할 실증 (P0 — 여기서 갈린다)

아래 둘은 **실기기(아이폰)에서만** 확인된다. 결과에 따라 설계가 바뀌므로 **먼저 한다.**

| # | 확인할 것 | 결과가 이러면 |
|---|---|---|
| P0-1 | 사파리에서 로그인 → 홈 화면에 추가 → **설치본을 열었을 때 로그인 상태인가** | 유지된다면 §3-5 전제가 무너지고 P1(회수)이 불필요해진다 |
| P0-2 | **설치본 안에서 카카오 로그인이 끝까지 완주되는가** (외부 도메인을 다녀와야 한다) | ❌ 실패하면 설치 유도 자체를 **보류한다** — 설치본에 들어갈 방법이 없는 앱을 설치시키는 셈이다 |

**P0-2가 이 계획 전체의 급소다.** 여기가 막히면 시트를 아무리 잘 만들어도 사용자는
설치본에서 로그인하지 못하고, 우리가 계정 분리를 대량 생산하게 된다.

## 9. 검증 (전역 지침 §개발 서버 확인)

**사회적 기능이 아니다 → A 계정 하나로 충분하다.** 다만 컨텍스트는 둘이 필요하다
(브라우저 탭 vs 설치본).

개발 서버에서 **눈으로 볼 것** — "에러가 안 났다"가 아니라 "의도한 것이 보이는가":
1. iOS UA 흉내 → 시트가 뜨고 **단계 카드가 정확히 3개**인가
2. `beforeinstallprompt` 발생시킴 → **단계 카드가 0개**이고 버튼 하나인가
3. standalone 에뮬레이션 → **시트가 안 뜨는가**(부정 확인)
4. 시트를 닫고 새로고침 → **다시 안 뜨는가**
5. 로그인 없이 랜딩 진입 → **안 뜨는가**(익명 사용자에게 밀지 않는다)
6. 카톡 UA 흉내 → **로그인 화면 대신 시트 C**가 뜨는가(부정 확인: 로그인 버튼이 안 보여야 한다)

그다음 lint · typecheck · 전체 test · build · `pnpm verify:regression --tier readonly`
→ 사장님 승인 → 배포 → **프로덕션 실기기**에서 P0-1·P0-2 재확인.

## 10. 결론

**권고:** 요청한 대로 "첫 로그인 직후 설치 안내 시트"를 만든다. 단 **혼자 만들면
안 된다** — iOS 설치본은 로그아웃 상태로 열리고 현재 코드는 그때 **새 익명 계정을
발급**하므로, 회수 경로(P1)를 **먼저** 넣어야 설치 유도가 이득이 된다.

**핵심 통찰:** 이 일은 "팝업 하나 만들기"가 아니라 **브라우저 세션에서 설치본
세션으로 사람을 옮기는 이주 파이프라인**이다. 팝업은 그 파이프라인의 입구일 뿐이고,
지금 없는 것은 **출구**다.

**감수하는 것:** iOS는 끝까지 사람이 3번 눌러야 한다(우회로 없음) · 인앱 브라우저
탈출은 카톡 UI에 의존해 버전에 따라 문구가 달라질 수 있다 · 재노출 정책은 설치율과
성가심의 교환이라 실측 후 조정이 필요하다.

## 12. 아이폰 vs 갤럭시 — 같은 안내를 쓰면 안 된다

### 실제 사용자 분포 (2026-08-21, 운영 DB 읽기 전용 조회)

| 근거 | iOS | Android |
|---|---|---|
| `push_subscriptions` 엔드포인트 | 4 (Apple) | 1 (FCM) |
| `bug_reports` UA (최근 9건) | 6 | 3 |
| 프로필 총 8명 · 신고 9건 **전부 `standalone=true`** | — | — |

**양쪽 다 실사용자가 있다. 안드로이드를 건너뛸 수 없다.** 그리고 신고자가 전부
설치 사용자라는 것은, 지금까지 설치한 사람은 **수기 안내를 받은 소수**라는 뜻이다.

### 갈리는 세 지점

| | 아이폰(사파리) | 갤럭시(크롬) |
|---|---|---|
| 설치 | 공유 → 홈 화면에 추가 → 추가 (**사람이 3번**) | **버튼 하나** (`beforeinstallprompt` → `prompt()`) |
| 설치 후 로그인 | **다시 해야 함** (저장소가 갈림) | **유지** (크롬과 저장소 공유) `[미검증]` |
| 카톡 탈출 | 공유 → `Safari로 열기` (**2단계 안내**) | `intent://` 로 **버튼 하나** |

⚠️ **시트 A(3단계)를 안드로이드에 보여주면 틀린 안내다.** 판정은 UA 추측이 아니라
`beforeinstallprompt` **수신 여부**를 우선한다(이벤트가 진실이다). 이벤트가 안 오면
`⋮ → 홈 화면에 추가` 2단계로 강등.

⚠️ **시트 D(재로그인)는 iOS 전용이다.** 안드로이드에 띄우면 멀쩡히 로그인된
사람에게 로그인을 시키는 셈이다.

### P0에 추가하는 확인

| # | 확인 | 기기 |
|---|---|---|
| P0-3 | 갤럭시에서 설치 후 **로그인이 유지되는가** | 안드로이드 |
| P0-4 | 갤럭시에서 `beforeinstallprompt`가 **실제로 발생하는가** (sw.js의 빈 fetch 핸들러로 설치 조건을 만족하는지) | 안드로이드 |

⚠️ 안드로이드 실기기 확인자가 필요하다. 크루 8명 중 안드로이드 사용자에게 부탁한다.

## 13. 안내 그림 — 실제 스크린샷을 쓴다 (사장님 지시 2026-08-21)

*"이 표시 그대로 사용할 수 있어? 안내에?"* → **쓴다.** 아이콘 그림보다 실제 화면
사진에 빨간 동그라미가 훨씬 강하다. 단 세 규칙을 지킨다.

1. **다시 찍는다.** 사장님이 보낸 원본에는 공유 시트에 **카톡 친구 프로필 사진과
   실명**이 찍혀 있다. 그대로 넣으면 전 사용자에게 그 사람들이 보인다.
   → 친구 목록이 안 뜨는 상태로 새로 촬영한다.
2. **하단 바만 크롭한다.** 시트 안에 폰 전체 스크린샷을 넣으면 손톱만 해져 안 보인다.
   가로로 잘라 버튼을 크게 보여준다. `webp`로 최적화(장당 30KB 이하 목표).
3. **사진 + 글자를 같이 둔다.** iOS·카톡이 업데이트되면 사진은 낡는다. 글자가
   맞으면 낡은 사진으로도 따라갈 수 있다.

### 사진 대신/함께 쓰는 화살표 — 낡지 않는 쪽

공유 버튼은 **브라우저 UI**라 우리가 그 위에 그릴 수 없다. 대신 **우리 화면 맨
아래에서 그쪽을 가리키는 화살표**는 그릴 수 있다. 카톡 하단바는 웹뷰 바로 아래에
붙어 있고, 공유 버튼은 **맨 오른쪽**이다(스크린샷 2장으로 확인, 2026-08-21).

```
│   바로 아래 이 버튼!  ↓↓↓ │   ← 우리가 그리는 화살표(우측 정렬)
└───────────────────────────┘
  ←    →    ⟳         ⬆️      ← 카톡 하단바(실물)
```

낡지 않고, 사용자 **자기 화면**을 가리키므로 헷갈릴 여지가 없다. **둘 다 넣는다.**

### 필요한 촬영 목록 (아이폰만)

| # | 무엇 | 주의 |
|---|---|---|
| 1 | 카톡 하단바 — 공유 버튼 위치 | 가로 크롭 |
| 2 | 공유 시트의 `Safari로 열기` | **친구 목록이 안 나오게** |
| 3 | 사파리 공유 시트의 `홈 화면에 추가` | 목록을 내린 상태 |
| 4 | `추가` 누르는 마지막 화면 | 우측 상단이 보이게 |

**갤럭시는 촬영이 필요 없다** — 버튼 하나라서 그림으로 설명할 단계가 없다.
저장 위치: `public/onboarding/install/` (기존 `public/onboarding/` 규약을 따른다).

### 13-2. 사진을 **안** 넣은 단계 — 의도한 것이다

시트 A의 ①(공유 버튼)과 ③(오른쪽 위 `추가`)에는 사진이 없다.

- ①은 시트 C에서 **이미 한 번 눌러 본 버튼**이다. 다시 보여주면 "새로운 것"처럼 보인다
- ③은 화면 오른쪽 위 한 곳뿐이라 글자로 충분하다

**사진은 "못 찾을 만한 곳"에만 쓴다.** 전부 붙이면 시트가 길어져 스크롤이 생기고,
스크롤이 생기면 마지막 단계를 아무도 못 본다.

### 13-3. 남은 촬영 — 갤럭시 1장 (선택)

안드로이드는 버튼 하나라 안내 사진이 필요 없다. 다만 `beforeinstallprompt`가 안 오는
경우의 예비 안내(`⋮ → 홈 화면에 추가`)를 만들 거라면 갤럭시 크롬 메뉴 1장이 필요하다.
**P0-4(이벤트가 실제로 오는가) 확인 뒤에 결정한다** — 이벤트가 잘 오면 필요 없다.

## 15. ⚠️ §5-1을 뒤집는다 — 안내는 **로그인 뒤**다 (2026-08-21 사장님 결정)

§5-1은 *"인앱 탈출 안내를 로그인보다 먼저 띄운다"*고 정했다. 근거는 저장소가
세 겹(카톡 인앱 → 사파리 → 설치본)이라 카톡에서 로그인하면 사파리에서 또 해야
하고, iOS 로그인이 **3번**이 된다는 것이었다.

**그 계산이 한쪽만 봤다.** 사장님 지적: *"먼저 로그인을 하고 어플을 깔라고
안내하는 게 더 낫지 않아?"*

| | 로그인 전 안내 (옛 §5-1) | **로그인 후 안내 (채택)** |
|---|---|---|
| iOS 로그인 횟수 | 2번 | 3번 |
| 안내를 받는 사람 | 앱을 **아직 아무것도 못 본** 낯선 사람 | 이미 써 보고 크루에 들어온 사람 |
| 첫 화면 | "여기선 앱을 못 깔아요" 모달 | 평소 로그인 화면 |

**추가 로그인 1회의 진짜 비용은 카카오 버튼 한 번**이고 계정도 같다(같은 카카오 →
같은 GND 계정). 반면 첫 화면부터 브라우저를 옮기라는 모달은 **사람을 통째로 잃는다.**
싼 것과 비싼 것을 바꿔 계산하고 있었다.

### 바뀐 것

- `InstallGate`: 탈출 안내도 **`linked`(신원 붙음)일 때만** 띄운다
- `InstallSheet`: `escape-ios`의 "처음 온 사람" 말투를 **없앴다.** 하나뿐이다 —
  *"이제 홈 화면에 놓을 차례예요 / 카톡 안에서는 앱을 못 깔아요"*
- 💡 *"사파리에서 카카오 버튼 한 번만 더 누르면 끝이에요. 기록은 그대로예요."*
  ← **미리 말한다.** 안 말하면 사파리에서 로그인 화면을 보고 "아까 한 게 날아갔나?"
  하며 되돌아온다
- `afterLogin` 인자를 **제거했다** — 상태가 하나 줄면 틀릴 여지도 준다

⚠️ `InstallGate`가 루트 레이아웃에 있는 이유도 바뀌었다. "로그인 화면보다 먼저 떠야
해서"가 아니라, 로그인 직후 착지점이 `/record`·`/challenge`·`/account`로 갈리기
때문이다. 탭 안에만 두면 뒤의 둘에서 안 뜬다.

### 그 밖에 실화면에서 잡은 것

- **아이폰 설치 안내가 3단계가 아니라 4단계였다** (§11 정정). 카톡의 `Safari로 열기`로
  넘어온 사파리는 하단바에 **공유 버튼이 없다** — `< | 주소 ⟳ | ···` 이고 공유는
  `···` 안에 있다. 첫 단계부터 틀린 안내였다. 사장님 실물 스크린샷으로 잡혔다
- **시트가 732px이라 실기기에서 버튼이 화면 밖으로 밀렸다.** 제목·💡·버튼을
  스크롤 **밖**에 고정하고 단계만 스크롤한다. 390×745(아이폰 14)에서 전부 들어가고,
  660px짜리 작은 화면에서는 마지막 단계만 조금 밀린다
