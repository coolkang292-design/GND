# 오늘의 퀘스트 — 하루 계획 여러 개를 각각 보이고 각각 시작하기

작성 2026-11-25 · 상태: **계획만 있음, 코드·DB·배포 손대지 않음** · 분류: P1 버그 수정

> 기준 코드는 **`origin/main`** 이다. 지금 체크아웃(`feat/posthog-funnel`)은 main보다 254커밋 뒤라서
> 퀘스트 파일(`daily-quest*.ts(x)`, `quest-*.tsx`)이 아예 없다. 여기서 작업하면 안 된다 (§T0).

## 1. 한 줄 결론

달력에 인터벌(07:00)과 풀업(20:00)이 같이 있어도 퀘스트 화면은 **풀업 목록 하나만** 퀘스트로 그리고 인터벌을
숨긴다. 원인은 "퀘스트 카드를 달력 계획이 아니라 **지금 준비 중인 운동 목록(draft)** 을 보고 그린다"는 점이다.
카드를 **달력 계획(`todayPlans`) 기준**으로 그리면 해결되고, **DB 변경은 필요 없다.**

## 2. 계획서와 실제 코드가 다른 점 (정정)

| 계획서 주장 | 실제 (main 코드·운영 DB로 확인) | 영향 |
|---|---|---|
| 하루 여러 일정 등록 가능 | **일반 계획은 하루 1개**(사용자 결정 2026-10-13, `domain/day-plan.ts`). 같은 날 일반 계획이 둘이면 읽을 때 자동으로 하나로 합치고 나머지를 지운다(`consolidateDayPlans`). 인터벌·프로그램 계획만 따로 둘 수 있다 | "아침 웨이트 + 저녁 웨이트"는 지금 규칙상 불가능. 이번 범위에서 **규칙을 바꾸지 않는다** (§9 결정 1) |
| 11/25에 계획 2개 | **맞다.** 인터벌 8분(`scheduled_at` 22:00Z = 07:00 KST, 4종목) + 일반 계획 "수 저녁 가벼운 풀업"(11:00Z = 20:00 KST, 풀업 1종목). 인터벌=특별 계획, 풀업=일반 계획 | 이미 규칙상 공존 가능한 조합이라 구조 변경 없이 풀린다 |
| "11/22 로직이 일부 계획을 숨긴다" | **맞다.** 정확한 위치는 `record/page.tsx` 의 `planQuestShown`(≈4800행). 인터벌 카드는 `draft.exercises.length === 0 \|\| draft.suggestedForDayKey !== null` 일 때만 뜬다. 풀업 일반 계획은 앱을 열면 목록에 **자동으로 담겨**(`shouldAutoLoadTodayPlan`) 이 조건이 거짓이 된다 | 이게 본 버그 |
| 완료 상태를 저장하려면 연결 정보 필요 | 완료하면 **특별 계획은 통째로 삭제**, 일반 계획은 **한 세트라도 한 종목만 빼고 남김**(`settlePlanAfterWorkout`, 사용자 결정 2026-10-13). "남은 것만 보인다"가 이미 구조다 | 완료 표시는 **DB 없이** 오늘 완료 세션(`todaySessions`)으로 충분 (§9 결정 2) |
| 운동 중 다른 계획 시작 방지 필요 | **이미 있다.** `handleLoadPlan`(3154행)·`beginTabata`(2909행)이 `active`면 막는다 | 새로 만들지 않고 **테스트만** 건다 |
| 파일 6개 수정 | `workout-plan.ts`(domain) 자동 불러오기, `day-plan-store.ts` 는 **고치지 않는다**. 대신 퀘스트 쪽 판정만 바꾼다 | 수정 범위가 더 작다 |

## 3. 숨겨지는 경로 3개 (모두 코드로 확인)

1. **인터벌이 풀업 목록에 가려짐** — `planQuestShown` 조건. (오늘 신고된 증상)
2. **아침 운동 후 저녁 퀘스트 카드가 사라짐** — `questCardShown` 에 `!didWorkoutToday`. 목록 화면(고정 시작 버튼)은 남지만 퀘스트 카드는 없다. 계획서의 **반증 조건에 이미 걸려 있다.**
3. **풀업을 부분만 하면 인터벌이 다시 숨음** — 남은 종목이 다시 목록에 자동으로 담겨 1번과 같은 상태가 된다.

추가로 눌렀을 때 충돌: 풀업이 목록에 담긴 채 인터벌 카드를 누르면 `beginTabata` 가
`"준비 중인 운동 목록을 지우고 전신 인터벌을 시작할까요?"` 확인창을 띄운다(2921행). 풀업 계획은 DB에 남아
있으므로 잃는 게 없는데도 겁을 준다 — 이 확인은 **계획에 묶인 목록이면 건너뛰어야** 한다.

## 4. 설계 (변경 최소)

원칙: **카드 = 달력 계획 한 줄**, **draft = 시작하려는 한 번의 운동**. 둘을 섞지 않는다.

- 오늘 계획 전부(`todayPlans`)를 `scheduledAt` 순(없으면 맨 앞)으로 카드로 그린다.
- 캐릭터 배너(`QuestHero`)는 **한 번만**, 카드는 그 아래에 계획마다.
- 시작 동작은 지금과 같다 — 인터벌: `handleLoadPlan(plan)`(시트를 연 뒤 시간 선택), 프로그램: `{startNow:true}`,
  일반 계획: 목록 화면으로(`setQuestListOpen(true)`) 후 기존 고정 시작 버튼.
- 계획 없는 날은 기존 추천(`questKind`)을 **그대로** 유지한다.
- 자동 불러오기(`shouldAutoLoadTodayPlan`)·동기화(`decidePlanPull/Push`)·`settlePlanAfterWorkout`은 **그대로 둔다.**
  이것들은 10/13에 신고 6건을 거쳐 맞춘 부분이라 건드리면 파급이 크다.

### 바꾸는 판정 3개
| 지금 | 변경 후 |
|---|---|
| 특별 계획 카드: draft가 비었거나 제안일 때만 | **인터벌이 든 draft가 아니면 항상** (`draft.tabataMinutes === null` 또는 옛 복사본). 일반 목록이 있어도 낸다 |
| 일반 목록 카드: `!didWorkoutToday` | `!didWorkoutToday \|\| draft.scheduledPlanId !== null` — **계획에 묶인 남은 목록은 운동했어도 카드로** 낸다. 기계가 담은 제안은 지금처럼 운동 후엔 안 낸다 |
| `beginTabata` 확인창: 목록이 있으면 항상 | 목록이 **달력 일반 계획에 묶여 있으면 건너뜀**(계획은 DB에 남고 끝나면 다시 목록에 오른다). 묶이지 않은 목록만 묻는다 |

## 5. 작업 단계

**T0. 작업 자리 만들기** — `origin/main` 에서 새 브랜치 + 작업 복사본(worktree). 현재 체크아웃은 건드리지 않는다
(수정 중 파일 40여 개가 있다). 이름 예: `fix/multi-quest-cards-20261125`. `.env.local`은 복사하지 않고
`reference_deploy_without_env_copy` 방식을 따른다.

**T1. 판정 함수를 순수 함수로 (테스트 먼저)** — `domain/daily-quest.ts` 에 추가:
- `buildQuestPlanCards({ todayPlans, timeZone })` → `{ planId, kind: interval|program|general, timeLabel|null, names[], detail }[]`, `scheduledAt` 순
- `shouldShowSpecialPlanCards({ active, draftTabataMinutes, hasStaleCopy })`
- `shouldShowListQuestCard({ ..., didWorkoutToday, draftBoundToPlan })`
- `isDraftBoundGeneralPlan({ draftScheduledPlanId, todayPlans })` (확인창 건너뛰기 판정)
RED: 아래 QA 표의 판정형 항목(1~9, 12, 13)을 먼저 테스트로 쓴다 → 실패 확인 → 구현.

**T2. 컴포넌트** — `daily-quest-card.tsx` 에 `showHero`(기본 true) 추가해 카드가 여러 개여도 배너는 한 번.
`quest-today-card.tsx` 는 칸 위에 `07:00 · 8분 · 4종목` 같은 한 줄 머리글(선택 prop)만 더한다.
기존 호출처(`record-empty-state.tsx`)는 기본값 그대로라 안 바뀐다.

**T3. 기록 화면 연결** — `record/page.tsx` 의 `planQuestShown`·`questCardShown`·카드 렌더(4974~5164행)를 T1 함수로
바꾼다. 카드 순서는 시간순, 배너는 첫 카드에만. 목록이 담겨 있으면 그 목록 카드를 해당 계획 시각 자리에 낸다.

**T4. 충돌 정리** — `beginTabata` 확인창에 T1의 `isDraftBoundGeneralPlan` 적용. `handleLoadPlan` 은 이미 묶인
목록이면 묻지 않으므로 그대로.

**T5. 검증 (§6)** → `pnpm lint` · `typecheck` · 전체 `test` · `build` → 사용자 화면 확인.

## 9. 사용자 결정이 필요한 것 (구현 시작 전)

1. **하루 일반 계획 1개 규칙을 유지할까?** 권장: **유지.** 바꾸려면 10/13 결정을 뒤집어야 하고 합치기·동기화
   6곳이 같이 바뀐다. 유지하면 "아침 웨이트 + 저녁 웨이트"는 계속 한 계획으로 합쳐진다.
2. **완료한 계획을 카드에 "완료"로 남길까?** 권장: **이번엔 안 남김.** 완료하면 계획이 사라지는 게 현재 설계이고,
   오늘 한 운동은 `TodayCompletedList`/피드가 이미 보여준다. 남기려면 세션↔계획 연결 컬럼(마이그레이션)이 필요해 범위가 커진다.
