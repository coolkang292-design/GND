# 특정 계정의 인터벌 음원 적용

사용자 승인: 세 계정만 Dynamite (Tabata)를 쓰고 시작·일시정지·종료를 기존 인터벌과 함께 제어한다. 8·16분은 반복한다. 운영 배포는 별도 승인이다.

## 설계

- 운영 프로필을 읽기 전용으로 조회해 세 계정의 고유번호를 확인했다. 실제 등록 표기는 `스칼레또`다.
- 고유번호는 Git에 넣지 않고 `.env.local`의 `NEXT_PUBLIC_INTERVAL_DYNAMITE_USER_IDS`에 보관한다. 이 값은 클라이언트의 음원 선택용이며 권한 검사나 비밀값이 아니다.
- 현재 기록 화면이 가진 `userId`를 인터벌 시트에 전달한다. 목록에 정확히 일치하는 계정만 별도 트랙을 선택한다. 누락·다른 계정은 기존 트랙을 쓴다.
- 새 음원을 기존 13초 준비·20초 운동·10초 휴식·250초 블록에 맞춘 뒤 PCM 상태에서 1·2·4회 연결하고 MP3로 인코딩한다. 타이머 계산과 운동 기록 구조는 유지한다.
- 음원은 별도 버전 이름으로 추가한다. 기존 음원과 사용자 데이터는 바꾸지 않는다.
- 새 선택 UI·라이브러리·DB 변경·실사용자 알림은 추가하지 않는다. 대상 계정에는 현재 배경음 제목을 표시한다.

## 실행·검증

1. 계정별 선택과 컴포넌트 재생 흐름의 실패 테스트를 먼저 확인한다.
2. 새 음원의 안내 전환 시각을 분석하고 기존 시간 구조와 맞춘 4·8·16분 파일을 만든다.
3. 음원 선택·기록 화면 연결을 구현하고 관련 테스트를 실행한다.
4. 개발 서버에서 실제 시트의 코스 선택·시작·운동/휴식 전환·일시정지·재개·중단·종료와 일반 계정의 기존 음원을 확인한다. 실제 사용자 기록을 만들지 않는 개발용 화면을 사용한다.
5. lint·typecheck·전체 test·build를 실행하고 최종 diff·비밀값을 검사한다.
6. 진행 기록·인수인계서를 갱신하고 검증한 파일만 커밋한다. 나가는 커밋·브랜치·바이너리 크기를 제시해 푸시 여부를 묻는다. 운영 배포는 별도 승인이다.

## 한계

- 실제 iPhone의 무음 스위치·잠금 화면·오디오 출력은 데스크톱에서 대신 증명할 수 없다.
- 음원의 앱 사용 권리는 이번 기술 검증 범위에서 확인하지 않았다.
