**Tech Stack:** Next.js · TypeScript · Supabase/Postgres · Vitest · 기존 회귀 러너. 새 라이브러리 없음.

**작성일:** 2026-11-13 · **계획 기준:** `feat/level-growth-v2` / `6a68d1b`(점프 규칙 `1502191` 포함).

## 1. 현재 사실과 이번 범위

- [확실] 성장 계산·본인 조회·카드·기능 플래그 연결은 구현됐다. 실데이터 비교표, 픽스처 A의 성장 0/비교 불가 9종목, 오뎅끼데스까의 성장 6/비교 제외 12종목 화면 확인이 기록돼 있다. 이번 계획 작성자가 화면을 다시 확인한 것은 아니다.
- [확실] 기준 대비 +100% 초과를 `jump`로 제외하는 규칙이 추가됐다. 정확히 +100%는 성장으로 인정하며, 구현은 부동소수 오차를 고려한 `100 + 1e-6` 경계를 사용한다. 정상적인 초보자 향상도 제외할 수 있으므로 서버 조건으로 그대로 옮기는지는 승인 대상이다.
- [확실] 0131·0132는 운영 적용됐다. 스키마 문서 갱신·전체 최종 검사·진화 카드의 옛 성장률 중복 정리가 남았다. 최신 화면 확인보다 뒤처졌던 인수인계 첫 상태·§8은 이번 문서 작업에서 정정했다.
- [확실] 서버는 XP만으로 단계를 올린다. `src/lib/progression.ts`의 본인·크루 조회도 DB 단계 대신 `getLevelProgress(totalXp)`의 단계를 반환한다. 서버만 바꾸면 화면은 계속 XP 단계로 표시된다.
- [확실] `src/lib/level-growth.ts`도 레벨에서 단계와 진입 시각을 구한다. 진화 보류를 도입하면 실제 단계 진입 이력으로 바꿔야 한다.
- [확실] 기존 `level_growth_baselines`는 `target_level`과 `sample_count = 3`을 전제로 한다. 단계별 단일 최고 기록 저장소로 그대로 재사용하지 않는다. 기존 테이블·RPC는 이번 작업에서 삭제하지 않는다.
- [확실] 사용자 결정(이번 대화): 기구별로 종목 이름을 나누고, 과거 모호한 비교는 따로 검증한다. 과거 기록을 숫자만 보고 자동 변경하지 않는다.

1차 산출물은 카드 마무리와 규칙 영향 분석이다. 2차 산출물은 서버 판정과 호환 화면이다. 둘을 한 번에 운영 활성화하지 않는다.

### 최신 사용자 결정 — 필요 N종목을 분모로 고정한 평균

2026-11-13 후속 대화에서 **최소 성장 N종목과 상위 N종목 평균 목표를 함께 충족**하는 방식으로 확정했다. 비교 가능한 전체 종목 수로 나누거나 운동 여러 번의 기록을 평균하지 않는다. 코드에는 아직 적용하지 않았다.

```text
종목별 성장 점수 = max(0, (이번 단계 최고 - 진입 시 기준 최고) / 기준 최고 × 100)
N = max(1, ceil(이전 단계 기록 종목 수 M × 목표 단계 비율))
선택 = 유효한 성장 종목 중 성장률이 높은 상위 N개
진화 평가 평균 = 선택된 성장률 합 / N   # 부족한 자리는 0%
성장 조건 충족 = 실제 성장 종목 수 >= N AND 진화 평가 평균 >= 단계별 평균 목표
```

- +10/+8/+6일 때 N=3이면 8%, N=4이면 (10+8+6+0)/4=6%. N=4에서는 성장 종목 3개이므로 평균 목표를 넘더라도 진화 보류.
- 5종목이 성장했는데 N=3이면 높은 3종목만 선택하고 3으로 나눈다. 동률은 종목 식별 키로 안정 정렬한다.
- N=4·평균 목표 8%에서 +20/+10/+1/+1은 **통과**한다(사용자가 명시적으로 선택). 개별 종목마다 8% 이상일 필요는 없다. 기준보다 증가한 종목을 성장 종목으로 센다.
- 동일·하락은 음수로 반영하지 않는다. 기준 없음·다른 기구·jump 제외는 성장 종목으로 채우지 못한다. 이때도 분모 N을 줄이지 않고 부족한 자리를 0%로 둔다.
- 기준·단계 이력 자체가 없으면 '측정 준비 중'. 기준이 준비됐지만 아직 성장하지 않았으면 평균 0%, 성장 0/N이다. 조회 오류를 0으로 숨기지 않는다.
- kg·반복·초 원값을 섞어 평균하지 않는다. 각 종목의 변화율을 구한 뒤 평균하며, 판정은 소수 첫째 자리 표시 전 원값으로 한다.
- 이 값은 필요한 N종목 기준의 **진화 평가 성장률**이다. 전체 체력의 평균 향상률로 설명하지 않는다. 선택된 종목과 N을 화면에 함께 보여 준다.
- M×비율로 필요한 성장 종목 수를 정하는 구조는 유지한다. 평균을 추가했다고 최소 성장 종목 수 조건을 없애지 않는다.

### 적용 시작 — 시동러까지 XP만, 꾸준러 진입부터 조건 적용

- 개노답(1)→꿈틀러(2, Lv.6), 꿈틀러(2)→시동러(3, Lv.11): 기존처럼 XP만 충족하면 진화. 운동일·경과 주·성장·미션으로 막지 않는다.
- 시동러(3)→꾸준러(4, Lv.16 이상)부터: XP + 승인된 운동 습관 + 최소 N종목 + 상위 N종목 평균 목표. 후반 단계는 승인된 추가 미션도 적용.
- 이미 꾸준러가 된 뒤 다음 진화부터가 아니라 **꾸준러 진입이 최초 적용 시점**이다. 초기 단계에서도 원본 기록을 계속 쌓아 시동러 진입 기준과 이후 성장을 준비한다.

현재 문턱은 레벨마다가 아니라 목표 단계별이다. 평균 방식으로 옮길 때 아래 수치를 출발점으로 실데이터를 검토하며 그대로 확정한 것은 아니다.

| 목표 단계 | XP 자격 | 평균 목표 초안 | N 비율 초안 | M=18 예시 |
|---|---|---|---|---|
| 2 꿈틀러 | Lv.6 이상 | 적용 안 함 | 적용 안 함 | XP만 |
| 3 시동러 | Lv.11 이상 | 적용 안 함 | 적용 안 함 | XP만 |
| 4 꾸준러 | Lv.16 이상 | +5% | 15% | 3종목 |
| 5 불꽃러 | Lv.21 이상 | +8% | 20% | 4종목 |
| 6 대장 | Lv.26 이상 | +12% | 25% | 5종목 |
| 7 전설 | Lv.31 이상 | +15% | 30% | 6종목 |

```ts
export function computeEvolutionGrowthScore(summary: StageGrowth, requiredCount: number) {
  if (!Number.isInteger(requiredCount) || requiredCount < 1) {
    throw new RangeError('requiredCount must be a positive integer');
  }
  const selected = [...summary.growths]
    .filter(g => g.growthPct > 0)
    .sort((a, b) => b.growthPct - a.growthPct
      || (a.exerciseKey < b.exerciseKey ? -1 : a.exerciseKey > b.exerciseKey ? 1 : 0))
    .slice(0, requiredCount);
  return {
    selected,
    requiredCount,
    filledCount: selected.length,
    countMet: selected.length === requiredCount,
    averagePct: selected.reduce((sum, g) => sum + g.growthPct, 0) / requiredCount,
  };
}
```
