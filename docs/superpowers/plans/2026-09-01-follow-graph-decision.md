# 팔로워 / 팔로잉 — 결정 기록과 구현 계획 (2026-08-31)

> **상태: 미착수.** 사장님 지시로 **기록만 남기고 오늘은 구현하지 않는다.**
> 아래는 first-principles로 따진 결과와, 실제로 만들 때 지킬 선이다.

## 0. 왜 이 얘기가 나왔나

사장님 말:

> *"크루 리스트를 인스타의 팔로워와 팔로잉 개념을 도입하면 어떨까?
> 인플루언서나 트레이너의 운동 내역을 보고 그들의 운동을 따라하게 피드에 뜨게 하기
> 위함이거든? 친구가 많으면 너무 많은 알림이 소음이 될수도 있을거 같은데"*
>
> *"팔로워와 팔로잉은 개인 프로필을 열면 보이게끔"* — 인스타 프로필의
> `게시물 / 팔로워 / 팔로잉` 3칸 배치 스크린샷을 참고로 주셨다.

## 1. 실측한 지반 사실 (2026-08-31)

| 사실 | 값 | 함의 |
|---|---|---|
| **`workout_started` 알림** | **294건 / 전체 837건 = 35%** | 소음의 정체. **팔로우 수에 정비례해 폭발한다** |
| 1인당 알림 | 최다 179 · 중앙값 109 | 실사용자 4명 · 크루 8쌍에서 **이미** 이 정도다 |
| 크루 판정을 쓰는 RLS 정책 | **2개** | ⚠️ 옛 계획서의 *"RLS 74개가 그 전제 위에 있다"* 는 **틀렸다** |
| `is_crew_with` 호출 지점 | 14곳 (RPC 12 + 정책 2) | 실제 변경 표면 |
| 인플루언서·트레이너 | **0명** | 가설이 아직 검증 안 됐다 |

## 2. 핵심 통찰 — **가시성과 구독은 다른 것이다**

"팔로우"에 두 가지가 섞여 있다. 인스타가 묶었을 뿐, 분리할 수 있다.

```
가시성  그 사람 기록을 볼 수 있는가   → 따라하기가 필요로 하는 것
구독    새 활동이 나에게 밀려오는가   → 알림 소음의 원인
```

**따라하기는 가시성만 필요하고, 소음은 전적으로 구독에서 온다.**
둘을 묶으면 ①(따라하기)을 얻으려다 ③(조용함)을 잃는다.

> **알림은 _관계_ 에서 오고, 피드는 _관심_ 에서 온다.**
> 인스타의 알림 설정이 그렇게 복잡한 이유가 이 둘을 묶었기 때문이다.
> GND는 처음부터 나눌 수 있다.

## 3. 크루를 **대체하지 않는다**

크루가 상호 수락인 것은 기술적 사정이 아니라 **프라이버시 근거**다 —
GND의 게시물에는 무게·횟수·인증사진·몸이 들어간다. 인스타 사진보다 사적이다.

단방향만 남기면 모르는 사람이 내 몸 데이터를 내가 모르는 채 본다.
그래서 인스타도 **공개 계정 / 비공개 계정**이 공존한다. 같은 모델로 간다.

```
기본            비공개 = 상호 크루 (지금 그대로)
원하는 사람만    공개 계정 → 누구나 단방향 팔로우 가능
```

## 4. ⚠️ 검증 수단이 **이미 배포돼 있다** — 0단계

트레이너가 **공개 모집 챌린지**(0085~0087)를 열고 사람들이 참가하면:

- `shares_any_challenge_with`가 열려 **참가자끼리 기록·프로필이 이미 보인다**
- **따라하기가 이미 된다**
- **참가해도 크루가 되지 않는다**(사장님 결정) → 단방향에 가깝다

즉 *"사람들이 트레이너를 따라할까?"* 를 **코드 한 줄 없이** 시험할 수 있다.
다른 점은 기간이 있다는 것뿐이다. **팔로우를 만들기 전에 이걸 먼저 해 본다.**

## 5. 만들 때의 단계와 지킬 선

| 단계 | 무엇 | 비용 |
|---|---|---|
| **0** | 공개 모집 챌린지로 가설 검증 | **0** |
| **1** | `profiles.is_public` + `follows` 테이블 · **피드에만** 반영 | 마이그레이션 1 · 정책 2곳 · 피드 질의 |
| **2** | 프로필에 `게시물 / 팔로워 / 팔로잉` 3칸 + 탭하면 명단 | UI |

### ⛔ 1단계에서 반드시 지킬 것

1. **`workout_started` 알림을 팔로우로 확장하지 마라.** 전체 알림의 35%이고
   소음의 정체다. 알림은 크루에만 둔다.
2. **팔로우는 "보기"만 준다.** 댓글·응원·찌르기·랭킹·챌린지는 크루 그대로.
   이러면 변경이 **정책 2개 + 피드 질의**로 끝난다. 여기를 넓히는 순간
   14곳이 전부 대상이 된다.
3. **차단(`is_blocked_between`)이 팔로우에도 적용돼야 한다.** 차단한 사람이
   나를 팔로우한 채로 남으면 차단이 반쪽이 된다.
4. **공개는 opt-in, 기본 꺼짐.** 기본이 공개면 기존 사용자가 모르는 사이에
   노출된다.

### 받아들이는 것

팔로우해도 **말은 못 건다**(댓글 불가). 트레이너 입장에선 50명이 말 걸어오는
것보다 나을 수 있지만, "소통"을 원하면 2단계에서 다시 결정해야 한다.

## 6. 프로필 3칸 배치 (2단계)

지금도 프로필 시트에 **`누적 성과` 3칸**이 있다 — `운동 N회 · 운동한 날 N일 · 시간`.
**배치는 이미 인스타와 같다.** 빠진 것은 성격이다:

| | 인스타 | GND 지금 |
|---|---|---|
| 성격 | **사람 수**(사회적 증명) | **내 활동량** |
| 탭 | 팔로워·팔로잉이 **명단으로 열린다** | 안 눌린다 |

그래서 2단계의 실제 작업은 "3칸을 만드는 것"이 아니라
**사람 수를 넣고 탭하면 명단이 열리게 하는 것**이다.

⚠️ `get_crew_member_profile`은 `RETURNS jsonb`라 **키를 더해도 시그니처가 안
바뀐다** — `create or replace`로 끝나고 drop이 필요 없다. 즉 0085의
PUBLIC EXECUTE 부활 함정(인수인계서 §4 ⑤)을 안 밟는다.

⚠️ 다만 **남의 팔로잉 명단을 공개할지는 따로 정해야 한다.** 인스타는 공개하지만,
GND에서 그건 "그 사람의 사회 관계"를 드러내는 것이다. 수만 보여주고 명단은
본인만 보는 선택지도 있다.
