## 3. ⚠️⚠️ 화면 조사 — v2가 틀렸던 자리

### 3.1 홈 "나의 크루"는 이모지 자리가 **아니다**

`components/home/friend-board-card.tsx:162`

```tsx
<Image src={row.characterPath} alt={`${row.stageName} 캐릭터`} ... />
```

주석이 못 박아 두고 있다:

> 프로필 이모지가 아니라 **현재 레벨의 캐릭터**를 쓴다(**2026-08-07 사용자 요청**).

**즉 사장님이 지목한 두 곳 중 하나는 이미 캐릭터 그림 자리다.** 여기를 사진으로
갈아 끼우면 2026-08-07 결정을 되돌리는 것이 된다.

**해결 (v3 채택): 사진이 있으면 사진, 없으면 지금처럼 캐릭터.**
아무것도 잃지 않는다 — 08-07 결정이 기본값으로 남고, 사진은 본인이 올릴 때만 덮는다.

### 3.2 챌린지 참가자 아바타는 **클릭이 안 된다**

`challenge/page.tsx:964 · 1232 · 1358` — 전부 `<span>`이다. `MemberProfileSheet`는
피드 · 크루 화면 · 홈 친구목록 **세 곳에서만** 열린다.

즉 **#1의 진입점 자체가 없다.** 그리고 만들어도 막힌다:

| 무엇 | 왜 |
|---|---|
| `get_crew_member_profile`이 `not_crew`를 raise | 같은 챌린지인데 크루가 아닌 사람이 있다 |
| 시트는 이미 그 경우를 처리 중 | `member-profile-sheet.tsx:228` — "크루가 아니에요" 안내만 뜬다 |
| **해결책은 이미 있다** | 0051의 `shares_challenge_with(challenge, user)` — 같은 챌린지 참가자 판정 |

→ RPC 게이트를 `크루` **또는** `같은 챌린지`로 넓힌다. 새 개념이 아니라 0051의 재사용.

### 3.3 아바타 렌더 지점 — 정확한 수

**14곳 / 11파일** (v2의 "15개 파일"은 부정확했다).

| 파일 | 줄 |
|---|---|
| `(tabs)/challenge/page.tsx` | 964 · 1232 · 1358 |
| `components/crew/crew-list.tsx` | 38 · 89 |
| `components/feed/feed-item.tsx` | 106 · 147 |

전부 `{x.avatar_url ?? "👤"}` 꼴로 **글자를 그린다.** 하나라도 놓치면 그 화면에
`https://…`가 **글자로 그대로 노출된다.**

### 3.4 계측이 **0이다**

`track(` · `logEvent` · posthog · gtag — **한 건도 없다.** `workout_events`는
운동 시작/완료/취소 전용이다.

열람권이 0건인 걸 알 수 있었던 건 `record_views` **테이블이 있어서**다.
새 기능은 그 흔적이 없으면 **쓰이는지 영원히 알 수 없다.**

## 5. 작업 계획

### Phase 0-A · #5 프로필 사진 — 하 · **2일** (검증 포함)

| | |
|---|---|
| 있는 것 | `avatars` 버킷(public, 0005) · `avatars_upload_own`/`update_own` · `compressImage()` |
| 컬럼 | `avatar_url text` — **길이 제약 없음.** 0001 주석이 이미 *"이모지 문자 또는 storage 경로"* 라고 적어 뒀다 |
| 마이그레이션 | **0건** (버킷·정책이 이미 있다) |

**함정 4개 — 전부 처리한다**

| # | 함정 | 처리 |
|---|---|---|
| 1 | 이모지/URL 판정이 14곳에 흩어진다 | `domain/avatar-source.ts` **순수 함수 1개** + 테스트. 화면은 판정하지 않는다 |
| 2 | public 버킷에 같은 경로로 덮어쓰면 **브라우저 캐시가 옛 사진을 계속 보여준다** | 경로에 타임스탬프: `{uid}/{Date.now()}.jpg`. 매번 새 URL |
| 3 | 옛 사진이 버킷에 쌓인다 (0005에 **delete 정책이 없다**) | 이번엔 **지우지 않는다.** 8명 규모라 무시 가능. 정책 추가는 별건으로 남긴다 |
| 4 | 렌더 지점 하나만 놓쳐도 URL이 글자로 노출 | 14곳 전부 `<Avatar>`로 교체 + **`?? "👤"` 패턴이 0건임을 테스트가 단언** |

**성공 판정** — 개발 서버에서 눈으로:
사진 올림 → ①프로필 시트 ②홈 크루 목록 ③챌린지 참가자 ④피드 카드 ⑤크루 화면에
**같은 사진**이 뜬다. 안 올린 사람은 홈에서 **캐릭터**, 나머지에서 **이모지**.
어디에도 `http` 글자가 없다.

### Phase 0-B · #1 이력 타임라인 — 하~중 · **3일** (검증 포함)

| | |
|---|---|
| 확장점 | `get_crew_member_profile` (0026 → 0032 → 0039) |
| 더할 것 | `joinedAt` · 레벨업 시점 배열 · 누적 분/일수/미터 |
| 게이트 확장 | 크루 **또는** `shares_challenge_with` (0051 재사용) |
| 핵심 | RPC가 **security definer**라 `user_badges`·`xp_transactions`의 own-only RLS를 서버에서 우회 — **RLS를 열지 않는다** |
| 레벨업 시점 | `xp_transactions` 누적 재생 → `level_definitions` 임계 통과 시각 |
| 진입점 | **챌린지 참가자 3곳을 누를 수 있게 만든다** (지금 `<span>`) |
| 마이그레이션 | **1건** |
| 롤백 | `create or replace`라 **0039의 정의를 다시 Run**하면 원복. 마이그레이션 파일 머리에 그 경로를 적을 것 |

**계측 (v3 신규, 필수)** — 안 하면 열람권 꼴이 난다.
`profile_views` 테이블 1개: `viewer_id · target_id · source('feed'|'crew'|'home'|'challenge') · created_at`.
`record_views`(열람권)와 **다른 테이블**이다 — 섞으면 열람권 통계가 오염된다.

**성공 판정** — 배포 1주 뒤 `profile_views`를 세어 본다.
0건이면 진입점이 안 보이는 것이고, 그때는 **기능을 늘리지 말고 진입점을 고친다.**

  v2·v3가 그 이유로 `/home` 유지를 권했는데 **재 보니 근거가 없었다**
  (2026-08-19 프로덕션 빌드 실측, `next start` + Playwright 콜드 캐시 3회 중앙값).

  | | /home | /record | |
  |---|---|---|---|
  | JS 전송 | 377 KB | **377 KB** | **똑같다** |
  | DB 요청 | 21건 | **18건** | 기록이 3건 적다 |
  | DOM 노드 | 245 | **92** | 기록이 153개 적다 |

  **왜 틀렸나 — 세 가지 착각**
  1. **줄 수를 무게로 봤다.** `record/page.tsx` 3,133줄 중 **575줄(18%)이 주석**이고
     주석은 번들에서 사라진다. 나머지도 대부분 **버튼을 눌러야 도는 핸들러**지
     화면을 켤 때 도는 코드가 아니다.
  2. **이 앱은 공유 번들이 지배적이다.** 라우트를 갈라도 전송량이 안 변한다(377KB 동일).
  3. **홈이 오히려 더 많이 그린다** — 크루 목록·챌린지 요약·캐릭터·주간통계·스트릭.

  → **성능은 이 결정의 판단 근거가 아니다.** 진짜 트레이드오프는 아래.

- **진짜로 잃는 것: 첫 화면에서 크루·챌린지가 밀린다.** 4명 중 2명이 이탈한 지금
  사회적 자극이 첫 화면에서 사라지는 건 실제 비용이다. 두 상태 카드에 크루 한 줄을
  같이 넣을지 화면 설계에서 다시 본다.
- ⚠️ `src/app/page.tsx`의 utm 전달을 **반드시 유지**한다(그 파일 주석 참조).
  `/home` → `/record`로 목적지만 바꾸고 쿼리스트링 전달은 그대로 둔다.
- ⚠️ **운동 중(active session)일 때 랜딩**을 따로 확인한다. 기록 화면이 타이머·
  오버레이·idle guard를 띄운다 — 이 실측은 운동 중이 아닌 계정으로 쟀다.
- 어느 쪽이든 **두 상태는 배타적이다**:
