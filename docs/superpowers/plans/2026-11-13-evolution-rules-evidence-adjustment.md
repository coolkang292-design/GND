### 2.1 꾸준함 1회의 정의 (변경점)

**이전(폐기):** 이번 단계 진입 후 겹치지 않는 연속 4주 구간에서 **4주 모두** 주 2일 이상.
**변경:** 4개의 연속 달력 주(월~일, Asia/Seoul) 중 **3주 이상**에서 서로 다른 운동일이 **주 2일 이상**이면 1회.

- 달력 주는 월요일 시작, `completed_at`을 Asia/Seoul 날짜로 환산한 **서로 다른 날짜**로 센다(0134의 운동일 계산과 같은 방식).

- 완료·미삭제 세션만, 무효/취소 세션은 제외(성장 계산과 같은 기준).

## 4. 시험 기준 (일부러 고장냈을 때 실패해야 한다)

- 목표 2·3은 XP만 충족하면 습관·성장·미션과 무관하게 통과.
- 4단계: 운동 35일은 보류, 36일은 통과(성장 조건 충족 시). 대체 경로는 53일 보류/54일 통과.
- 5단계: 미션 0회면 성장·운동일을 채워도 보류, 1회면 통과. 대체 경로 89일 보류/90일 통과(**미션 0회여도 통과** — 면제). 90일 미만이면 미션 면제도 없다.
- 6·7단계: 경과 주만 판정(운동일 100/156 조건 없음), 39주 보류/40주 통과. 최근 활동 28일 중 7일 보류/8일 통과, 7단계는 11/12일.
- 꾸준함: 4주 중 3주 충족 = 1회, 2주 충족 = 0회, 구간이 겹치지 않게 센다(8주 연속 충족 = 2회, 7주 = 1회). 주 경계(월요일 00:00 KST)와 진입 주의 부분 주, 한 날 여러 번 운동(1일)을 모두 시험한다.
- N 부족은 평균이 높아도 보류, M=0으로 N=0이 되어 자동 통과하지 않는다, 최종 단계 `nextStage=null`, 반올림 전 판정.
- 단언 0건인 시험(픽스처가 비는 경우)은 개수 가드를 둔다.

| 구간 탐색 | 단계 진입 주(월요일)부터 시작. 충족하면 4주 건너뛰고, 아니면 **한 주씩 밀어** 다음 구간을 찾는다 | 앞에서부터 탐욕적. `[0,0,2,2,2,2,2,2]`(8주)=1회 |
| 진입 날짜 | `user_stage_history.entered_at`(KST 날짜). 0135가 `user_level_history`의 해당 단계 첫 레벨 진입 시각으로 채운다 | 지시서 §2.1이 "구현 시 확인해 기록"하라고 한 항목 |
| 대체 경로 사용 자격 | **누구나** 쓸 수 있다(성장 기록이 없는 사람만이 아니다). 성장 경로와 대체 경로 중 하나를 채우면 된다 | §13 표의 "성장 대신". 측정했지만 성장이 모자란 사람도 우회 가능 — 의도와 다르면 알려 달라 |
| 대체 경로 + 습관 | 대체 경로는 **성장 조건만** 대신한다. 경험치·습관·6·7단계 최근 활동은 그대로 필요 | 기존 계약(`evaluate`)과 같은 구조 |
| 면제 범위 | 5단계 운동일 90일 경로만(`alt_exempts_steady`). 90일 미만이면 꾸준함 1회가 필요 | 사용자 확정, 시험 3건 |
| 반올림 | 평균은 반올림 전 값으로 `>=` 비교(2.99999는 3% 미달) | 시험 |
| `evolution.ts`의 옛 `EVOLUTION_REQUIREMENTS` | **건드리지 않았다.** 서버 규칙 미설치 상태의 옛 클라이언트 미리보기가 쓴다. 새 규칙 표는 `evolution-gate.ts`의 `STAGE_RULES` | 지시서 밖. 서버를 켠 뒤 옛 미리보기 제거 여부를 별도로 정한다 |

### 8.2 만든 것

- `0133`: `stage_evolution_rules`에 `habit_kind`·`steady_required`·`alt_days`·`alt_steady_required`·`alt_exempts_steady` 추가, 확정 수치로 교체, 제약(4·5=일만, 6·7=주만, 대체는 한 종류, 면제는 운동일 경로에만).
- `0134`: `gnd_evolution.steady_count`(순수 함수) + `stage_status`에 습관 종류별 판정·꾸준함·대체 경로·면제, JSON에 `steady` 조건과 `alternate`·`path` 추가.
- `evolution-gate.ts`: `STAGE_RULES`, `countSteadyWindows`, `evaluateStageGate`(SQL과 독립 구현), 서버 계약 `steady`·`alternate`·`path:'alternate'`. 옛 `DRAFT_GROWTH_RATIOS` 제거.
- 화면 `stage-evolution-status.tsx`: 꾸준함 행·대체 경로 행·설명 문구(재촉·죄책감 문구 없음), `stage-guide-sheet.tsx` 문구.
- 시험: `evolution-gate.test.ts` 35건(경계값 36/35·54/53·90/89·39/40주·28중7/8·42중11/12·월요일 경계·진입 주 부분 주·한 날 여러 번), 화면 3건 추가.

### 8.3 검증

- 관련 vitest 167파일 **3,055건 통과**, `pnpm typecheck` 0건.
- **일부러 고장 낸 4가지가 모두 시험에 잡혔다**(3/4→4/4, 구간 끝 조건 제거, 면제 제거, 진입 이전 날짜 포함).
- **SQL `steady_count`**: `pg_temp`(운영 스키마 무변경)에서 TS 시험과 **같은 20개 벡터**를 돌려 전부 일치. 임시 객체는 세션과 함께 사라졌고 `public`에 남은 것 없음.
- **로컬 PGlite 시험(사용자 승인 후 설치, 2026-11-13)**: PGlite 0.3.14(PostgreSQL 17.5, 메모리 전용)를 repo 밖 임시 폴더에 설치. 운영 DB·.env에 접속하지 않는다. `node scripts/evolution-gate-check.mjs` **64건 통과/0 실패**(0133~0136을 순서대로 로드, 운영 현행 함수 정의는 `docs/db-current-schema.sql` 스냅샷 사용), `evolution-gate.sql.test.ts` 통과(SQL·TS 점수 대조).
  - 시험이 잡은 **실제 버그 1건**: 0134에 꾸준함 함수를 넣을 때 JS `String.replace`가 `$$`를 `$`로 바꿔 함수 구분자가 깨졌다(`syntax error at or near "$"`). 고쳤다. ⚠️ 마이그레이션을 스크립트로 편집할 때 `$$`가 든 문자열을 `replace`에 문자열로 넘기지 말 것(함수 형태 사용).
  - 옛 규칙 전제 시험 2건을 새 규칙에 맞춰 고치고(5단계는 진입 이후 꾸준함 필요) 시험을 추가: 꾸준함 20벡터(TS와 동일), 진입 이후 4주 → 1회, 5단계 대체 경로 89일(통과 안 함)/90일(꾸준함 0회여도 통과, `path:alternate`).
  - **SQL 고장 주입 4종 모두 시험이 잡는다**(면제 제거, 3/4→4/4, 구간 끝 조건 제거, 진입 이전 날짜 포함). 처음에는 2종을 못 잡아 위 20벡터를 추가했다.
