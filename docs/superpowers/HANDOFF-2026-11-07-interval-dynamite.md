## 개발 화면 직접 확인

`localhost:3000/interval-audio-qa` 임시 페이지에서 **실제 TabataSheet·오버레이·HTML audio**를 재사용했다. 계정 선택은 로컬 설정의 실제 고유번호를 넘겼고, 세션 생성/완료/취소 콜백만 메모리 카운터로 대체해 운영 운동 기록을 만들지 않았다. 루트의 개발 전용 QA 플래그로 인증·트래커 실행을 막았다.

- Chrome에서 세 대상의 새 음원과 일반 계정의 기존 4/8/16분 파일을 확인했다. 코스 선택 때는 재생되지 않았다.
- 4분: 시작·일시정지·재개·13/33/43초 운동/휴식·파일 끝 자연 종료를 확인했다.
- 8분: 263초 9/16라운드 운동20초, 283초 휴식10초를 화면에서 확인했다. 파일 끝의 자연 완료도 확인했다.
- 16분: 763초 25/32라운드 운동20초와 자연 완료를 확인했다.
- 중단: 실제 버튼을 눌러 취소 콜백1회, audio.paused=true/currentTime=0, 준비 화면 복귀를 확인했다. 내장 브라우저의 네이티브 confirm 처리가 멈춰 Chrome의 검사 페이지에서 확인 응답만 자동 허용했다. 제품의 confirm 코드는 바꾸지 않았다.
- 390×844 화면에서 배경음 제목·시간 버튼·시작 버튼을 확인했다. 스크린샷: 루트 `artifacts/interval-audio/interval-dynamite-390.png`(Git 제외).

4. 검증된 로컬 main의 깨끗한 복사본으로 프로젝트 지정 CLI 방식(`--scope gnd4`)으로 배포한다. 소스·배경음 3개·계정별 선택과 운영 화면을 다시 확인한다. 실사용자 알림은 발송하지 않는다.
