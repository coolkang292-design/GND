# 기록 갱신 보상 설계 (A안)

## 목표

지난 운동을 복사한 예정표로 운동을 완료했을 때 원본 세션보다 성과가 크면 — 완료 화면 축하 + 피드 🏅 뱃지 + 크루 알림(푸시 자동)을 준다. (사용자 확정 2026-07-19: A안, 유형별 합계 아무거나 기준)

## 판정 규칙

- 대상: `sourceSessionId`가 있는 운동만 (복사 예정표 → 운동 준비하기 경로). 그 외 운동은 판정하지 않는다.
- 비교: 원본의 **완료 세트** 합계 vs 이번 운동의 **완료 세트** 합계.
- 지표(우선순위 순): 웨이트 총볼륨 kg → 맨몸 총횟수 → 맨몸 시간 분 → 유산소 거리 km → 유산소 시간 분.
- **원본에 실적이 있던 지표만 비교 대상** (원본 0인 지표는 새 종목 추가일 뿐 갱신 아님). 첫 초과 지표로 문구 생성: "볼륨 +12kg", "횟수 +15회", "맨몸 시간 +3분", "거리 +0.5km", "유산소 +5분".
- 판정·문구는 순수 도메인(`lib/domain/record-beaten.ts`) TDD.

## 구성

1. **draft v4**: `WorkoutDraft.sourceSessionId` 추가(기본 null, v3 로드 시 null 보강). 예정표 불러올 때 `plan.sourceSessionId` 저장, 완료·초기화 시 리셋.
2. **0018 마이그레이션** (사용자 SQL Editor 적용): ①`workout_sessions.record_note text`(널 허용) ②notifications type 체크에 `record_beaten` 추가 ③`mark_record_beaten(p_session_id, p_note)` definer RPC — 본인·완료 세션·record_note 미설정·문구 1~40자만 허용, 설정 후 같은 크루원(본인 제외)에게 알림 insert → 0016 트리거가 푸시 자동 발송.
3. **완료 흐름**: `handleFinish`에서 완료 성공 후 원본(`getSessionLogExercises`)과 비교 → 갱신이면 RPC 호출 + 완료 화면에 "🏅 기록 갱신! 지난번보다 볼륨 +12kg". **판정·RPC 실패는 완료 흐름을 막지 않는다**(비프음 원칙).
4. **표시**: 피드 카드에 record_note 있으면 "🏅 기록 갱신 · 볼륨 +12kg" 뱃지. 달력 날짜 상세의 세션 행에도 🏅 표시.
5. **푸시 URL**: `record_beaten` 알림 탭 → `/feed`.
