# 챌린지 초대 링크 온보딩 수정 설계

## 목표

새 사용자가 챌린지 초대 링크를 누르면 일반 크루 가입 화면으로 빠지지 않고 아래 흐름만 거친다.

`초대 링크 → 닉네임 입력 → 챌린지 참가하기 → 챌린지 화면`

## 원인

현재 `/challenge?join=CODE`의 코드는 챌린지 화면의 `useEffect`에서 저장한다. 프로필이 없는 새 사용자는 `OnboardingGate`가 먼저 `/onboarding`으로 이동시킬 수 있어, 코드가 저장되기 전에 원래 주소가 사라진다.

## 확정 설계

1. `OnboardingGate`가 프로필 조회를 시작하기 전에 현재 주소의 `join` 코드를 즉시 보관한다.
2. 프로필이 없는 사용자는 기존처럼 `/onboarding`으로 이동한다.
3. 온보딩이 보관된 챌린지 코드를 발견하면 챌린지 전용 화면으로 표시한다.
   - 표시: 초대 안내, 닉네임 입력, `챌린지 참가하기` 버튼
   - 숨김: 프로필 사진 선택, 주간 운동 목표, 크루 만들기·크루 참여·혼자 시작 버튼
4. 버튼을 누르면 기본 프로필 값을 저장하고 `join_challenge_with_code`를 호출한 뒤 `/challenge`로 이동한다.
5. 이미 프로필이 있는 사용자는 현재처럼 링크를 누르는 즉시 챌린지에 참가한다.
6. 기존에 공유된 `/challenge?join=CODE` 링크도 그대로 지원한다.

## 오류 처리

- 닉네임이 비어 있으면 참가하지 않고 입력 안내를 보여준다.
- 챌린지 참가에 실패하면 코드를 지우지 않고 같은 화면에서 오류를 보여줘 다시 시도할 수 있게 한다.
- 참가 성공 뒤에만 보관한 코드를 지우고 챌린지 화면으로 이동한다.

## 검증

- 코드 저장보다 온보딩 이동이 빨랐던 상황을 자동 테스트로 재현한다.
- 챌린지 초대 모드에서 닉네임과 `챌린지 참가하기`만 보이는지 확인한다.
- 참가 성공 시 코드 삭제와 `/challenge` 이동을 확인한다.
- 참가 실패 시 코드가 남고 크루 화면으로 가지 않는지 확인한다.
- 기존 사용자 즉시 참가 흐름과 전체 테스트를 확인한다.
