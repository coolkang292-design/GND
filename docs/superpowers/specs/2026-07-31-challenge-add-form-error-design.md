# 챌린지 추가 화면·오류 문구 수정 설계

## 목표

챌린지 추가 화면을 처음 보는 사람도 바로 새 이름을 입력할 수 있게 하고, 오류가 생겼을 때 `오류: [object Object]` 대신 실제 원인을 읽을 수 있게 한다.

## 확인된 원인

1. Supabase 오류는 `Error` 객체가 아니라 `{ message, code, details, hint }` 모양의 일반 객체로 올 수 있다. 현재 `String(error)`가 이를 `[object Object]`로 바꾼다.
2. `openSheet("create")`가 이름 기본값을 `${현재 월}월 GND 챌린지`로 넣어 새 챌린지에도 기존처럼 보이는 이름이 미리 표시된다.
3. 추가 진입 버튼 문구가 `챌린지 하나 더 만들기`라 짧은 행동 이름보다 길고 어색하다.

## 사용자 화면

- 기존 챌린지가 있을 때 생성 진입 버튼은 `＋ 챌린지 추가하기`로 표시한다.
- 추가 화면의 이름칸은 빈칸으로 연다.
- 이름칸에는 `챌린지 이름을 입력하세요` 안내 문구를 표시한다.
- 화면이 열리면 이름칸에 커서를 자동으로 둬 바로 입력할 수 있게 한다.
- 빈 이름으로 저장하면 기존 검증 문구 `챌린지 이름을 입력하세요`를 그대로 보여준다.

## 오류 처리

- `Error` 인스턴스면 기존처럼 `message`를 읽는다.
- 일반 객체에 문자열 `message`가 있으면 그 값을 읽는다.
- 알려진 서버 오류 코드는 기존 한글 안내로 바꾼다.
- 어떤 형태인지 알 수 없는 값은 `[object Object]`를 노출하지 않고 `알 수 없는 오류`로 처리한다.

## 수정 범위

- `src/app/(tabs)/challenge/page.tsx`
  - 오류 메시지 추출 보강
  - 생성 버튼 문구 변경
  - 생성 모드 이름 기본값을 빈 문자열로 변경
- `src/components/challenge/setup-sheet.tsx`
  - 이름 입력 안내 문구와 자동 커서 추가
- 관련 테스트 파일
  - 일반 객체 오류 메시지
  - 버튼 문구
  - 빈 이름칸·안내 문구·자동 커서

## 수정하지 않는 것

- 데이터베이스 구조와 마이그레이션
- 기존 챌린지 이름
- KPI 계산과 챌린지 생성 순서
- 초대·참가·랭킹 기능
- 운영 배포는 구현과 로컬 검증 뒤 별도 승인을 다시 받은 후 진행한다.

## 성공 기준

1. 새 챌린지 추가 화면에서 이름칸이 비어 있고 바로 입력할 수 있다.
2. 버튼에 `챌린지 추가하기`가 표시된다.
3. 일반 객체 형태의 서버 오류가 `[object Object]`로 보이지 않는다.
4. 관련 테스트와 전체 `lint`, `typecheck`, `test`, `build`가 통과한다.
