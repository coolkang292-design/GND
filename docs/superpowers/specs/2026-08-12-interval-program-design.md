# 고강도 인터벌을 공식 프로그램으로 — 설계

> 작성: 2026-08-12
> 상태: 설계 확정, 구현 전
> 선행: 0066(등록·재배치) · 0067(진행 보존·체감) · 0068(소유권 함수 보안) · 0069(연속 요일 허용)

## 1. 목표

공식 프로그램 6번째로 **고강도 인터벌 6주 프로그램**을 추가한다. 지금 인터벌은
운동 추가 허브에서 즉흥으로 시작하는 단발 기능이라, "6주 뒤에 무엇이 달라지는가"가
없다.

성공 기준:

- 등록하면 18회가 달력에 담기고, 회차마다 **무엇을 몇 분** 할지가 정해져 있다
- 처음 하는 사람이 1주차에 그만두지 않는다 — **1~2주에 점프가 없다**
- 6주가 진행되며 **양이 자란다** (4분 → 8분 → 16분)
- 기존 5종 프로그램의 동작이 **하나도 바뀌지 않는다**

## 2. 두 가지 구조 충돌 — 이 설계의 출발점

프로그램 회차는 **근력 모양**이고 인터벌 회차는 **시간 모양**이다. DB가 근력
모양을 강제한다(0066, 0069가 이어받음).

| 제약 | 현재 | 인터벌 | 결과 |
|---|---|---|---|
| `jsonb_array_length(plan.exercises)` | `5~6` | **4** | `program_invalid_exercises` |
| `prescription.restSeconds` | `60~300` 필수 | **10초**(음원이 정함) | `program_invalid_prescription` |
| `level_at_start` | `beginner`·`experienced` | 3단계 필요 | `check` 위반 |

`workout_plans.tabata_minutes`(4·8·16)는 0059에 **이미 있다.** 여기는 안 막힌다.

두 번째 충돌: `OfficialProgram.sessions`는 `[A, B, C]` 셋뿐이고 6주가 이 셋을
그대로 반복한다. **주차별로 종목을 바꿀 자리가 없다.**

이 설계는 두 충돌을 이렇게 푼다.

- 첫 번째: RPC가 **`tabata_minutes`가 있으면 인터벌 모양으로** 검증한다 (0070)
- 두 번째: **주차 차원을 추가하지 않는다.** 난이도를 사용자가 고르게 해서
  난이도가 단계를 대신하고, 양(길이)만 주차가 올린다

## 3. 결정 사항

### 3.1 범위 — 전용 프로그램 1종

기존 5종에 섞지 않는다. 한 프로그램 안에 근력 회차와 인터벌 회차가 섞이면
18회 진행률·재배치·무게 추천·노력 피드백이 전부 "이 회차는 어느 종류인가"로
갈라진다. 방금 만든 `initialProgramLoad`·`shouldAskEffort`·종목별 휴식은
인터벌 회차에서 의미가 없다.

### 3.2 난이도를 사용자가 고른다 — 단계 대신

등록 3단계 화면에 이미 `초보 / 운동 경험 있음` 선택이 있다(`levelAtStart`).
여기에 값을 하나 더해 **3단계**로 만든다.

| 값 | 표시 | 성격 |
|---|---|---|
| `beginner` | 입문 | 점프·착지 충격 0 |
| `moderate` | **새 값** · 보통 | 저충격 점프 |
| `experienced` | 높음 | 폭발력 |

기존 등록 행은 `beginner`·`experienced` 그대로 두고 `moderate`만 추가하므로
**기존 데이터를 건드리지 않는다.**

⚠️ 기존 근력 5종에서 `experienced`는 "운동 경험 있음"이었고 세트 수만 늘렸다.
인터벌에서는 "높음"으로 읽힌다. 같은 컬럼을 두 뜻으로 쓰는 셈이지만, 프로그램마다
라벨을 다르게 보여 주면 사용자에게는 갈라지지 않는다. 라벨은 프로그램 정의가 준다.

### 3.3 종목 조합 9개

4종목을 **기능 슬롯**으로 고정한다: `하체` · `밀기` · `코어·후면` · `전신`.
한 라운드에 같은 부위를 연속으로 때리면 자세가 먼저 무너진다.

**당기기(풀업·인버티드 로우)는 뺀다** — 철봉이 있어야 해서 집에서 못 한다.
**시간형(플랭크·월 싯·매달리기·핸드스탠드·사이드 플랭크)도 뺀다** — 지금 인터벌
기록은 횟수로 저장돼서(`tabataRepsForMinutes`) 시간형이 들어가면 어긋난다.

아래는 전부 `exercise_catalog`에 실재하는 맨몸 종목이다(2026-08-12 실측 44종에서 선택).

**입문 — 점프·착지 충격 0**

| 회차 | 하체 | 밀기 | 코어·후면 | 전신 |
|---|---|---|---|---|
| A | 맨몸 스쿼트 | 니 푸시업 | 데드버그 | 마운틴 클라이머 |
| B | 와이드 스쿼트 | 라잉 Y 레이즈 | 버드독 | 인치웜 푸시업 |
| C | 리버스 런지 | 니 푸시업 | 슈퍼맨 로우 | 마운틴 클라이머 |

**보통 — 저충격 점프**

| 회차 | 하체 | 밀기 | 코어 | 전신 |
|---|---|---|---|---|
| A | 리버스 런지 | 푸시업 | 마운틴 클라이머 | 점핑잭 |
| B | 사이드 런지 | 파이크 푸시업 | 바이시클 크런치 | 하이 니 |
| C | 런지 | 와이드 푸시업 | 레그 레이즈 | 점핑잭 |

**높음 — 폭발력**

| 회차 | 하체 | 밀기 | 코어 | 전신 |
|---|---|---|---|---|
| A | 점프 스쿼트 | 와이드 푸시업 | 브이 업 | 버피 |
| B | 피스톨 스쿼트 | 타이슨 푸시업 | 러시안 트위스트 | 하이 니 |
| C | 점프 스쿼트 | 인치웜 푸시업 | 플러터 킥 | 버피 |

⚠️ **이 조합은 기본값이지 처방이 아니다.** 의학·전문가 검수를 거치지 않았다.
`피스톨 스쿼트`·`타이슨 푸시업`은 난도가 높고, 높음 A·C는 카탈로그의 폭발적 하체
종목이 셋뿐이라 `점프 스쿼트`·`버피`가 겹친다. 사용자가 등록 전에 고칠 수 있게
하는 것(§3.5)이 이 한계에 대한 답이다.

### 3.4 주차가 양을 올린다 — 난이도별 상한

음원이 3개(4·8·16분)뿐이고 20초/10초 박자를 정하므로, 올릴 수 있는 것은 길이뿐이다.

| 주차 | 입문 | 보통 | 높음 |
|---|---|---|---|
| 1~2주 | 4분 | 4분 | 8분 |
| 3~4주 | 8분 | 8분 | 16분 |
| 5~6주 | **8분** | 16분 | 16분 |

**입문은 16분에 가지 않는다.** 16분은 32라운드, 종목당 8라운드다. 점프도 안 해 본
사람이 5주차에 그걸 하면 그 주에 그만둔다. 입문을 마친 사람의 다음 단계는
**보통으로 다시 등록**하는 것이다.

난이도(종목)와 주차(길이)는 **직교**한다. 둘이 서로를 참조하지 않으므로 표가
단순하고, 나중에 한쪽만 바꿀 수 있다.

### 3.5 등록 전에 회차 단위로 고친다

3/3 미리보기가 지금은 **날짜만** 보여 준다. 여기에 회차(A·B·C) 탭과 종목 목록을
놓고, 종목을 누르면 교체 피커를 연다.

**A·B·C가 6주 반복이므로 3번만 고치면 18회 전체에 반영된다.**

이미 있는 것을 잇는다 — 프로그램 상세의 A/B/C 탭(`746377d`)과 `ExercisePicker`.

운동 **시작 전** 수정은 이미 된다(준비 카드의 `✕` 삭제·`＋ 운동 추가`). 다만 그건
그 회차 하나만 바꾸므로, 6주 내내 싫은 종목은 등록 전에 고치는 편이 낫다.

이번 범위는 **인터벌 프로그램에 한정**한다. 근력 프로그램의 회차 편집은 같은
장치로 열 수 있지만 이번에는 하지 않는다.

### 3.6 실행은 전체화면

지금 인터벌은 `max-h-[88dvh]` **바텀시트**라 위쪽에 원래 화면이 비친다. 일반 운동은
`top-0 ~ bottom:0` 전체화면이다. 같은 프로그램인데 경험이 갈린다.

**시트는 고르는 화면으로만 남긴다**(코스·4종목 선택). `시작`을 누르면 시트가 닫히고
**새 전체화면 컴포넌트**가 열린다.

```
● 지금 인터벌 중              3라운드 / 8라운드
─────────────────────────────
        마운틴 클라이머            ← 지금 종목 (크게)
            00:14                 ← 20초 카운트다운 (아주 크게)
─────────────────────────────
   다음: 니 푸시업
   [일시정지]   [중단]
```

**새 파일로 만든다** — `ActiveSessionOverlay`에 인터벌 모드를 더하지 않는다. 그
파일은 이미 600줄이 넘고 세트 입력·휴식 두 모드를 갖고 있다. 세 번째 모드를 더하면
다루기 어려워진다.

## 4. 데이터 모양

### 4.1 타입

```ts
export type ProgramLevel = "beginner" | "moderate" | "experienced";

/** 난이도마다 다른 종목을 쓰는 경우. 문자열이면 세 난이도가 같다. */
export type LeveledExerciseName = string | Record<ProgramLevel, string>;

export type ProgramExerciseTemplate = ExercisePrescription & {
  exerciseName: LeveledExerciseName;   // ← 문자열도 계속 받는다
  beginnerSets: number;
  experiencedSets: number;
};

export type OfficialProgram = {
  // ...기존 필드
  /** 없으면 "strength" — 기존 5종은 정의를 안 고쳐도 된다 */
  kind?: "strength" | "interval";
  /** kind === "interval"일 때만. 난이도별 주차 길이 */
  minutesByWeek?: Record<ProgramLevel, readonly [4|8|16, ...]>;
  /** 난이도 라벨 — 근력은 "초보/…/운동 경험 있음", 인터벌은 "입문/보통/높음" */
  levelLabels?: Record<ProgramLevel, string>;
};
```

**기존 5종은 한 줄도 안 바뀐다** — `exerciseName`이 문자열이고 `kind`가 없으면
지금과 동일하게 동작한다.

### 4.2 계획 행

새 테이블을 만들지 않는다. 인터벌 회차도 `workout_plans` 한 줄이다.

```
tabata_minutes        = 4 | 8 | 16      ← 주차가 정한다 (0059에 이미 있는 컬럼)
exercises             = 4종목 · 각 1세트 · prescription 없음
program_enrollment_id = 인터벌 프로그램 등록
program_week/session  = 1~6 / 1~3       (그대로)
```

`tabata_minutes`가 있으면 인터벌 회차다. 이 한 컬럼이 판별자다.

## 5. 마이그레이션 0070

⚠️ 적용된 0066~0069는 고치지 않는다. 새 번호로 덮어쓴다. 본문은
`docs/db-current-schema.sql`의 **현행 정의**(0069 적용 뒤 재생성한 것)에서 옮긴다.

1. **`program_enrollments.level_at_start`** check에 `moderate` 추가
   - 기존 행은 손대지 않는다
2. **`create_program_enrollment`**
   - `p_level_at_start` 검증에 `moderate` 추가
   - 계획 payload에 `tabata_minutes` 허용 — `null` 또는 `4|8|16`
   - **`tabata_minutes`가 있으면 인터벌 모양으로 검증**
     - 종목 정확히 4개 · 각 세트 1개 · `prescription` 없어도 통과
   - 없으면 기존 근력 모양 그대로 (종목 5~6개 · `prescription` 필수)
   - `insert into public.workout_plans`에 `tabata_minutes` 열 추가
3. 권한은 0066·0069와 동일하게 다시 명시

**배포 순서: 0070 Run → 앱 배포.** 반대로 하면 사용자가 인터벌 프로그램을 고를 수
있는데 서버가 등록을 거절한다.

## 6. 구현 단계

세 덩어리로 나눈다. 각 덩어리가 끝날 때마다 초록이어야 한다.

**1단계 — 데이터와 카탈로그 (DB 불필요)**
`ProgramLevel`·`LeveledExerciseName`·`kind`·`minutesByWeek` 타입, 인터벌 프로그램
정의(9조합), 난이도별 종목 해석, 주차별 길이 계산. 전부 순수 함수라 TDD로 고정한다.
기존 5종 스냅샷 테스트가 안 바뀌는 것이 회귀선이다.

**2단계 — 등록 흐름 (0070 필요)**
난이도 3단계 선택, 계획 payload에 `tabata_minutes`, 3/3 미리보기의 회차 편집,
`0070` 작성·정적 검토 → 사용자 적용 → 실제 등록 확인.

**3단계 — 실행 화면**
`interval-session-overlay.tsx` 신설, 음원·라운드 로직을 시트에서 이관, 시트는
고르기 전용으로 축소.

## 8. 미정 · 위험

**미정**
- **대표 이미지 주인.** `lean.webp`가 인터벌 실루엣인데 지금은 `근육을 지키는
  체지방 관리 6주`가 쓴다. 인터벌 프로그램에 넘길지, 체지방 쪽에 새 이미지를 줄지
  사용자가 정한다
- 프로그램 `key`·제목·설명 문구

**위험**
- **3단계 실행 화면 이관이 가장 큰 변경이다.** 음원 재생·라운드 계산이 지금 시트
  안에 있다. 옮기다 놓치면 인터벌이 통째로 망가진다 — 이관 전에 현재 동작을
  테스트로 먼저 고정한다
- **조합이 검수되지 않았다**(§3.3). 등록 전 편집이 완화책이지만, 기본값 자체는
  사람이 한 번 봐야 한다
- **16분 = 32라운드의 실제 부하**는 화면에서 해 봐야 안다. 표로는 판단할 수 없다
- `experienced`가 근력에서는 "경험 있음", 인터벌에서는 "높음"으로 읽힌다.
  라벨을 프로그램이 주므로 화면은 갈라지지 않지만, 데이터만 보는 사람은 헷갈릴 수 있다
