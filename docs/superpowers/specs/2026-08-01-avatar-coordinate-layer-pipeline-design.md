# GND 좌표 기반 캐릭터 아이템 제작·장착 설계

작성일: 2026-08-01
대상 저장소: `C:\Users\SAMSUNG\workout-app`

## 1. 결정

GND의 꾸미기 화면은 `잘라낸 투명 아이템 이미지 + 1024×1536 기준 좌표`로
실시간 합성한다. 피드·프로필처럼 편집이 필요 없는 화면은 향후 장착 결과를 한 장으로
합친 캐시 이미지를 사용할 수 있다.

이 문서는
`docs/superpowers/specs/2026-08-01-avatar-shop-clickable-mockup-design.md`의 구매·장착
목업 범위는 유지하면서, 6장의 이미지 제작과 화면 합성 규칙을 좌표 기반 방식으로
교체한다. 이전 문서의 전체 캔버스 아이템 배포 규칙과 “신체 좌표를 측정하지 않는다”는
결정은 이 문서로 대체한다.

## 2. 목표와 성공 기준

### 목표

사용자가 제공한 가로형 완성 이미지의 불독 외형과 자세를 참고해 장착 전용 기준
캐릭터를 만들고, 캡·선글라스·후드티·조거 팬츠·신발·시계를 별개 자산으로 준비한다.
개발 서버에서는 캡의 목업 구매·장착·해제 흐름까지 완성한다.

### 성공 기준

- 기준 캐릭터는 `1024×1536`이며, 검은 밀착 민소매·숏팬츠·맨발이다.
- 얼굴·체형·팔·다리 자세는 확정 뒤 바뀌지 않는다.
- 머리, 귀, 눈, 코, 목, 어깨, 허리, 손목, 발의 기준 좌표가 JSON으로 기록된다.
- 아이템 6종은 각각 캐릭터가 섞이지 않은 투명 PNG로 존재한다.
- 각 아이템은 잘라낸 이미지와 `x/y/width/height/z` 명세를 가진다.
- 캡을 장착한 화면이 320px, 390px, 430px 폭에서 같은 위치로 보인다.
- 캡 카드 선택, 목업 구매, 장착, 해제, 재장착이 개발 서버에서 동작한다.
- 실제 지갑, 보유 목록, 데이터베이스에는 쓰지 않는다.
- 운영 배포는 이 단계에 포함하지 않는다.

## 3. 기준 이미지와 좌표계

사용자가 제공한 `256×200` 가로형 장면은 외형·자세·아이템 디자인 참고 이미지다.
장면 속 캐릭터 좌표를 런타임 좌표로 직접 사용하지 않는다. 배경과 차량이 포함돼 있고
최종 아바타 캔버스 비율과 다르기 때문이다.

제작 순서는 다음과 같다.

1. 첨부 이미지를 참고해 동일한 불독 외형과 자세의 최소 복장 기준 캐릭터를 만든다.
2. 기준 캐릭터를 `1024×1536` 투명 캔버스 중앙에 고정한다.
3. 확정된 기준 캐릭터에서 신체 좌표와 카테고리 마스크를 측정한다.
4. 이후 모든 아이템은 이 기준 캐릭터와 좌표만 사용한다.

좌표 원점은 기준 캔버스의 좌상단 `(0, 0)`이다. 좌표는 원본 픽셀 정수로 저장하고,
화면에서는 다음 비율로 변환한다.

```text
left%   = x / 1024 × 100
top%    = y / 1536 × 100
width%  = width / 1024 × 100
height% = height / 1536 × 100
```

미리보기 영역은 `aspect-ratio: 2 / 3`을 유지한다. 따라서 휴대폰 폭이 바뀌어도
기본 캐릭터와 아이템이 같은 비율로 축소된다.

## 4. 신체 좌표 명세

`landmarks.json`은 다음 정보를 저장한다.

```json
{
  "canvas": { "width": 1024, "height": 1536 },
  "points": {
    "headTop": [0, 0],
    "headCenter": [0, 0],
    "leftEar": [0, 0],
    "rightEar": [0, 0],
    "leftEye": [0, 0],
    "rightEye": [0, 0],
    "nose": [0, 0],
    "neckCenter": [0, 0],
    "leftShoulder": [0, 0],
    "rightShoulder": [0, 0],
    "waistCenter": [0, 0],
    "leftWrist": [0, 0],
    "rightWrist": [0, 0],
    "leftFoot": [0, 0],
    "rightFoot": [0, 0]
  },
  "regions": {
    "head": [0, 0, 0, 0],
    "eyes": [0, 0, 0, 0],
    "top": [0, 0, 0, 0],
    "bottom": [0, 0, 0, 0],
    "leftWrist": [0, 0, 0, 0],
    "feet": [0, 0, 0, 0]
  }
}
```

위 예시는 구조만 정의한다. `0` 값은 구현 단계에서 확정된 기준 캐릭터를 실제로
측정해 채운다. 좌표가 없는 상태에서는 아이템 생성이나 앱 장착을 시작하지 않는다.

카테고리별 기준은 다음과 같다.

| 아이템 | 기준점·영역 |
|---|---|
| 캡 | 머리 최상단, 머리 중심, 양쪽 귀, head 영역 |
| 선글라스 | 양쪽 눈, 코, 양쪽 귀, eyes 영역 |
| 후드티 | 목 중심, 양쪽 어깨, 허리, top 영역 |
| 조거 팬츠 | 허리, 양쪽 발, bottom 영역 |
| 신발 | 양쪽 발, feet 영역 |
| 시계 | 기준 손목, wrist 영역 |

## 5. 이미지 제작 파이프라인

### 5.1 기준 캐릭터

기준 캐릭터는 첨부 이미지를 참조하는 identity-preserve 편집으로 만든다.

- 유지: 불독 얼굴, 체형, 비율, 팔·다리 자세, 카메라 방향
- 제거: 캡, 선글라스, 후드티, 조거 팬츠, 신발, 시계, 차량, 실내 배경
- 추가: 검은 밀착 민소매, 검은 밀착 숏팬츠, 맨발
- 배경: 단색 크로마키, 그림자·반사·바닥 없음
- 출력: `1024×1536`

기본 경로는 built-in ImageGen으로 단색 크로마키 이미지를 생성한 뒤 설치된
`remove_chroma_key.py`로 투명 PNG를 만든다. 털 경계 제거가 실패하면 임의로 다른
모델로 바꾸지 않고 사용자에게 true-transparency CLI 경로 사용 승인을 요청한다.

### 5.2 아이템 6종

각 아이템은 서로 독립된 생성 작업이다. 한 호출에서 여러 아이템을 한 이미지로
생성하지 않는다.

1. 확정된 기준 캐릭터와 해당 카테고리 좌표 가이드를 참조한다.
2. 첨부 완성 이미지에서 해당 아이템의 모양·재질·조명을 참고한다.
3. 기준 캐릭터가 해당 아이템만 착용한 목표 합성본을 생성한다.
4. 같은 위치의 아이템만 단색 크로마키 위에 출력하도록 별도 생성한다.
5. 크로마키를 제거해 투명 PNG를 만든다.
6. 알파 경계 상자를 계산해 아이템 주변으로 자른다.
7. 잘라내기 전 원래 위치를 `x/y`, 잘라낸 크기를 `width/height`로 기록한다.
8. 기본 캐릭터 위에 다시 합성해 목표 합성본과 비교한다.

아이템 목록은 다음과 같다.

| key | 슬롯 | 이번 단계 앱 상태 |
|---|---|---|
| `gnd-cap-v2` | head | 구매·장착 가능 |
| `gnd-sunglasses-v2` | eyes | 준비 중 |
| `gnd-hoodie-v2` | top | 준비 중 |
| `gnd-joggers-v2` | bottom | 준비 중 |
| `gnd-sneakers-v2` | shoes | 준비 중 |
| `gnd-watch-v2` | wrist | 준비 중 |

### 5.3 앞뒤 가림

아이템이 신체의 앞과 뒤를 동시에 지나가면 한 장에 억지로 넣지 않는다.

```text
back 조각 → 기본 캐릭터 → front 조각
```

캡에서 귀가 앞에 보여야 하면 귀 부분을 투명하게 비우거나 `cap-back`과
`cap-front`로 나눈다. 후드·시계도 손이나 목과 겹치는 결과에 따라 같은 규칙을
적용한다.

## 6. 런타임 자산 명세

편집 원본과 앱 자산을 분리한다.

```text
docs/design-sources/avatar-coordinate-v2/
  reference.png
  base-chroma.png
  base-canonical.png
  landmarks.json
  composites/
  item-chroma/
  items/
  qa/

public/avatar-coordinate-v2/
  base.png
  items/
```

앱 자산 명세는 다음 타입을 사용한다.

```ts
type AvatarLayer = {
  src: string;
  x: number;
  y: number;
  width: number;
  height: number;
  z: number;
};

type AvatarItem = {
  key: string;
  name: string;
  slot: "head" | "eyes" | "top" | "bottom" | "shoes" | "wrist";
  price: number;
  available: boolean;
  layers: AvatarLayer[];
};
```

기본 캐릭터만 전체 `1024×1536` 투명 PNG다. 아이템은 알파 경계 주변으로 잘라낸
PNG를 사용한다. 화면은 `x/y/width/height`를 비율로 변환해 배치한다.

## 7. 개발 서버 사용자 흐름

경로는 기존 승인안대로 `/profile/avatar-mock`을 사용한다.

1. 사용자가 내 정보에서 아이템 상점 목업으로 이동한다.
2. 캡 카드를 누르면 캡이 선택되고 가격과 미리보기가 표시된다.
3. `구매하기`를 누르면 목업 잔액만 차감되고 캡이 보유 상태가 된다.
4. `장착하기`를 누르면 head 슬롯에 캡이 들어가고 미리보기에 즉시 합성된다.
5. `장착 해제`를 누르면 캡 레이어가 사라진다.
6. 다시 장착할 수 있다.
7. 새로고침하면 목업 잔액·보유·장착 상태가 초기화된다.

나머지 5종은 이미지와 좌표 명세까지 준비하지만 카드에는 `준비 중`을 표시하고
구매·장착 버튼을 비활성화한다.

## 8. 오류 방지

- 이미지 파일이 없으면 해당 아이템을 비활성화하고 텍스트 상태를 유지한다.
- 좌표가 음수이거나 기준 캔버스를 벗어나면 자산 검증을 실패시킨다.
- `width/height`가 0이거나 이미지 실제 크기와 다르면 검증을 실패시킨다.
- 슬롯과 카테고리 마스크가 일치하지 않으면 등록하지 않는다.
- GPT 결과가 얼굴·체형·자세를 바꾸면 해당 결과를 폐기한다.
- 캐릭터 털·피부·기본 복장이 아이템 PNG에 섞이면 자산을 다시 분리한다.
- 귀·손·옷깃의 가림 관계가 어색하면 자동 등록하지 않고 GIMP 보정 대상으로 남긴다.
- 목업은 Supabase 쓰기 함수, 실제 지갑 조회 결과, 구매 RPC를 사용하지 않는다.

## 9. 검증

### 자동 검증

- 기준 캐릭터가 `1024×1536 RGBA`인지 확인한다.
- 각 아이템 PNG가 RGBA이고 투명 모서리를 갖는지 확인한다.
- 자산 실제 픽셀 크기와 `width/height`가 일치하는지 확인한다.
- 모든 레이어 좌표가 기준 캔버스 안에 있는지 확인한다.
- 동일 슬롯 교체, 미보유 장착 방지, 구매, 장착, 해제 상태를 단위 테스트한다.
- 레이어 스타일이 좌표를 올바른 백분율로 변환하는지 컴포넌트 테스트한다.

### 이미지 품질 검증

- 흰 배경과 짙은 회색 배경에서 테두리를 확인한다.
- 기본 캐릭터와 각 아이템 단독 합성을 확인한다.
- 캡·선글라스·후드·조거·신발·시계를 함께 합성해 충돌을 확인한다.
- 목표 합성본과 재합성 결과를 나란히 비교한다.

### 개발 서버 확인

`pnpm dev`를 실행하고 브라우저에서 다음을 직접 확인한다.

1. `/profile`에서 목업 진입 카드가 보이고 기존 성장 정보가 유지된다.
2. `/profile/avatar-mock`에서 아이템 6개가 정확히 한 번씩 보인다.
3. 캡 선택, 구매, 장착, 해제, 재장착이 동작한다.
4. 나머지 5종 버튼은 비활성화돼 있다.
5. 320px, 390px, 430px 폭에서 캡 위치가 머리에서 어긋나지 않는다.
6. 새로고침하면 목업 상태가 초기화된다.

개발 서버 화면을 직접 조작할 수 없으면 배포하지 않고 확인 항목을 사용자에게
전달해 결과를 기다린다. 이번 범위에는 운영 배포가 없다.

## 11. 향후 아이템 추가

기준 캐릭터의 자세와 체형을 유지하는 동안 좌표 틀을 계속 재사용한다.

```text
슬롯 선택
→ 카테고리 좌표·마스크 불러오기
→ GPT 이미지 생성
→ 크로마 제거·자동 자르기
→ x/y/width/height 계산
→ 재합성 검증
→ 이미지와 카탈로그 한 항목 등록
```

모자마다 챙과 높이가 다르므로 모든 모자가 같은 `x/y/width/height`를 공유하지는
않는다. 머리·귀 기준과 head 마스크를 공유하고, 최종 경계 상자는 아이템별로 자동
계산한다. 캐릭터 자세나 체형을 변경하면 기준 좌표와 아이템을 새로 검증한다.
