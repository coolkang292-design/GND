# 달력 운동 예정표 설계

## 목표

완료한 과거 운동의 종목·세트 값을 오늘 이후의 날짜에 예정표로 복사한다. 예정표는 계정에 저장해 기기 간 동기화하고, 실제 운동을 완료하기 전에는 기록·월간 통계·챌린지 집계에 포함하지 않는다.

## 사용자 흐름

1. 달력의 완료 운동 상세에서 `복사`를 누른다.
2. 오늘 이후의 대상 날짜를 선택한다.
3. 같은 날짜에 예정표가 있으면 교체 확인 후 저장한다.
4. 대상 날짜에는 완료 스탬프와 별개로 `예정` 표시가 보인다.
5. 오늘 날짜의 예정표에서 `운동 준비하기`를 누르면 종목·세트가 운동 탭의 준비 목록으로 들어간다.
6. 실제 운동 완료가 성공하면 사용한 예정표를 삭제한다. 시작 후 취소하면 예정표는 보존되고, 완료 전까지 통계에는 반영되지 않는다.

예정표는 날짜별 1개다. 미래 예정표는 날짜 이동과 삭제만 제공한다. 지난 날짜의 미실행 예정표는 삭제하거나 오늘 이후로 이동할 수 있다.

## 데이터 구조

`workout_plans` 테이블:

- `id`, `user_id`, `plan_date`
- `source_session_id`: 복사 원본 추적용, 원본 삭제 시 null
- `exercises jsonb`: 종목과 세트 값을 하나의 구조화 묶음으로 저장
- `created_at`, `updated_at`
- `unique(user_id, plan_date)`: 날짜별 1개 강제

예정표와 `workout_sessions`를 분리한다. 따라서 기존 완료 세션 쿼리와 챌린지 집계는 변경하지 않는다.

## 접근 규칙

- 로그인 사용자는 본인 예정표만 조회·생성·수정·삭제한다.
- 다른 사용자의 `user_id`나 세션을 원본으로 지정할 수 없다.
- 새 예정표와 이동 대상은 사용자 시간대 기준 오늘 이후만 허용한다.
- 날짜 이동은 RPC에서 소유권·교체 여부를 확인하고 한 트랜잭션으로 처리한다.

## 화면

- 완료 운동 카드의 `복사` 버튼은 날짜 선택 시트를 연다.
- 달력 셀에 완료 스탬프와 겹치지 않는 작은 `예정` 라벨을 표시한다.
- 날짜 상세에 예정 종목명, `운동 준비하기`, 날짜 이동, 삭제를 표시한다.
- 준비 중인 운동이 있으면 예정표를 불러오기 전에 교체 확인을 받는다.

## 검증

- 도메인 테스트: 날짜 허용, 저장 구조 변환, 불완전 데이터 거부, 완료 체크 초기화
- 실 DB 테스트: 본인 CRUD, 타인 차단, 날짜 중복, 이동 교체, 과거 날짜 차단
- 전체: unit, lint, typecheck, build
