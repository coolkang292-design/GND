# GND 공식 추천 프로그램 설계

> 확정일: 2026-08-12
> 첫 프로그램: `시선이 머무는 어깨` / `상체의 틀을 넓히는 6주`

## 1. 목표

사용자가 GND가 미리 구성한 6주 프로그램을 고르고 시작 날짜·운동 요일·시간만
정하면, 18회의 운동 계획이 달력에 한 번에 등록되게 한다. 등록된 날에는 종목,
세트, 반복 범위, 권장 무게, 종목별 휴식시간과 자세 안내가 준비되어 사용자가 바로
운동을 시작할 수 있어야 한다.

첫 출시는 사용자가 공개 프로그램을 만드는 기능이 아니라 **GND가 검수한 공식
프로그램**만 제공한다. 개인이 저장하는 `workout_routines`는 기존 기능으로 유지하고
공식 프로그램과 섞지 않는다.

## 2. 사용자 확정 사항

| 항목 | 결정 |
|---|---|
| 프로그램 형태 | 하루 루틴이 아니라 6주 프로그램 |
| 빈도와 길이 | 주 3회 고정, 6주, 총 18회 |
| 일정 입력 | 시작 날짜를 먼저 고르고 요일별 시간 선택 |
| 달력 등록 | 18회를 미리 보여준 뒤 한 번에 등록 |
| 충돌 | 기존 계획을 덮어쓰지 않고 대체 일정 제안 후 확인 |
| 결석 | 다음 가능한 일정으로 재배치안을 만들고 확인 후 반영 |
| 강도 | 기록으로 자동 판단, 부족하면 `처음/꾸준히 해봄`만 질문 |
| 무게 | 최근 성공 무게를 자동 입력하되 시작 전에 수정 가능 |
| 반복 | 종목별 반복 범위를 사용하고 1~2회 여유 안내 |
| 노력 피드백 | 첫 세트와 마지막 세트에서만 한 번씩 입력 |
| 자세 안내 | GND 핵심 안내를 먼저 보여주고 네이버 원문은 선택 링크 |
| 첫 프로그램 범위 | 전신 기본 운동을 유지하면서 어깨 비중을 높임 |
| 첫 프로그램 카피 | `시선이 머무는 어깨` / `상체의 틀을 넓히는 6주` |

## 3. 첫 화면 카피

```text
GND 공식 프로그램

시선이 머무는 어깨
상체의 틀을 넓히는 6주

본능적으로 눈길이 가는 넓고 단단한 실루엣을 위한
18회 집중 프로그램

주 3회 · 6주 · 총 18회 · 회당 45~60분

[존재감 만들기]
```

`넓어진다`, `호감을 얻는다`처럼 결과를 보장하지 않는다. 마케팅 헤드라인은
시선과 존재감을 말하되, 상세 화면은 훈련 구성과 자동화 기능을 사실대로 설명한다.

## 4. 전체 사용자 흐름

1. 운동 추가 허브에서 `GND 추천 프로그램`을 누른다.
2. `시선이 머무는 어깨` 카드를 열어 목표, 6주 구성, 필요 기구를 확인한다.
3. 시작 날짜를 고른다.
4. 주 3회 요일과 각 요일의 시작 시간을 고른다.
5. GND가 18회 일정을 만들고 기존 계획과 충돌한 날짜를 표시한다.
6. 충돌 날짜에는 기존 계획을 유지한 채 가까운 빈 날짜·시간을 제안한다.
7. 사용자가 18회 미리보기를 확인하고 `달력에 담기`를 누른다.
8. 등록일의 계획에서 `운동 준비하기`를 누르면 최신 기록으로 무게가 채워진다.
9. 첫 세트 피드백으로 오늘 무게를 보정하고 마지막 세트 피드백으로 다음 회차의
   추천 무게를 정한다.
10. 일정을 놓치면 남은 회차의 순서와 회복 간격을 유지하는 재배치안을 보여주고,
    사용자가 확인한 뒤에만 달력을 바꾼다.

## 5. 일정 규칙

- 프로그램은 항상 18회의 순서를 가진다. 회차를 건너뛰어 다음 회차를 먼저 하지
  않는다.
- 기본 회복 간격은 프로그램 운동 사이 최소 하루다. 월·수·금처럼 배치한다.
- 사용자가 연속된 요일을 선택하면 선택 화면에서 바로 이유를 설명하고 다른 요일을
  고르게 한다.
- 한 날짜에는 기존 제약대로 `workout_plans` 한 개만 둔다.
- 충돌을 해결할 때 기존 일반 계획, 타바타 계획, 개인 루틴 계획을 삭제하거나
  교체하지 않는다.
- 등록과 여러 회차 재배치는 원자적으로 처리한다. 하나라도 충돌하면 일부만 저장하지
  않는다.
- 결석 재배치 제안은 오늘 이후의 빈 선호 요일을 먼저 쓰고, 없으면 가장 가까운 빈
  날짜를 제안한다. 제안만으로 DB를 바꾸지 않는다.

## 6. 공식 프로그램과 개인 루틴의 경계

`workout_routines`는 사용자가 직접 저장·수정·삭제하는 한 번짜리 운동 묶음이다.
공식 프로그램은 다음 정보가 더 필요하므로 별도 모델로 둔다.

- 프로그램 키와 버전
- 시작 강도
- 6주 18회 순서
- 선호 요일·시간
- 등록·진행·완료·취소 상태
- 각 달력 계획이 몇 주차 몇 회차인지

공식 프로그램 본문은 첫 출시에서 TypeScript 정적 카탈로그로 관리한다. 관리자 화면과
원격 CMS는 만들지 않는다. 사용자가 등록하는 순간 각 회차를 `workout_plans.exercises`
에 스냅샷으로 저장해, 나중에 공식 템플릿을 고쳐도 이미 등록한 사용자의 계획은
바뀌지 않게 한다.

## 7. 데이터 설계

### 7.1 `program_enrollments` 신규 테이블

- `id`, `user_id`
- `program_key`, `program_version`, `title_snapshot`
- `level_at_start`: `beginner | experienced`
- `start_date`, `timezone`
- `preferred_slots jsonb`: 요일과 현지 시각 3개
- `status`: `active | completed | cancelled`
- `created_at`, `updated_at`, `completed_at`, `cancelled_at`

본인 행만 조회·생성·수정한다. 사용자는 동시에 같은 프로그램 버전의 active 등록을
하나만 가질 수 있다.

### 7.2 `workout_plans` 확장

- `title text null`
- `scheduled_at timestamptz null`
- `program_enrollment_id uuid null`
- `program_week smallint null`
- `program_session smallint null`
- `program_template_version smallint null`

일반 계획은 모두 null이라 기존 동작을 유지한다. 프로그램 계획은 enrollment 안에서
`program_week + program_session`이 유일해야 한다.

### 7.3 운동 계획 스냅샷

기존 `PlanExercise`에 선택적인 `prescription`을 추가한다.

```ts
type ExercisePrescription = {
  repsMin: number;
  repsMax: number;
  targetRir: 1 | 2 | 3;
  restSeconds: number;
  loadStepKg: 1 | 2.5 | 5;
};
```

기존 일반 계획과 개인 루틴은 `prescription`이 없어도 정상이다. 파서는 알려진 필드만
복원하고 범위가 잘못된 처방은 계획 전체를 거부한다.

### 7.4 완료 세션 연결

`workout_sessions`에 프로그램 등록 ID, 주차, 회차를 선택적으로 저장한다. 예정표는
완료 후 기존처럼 삭제해도 완료 세션이 프로그램 진행 이력을 보존한다. 프로그램
완료율은 삭제된 계획 개수가 아니라 완료 세션 18개를 기준으로 계산한다.

`workout_sets`에는 첫·마지막 세트의 `effort_feedback`을 선택적으로 저장한다.
허용값은 `too_light | on_target | too_heavy` 세 가지다.

## 8. 첫 공식 프로그램 구성

### 프로그램 이름

- 마케팅 헤드라인: `시선이 머무는 어깨`
- 프로그램명: `상체의 틀을 넓히는 6주`
- 코드 키: `shoulder-frame-6w`
- 버전: `1`

### A — 밀고 세우기

| 운동 | 세트 | 반복 | 여유 | 휴식 |
|---|---:|---:|---:|---:|
| 바벨 백스쿼트 | 3 | 6~10 | 2회 | 150초 |
| 벤치프레스 | 3 | 6~10 | 2회 | 150초 |
| 시티드 로우 | 3 | 8~12 | 2회 | 120초 |
| 숄더프레스 | 초보 2 / 경험 3 | 8~12 | 2회 | 120초 |
| 사이드 레터럴 레이즈 | 초보 2 / 경험 3 | 12~20 | 1~2회 | 75초 |

### B — 등판과 뒤쪽 어깨

| 운동 | 세트 | 반복 | 여유 | 휴식 |
|---|---:|---:|---:|---:|
| 루마니안 데드리프트 | 3 | 6~10 | 2회 | 150초 |
| 랫풀다운 | 3 | 8~12 | 2회 | 120초 |
| 인클라인 벤치프레스 | 3 | 8~12 | 2회 | 120초 |
| 페이스풀 | 초보 2 / 경험 3 | 12~20 | 1~2회 | 75초 |
| 덤벨 컬 | 2 | 10~15 | 2회 | 75초 |

### C — 옆선과 전신 균형

| 운동 | 세트 | 반복 | 여유 | 휴식 |
|---|---:|---:|---:|---:|
| 레그프레스 | 3 | 8~12 | 2회 | 150초 |
| 덤벨 벤치프레스 | 3 | 8~12 | 2회 | 120초 |
| 바벨 로우 | 3 | 8~12 | 2회 | 120초 |
| 덤벨 레터럴 레이즈 | 초보 3 / 경험 4 | 12~20 | 1~2회 | 75초 |
| 페이스풀 | 2 | 12~20 | 1~2회 | 75초 |
| 케이블 푸시다운 | 2 | 10~15 | 2회 | 75초 |

전면 어깨는 벤치프레스와 숄더프레스에서도 충분히 관여하므로 전면 고립 운동을 더하지
않는다. 측면·후면 어깨에 직접 세트를 우선 배치하고, 가슴·등·하체는 주 2회 이상
노출되도록 유지한다.

### 6주 진행

- 1주차: 무게 보정. 반복 범위의 하단과 3회 정도 여유로 시작한다.
- 2~4주차: 같은 무게에서 반복을 먼저 늘리고 상한을 달성하면 최소 단위 증량한다.
- 5주차: 목표 세트 수를 모두 수행한다. 실패 반복은 요구하지 않는다.
- 6주차: 상한 반복 달성과 자세 유지 여부를 확인하고 다음 프로그램용 시작 무게를
  남긴다. 마지막 세트도 1회 이상 여유를 둔다.

복잡한 주간 변형보다 꾸준한 수행과 점진적 증가를 우선한다. ACSM 2026 입장문은
건강한 성인의 주요 근육군을 주 2회 이상 훈련하고, 근비대 목표는 근육군당 주간 약
10세트를 하나의 실용적 기준으로 제시하며, 실패지점·복잡한 주기화가 평균적인
성인에게 필수적이지 않다고 정리한다.

## 9. 무게 추천과 피드백

### 운동 시작 시

1. 같은 종목의 최근 완료 세트 중 반복 범위에 가까운 성공 무게를 찾는다.
2. 기록이 있으면 그 무게를 자동 입력하고 사용자가 수정할 수 있게 한다.
3. 기록이 없으면 무게를 임의로 추측하지 않는다. 다음 안내와 함께 첫 세트를 사용자가
   정하게 한다.

```text
8~10회를 안정된 자세로 수행할 수 있는 무게를 선택하세요.
10회를 마쳤을 때 2회 정도 더 할 수 있는 무게가 적당합니다.
```

### 첫 세트

- `너무 가벼움`: 다음 세트에 기구 최소 증량 단위를 제안한다.
- `적당함 · 1~2회 여유`: 오늘 무게를 유지한다.
- `너무 무거움 · 자세 무너짐`: 다음 세트 감량을 제안하고 증량을 잠근다.

### 마지막 세트

- 모든 세트에서 반복 상한을 달성하고 마지막 세트가 `적당함`이면 다음 회차에 최소
  단위 증량을 제안한다.
- 반복 하한을 못 채웠거나 `너무 무거움`이면 유지 또는 감량을 제안한다.
- 통증은 노력 피드백으로 처리하지 않는다. 별도 `통증 있음` 동작은 운동 중단과
  전문가 상담 안내로 연결하고 자동 증량을 금지한다.

기구마다 실제 원판·핀 간격이 다르므로 `loadStepKg`는 템플릿의 추천 단위일 뿐이다.
적용 전 사용자가 수정할 수 있고, 사용자가 한 번 고친 단위는 그 종목의 다음 추천에
우선한다.

## 10. 운동 지침과 네이버 원문

운동 카드의 `자세 안내`를 누르면 GND가 직접 작성한 짧은 안내를 먼저 보여준다.

- 시작 자세
- 동작 순서
- 호흡
- 자주 하는 실수
- 통증·안전 주의

아래에 `네이버 지식백과에서 자세히 보기 ↗`를 선택적으로 표시한다. 네이버의 글,
사진, 영상은 앱으로 복사하거나 iframe으로 삽입하지 않는다. URL과 출처명만 저장하고
사용자가 명시적으로 눌렀을 때 외부 페이지를 연다.

```ts
type ExerciseGuide = {
  exerciseName: string;
  setup: string[];
  movement: string[];
  breathing: string;
  mistakes: string[];
  caution: string;
  source?: {
    provider: "네이버 지식백과";
    url: string;
    checkedAt: string;
  };
};
```

원문 URL은 운동명과 페이지를 사람이 직접 대조한 것만 등록한다. 문서 ID를 추측해
만들지 않는다. 현재 사용자가 제공한 `docId=2099791` 링크는 링크 기능의 첫 검증
자료로 사용한다. 링크가 없거나 깨져도 GND 안내는 계속 보여야 한다.

## 11. 근거와 해석 범위

- ACSM 2026: 단순하고 지속 가능한 프로그램, 주요 근육군 주 2회 이상, 근비대 목표의
  주간 볼륨 증가를 우선한다.
- 실패지점 메타분석: 완전한 실패까지 수행하는 것이 비실패 훈련보다 근비대에 항상
  우월하다는 근거는 없다. 그래서 기본 목표를 1~2회 여유로 둔다.
- 휴식시간 메타분석: 60초 초과가 약간 유리할 수 있고 90초를 넘긴 구간의 차이는
  뚜렷하지 않았다. 복합 운동은 수행 보존을 위해 120~150초, 고립 운동은 75초를
  기본값으로 둔다.

이 프로그램은 건강한 성인의 일반적인 운동 가이드다. 부상, 질환, 임신, 의사의 운동
제한이 있으면 자동 프로그램보다 의료·운동 전문가의 개별 지시를 우선한다.

## 12. 성공 지표

첫 출시는 프로그램 수가 아니라 파이프라인이 실제로 작동하는지를 본다.

- 프로그램 상세 → 일정 설정 시작률
- 일정 설정 → 18회 달력 등록 완료율
- 등록 후 첫 운동 7일 내 시작률
- 1주차 3회 중 2회 이상 완료율
- 결석 재배치 제안 수락률
- 첫·마지막 세트 피드백 응답률
- 6주 18회 완료율
- 자세 안내 열람률과 네이버 원문 클릭률

## 13. 구현 분리

범위가 세 하위 시스템에 걸치므로 한 번에 배포하지 않는다.

1. **공식 프로그램과 달력 등록**: 정적 카탈로그, 일정 생성, enrollment, 18회 원자적
   등록, 충돌·재배치
2. **운동 중 자동 세팅**: 반복 범위, 최근 무게, 종목별 휴식, 첫·마지막 세트 피드백,
   완료 세션 연결
3. **운동 지침**: GND 안내 시트, 선택적 네이버 원문 링크, 링크 실패 폴백

각 단계는 개발 서버에서 실제 흐름을 직접 조작하고 전체 검사 후 별도 승인받아
배포한다. DB 마이그레이션은 사용자가 SQL Editor에서 직접 실행한다.
