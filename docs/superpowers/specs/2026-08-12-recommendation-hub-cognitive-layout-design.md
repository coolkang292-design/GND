# GND 추천 프로그램·운동 검색 인지 중심 레이아웃 설계

> 확정일: 2026-08-12
> 상태: 사용자 화면 구조 승인, 코드·DB·이미지 변경 전

## 1. 목표

사용자가 `운동 추가`를 열었을 때 먼저 해야 할 일은 종목 100여 개를 읽는 것이
아니다. 아래 둘 중 하나를 빠르게 고르는 것이다.

1. 목표를 고르고 GND에게 6주 계획을 맡긴다.
2. 오늘 할 운동을 직접 검색해 추가한다.

이 설계는 기존 상황별 추천·부위별 추천·지난 운동·내 루틴·타바타를 없애지 않는다.
첫 화면의 결정을 두 갈래로 줄이고, 나머지 기능은 목적에 맞는 하위 경로로
재배치한다.

## 2. 첫 번째 원칙 분석

### 문제의 본질

**핵심 문제:** 운동 방법을 모르는 사람과 이미 종목을 아는 사람이 같은 긴 목록에서
출발해 선택 비용이 커진다.

**성공 조건:** 사용자가 첫 화면에서 5초 안에 `프로그램` 또는 `직접 검색` 중 하나를
고르고, 뒤로 헤매지 않고 운동 계획 등록 또는 오늘 운동 추가를 완료한다.

### 버린 가정

| 가정 | 검토 | 결정 |
|---|---|---|
| 모든 기능을 첫 화면에서 같은 카드로 보여줘야 한다 | 기능 수가 늘수록 목적 구분이 약해진다 | 폐기 |
| 추천 프로그램만 크게 보여주면 전환이 높다 | 숙련 사용자는 검색까지 한 단계 더 거친다 | 수정 |
| `타바타`라는 이름만으로 기능을 이해한다 | 방식 이름이지 사용자의 필요가 아니다 | 폐기 |
| 추천 프로그램은 한 부위만 운동해야 한다 | 주 3회에서 균형·지속성과 맞지 않는다 | 폐기 |
| 이미지는 많을수록 고급스럽다 | 강한 초점이 여러 개면 행동 계층이 흐려진다 | 폐기 |

### 바닥 사실

- 초보자는 종목 이름보다 원하는 결과를 먼저 안다.
- 숙련 사용자는 원하는 종목 이름을 알고 검색 속도를 원한다.
- 주 3회 프로그램은 전신 기본 운동을 유지하면서 목표 부위의 주간 운동량을 높이는
  편이 다섯 목표를 하나의 운영 체계로 관리하기 쉽다.
- 달력 등록은 사용자가 요일과 시간을 직접 고르고 최종 확인해야 실제 약속이 된다.
- 기존 계획과 기록은 추천 기능이 자동으로 삭제하거나 덮어쓰면 안 된다.
- 이미지가 없어도 제목·설명·버튼으로 전체 흐름을 완료할 수 있어야 한다.

### 결론

`두 개의 선명한 입구 → 목적별 점진 공개 → 한 개의 주요 행동` 구조를 사용한다.
강한 3D 이미지는 프로그램 카드 한 곳에만 두고 검색은 기능 중심으로 표현한다.

## 3. 근거와 적용 범위

2026 ACSM 세계 피트니스 트렌드에서 체중 관리 운동은 3위, 모바일 운동 앱은 4위,
전통적 근력운동은 7위, 데이터 기반 기술은 8위, 기능성 운동은 10위다. GND는 이를
유행어로 복사하지 않고 다음 제품 결정으로 번역한다.

- 다이어트는 단기 감량 보장이 아니라 `근육을 지키는 체지방 관리`로 설명한다.
- 다섯 프로그램 모두 단순하고 반복 가능한 근력운동을 중심에 둔다.
- 최근 기록을 사용해 무게와 휴식을 제안하되 사용자가 수정할 수 있게 한다.
- 진행 중에는 18회 중 완료 회차를 보여줘 다음 행동을 분명히 한다.

2026 ACSM 저항운동 지침의 핵심은 복잡성보다 꾸준함이며, 근비대를 위한 실용적
기준으로 근육군당 주간 약 10세트가 제시됐다. 매 세트를 실패까지 수행하는 방식은
필수가 아니므로 기존 공식 프로그램 설계처럼 기본 강도를 1~2회 여유로 둔다.

인지 원칙은 다음처럼 제한적으로 적용한다.

| 원칙 | 화면 결정 |
|---|---|
| 선택 반응 시간 | 첫 결정을 프로그램/검색 두 개로 줄인다 |
| 재인 우선 | `타바타`보다 `4분부터 시작하는 전신 인터벌`처럼 행동을 말한다 |
| 점진 공개 | 카드에서는 결과·기간만, 상세에서 구성·근거·일정을 보여준다 |
| 목표 기울기 | 등록 뒤 `18회 중 N회` 진행률과 다음 회차를 함께 보여준다 |
| 실행 의도 | 사용자가 운동할 요일과 시간을 직접 정하게 한다 |
| 큰 터치 표적 | 카드 전체를 누를 수 있고 핵심 표적은 최소 44px를 확보한다 |

## 4. 전체 정보 구조

```text
운동 추가
├─ 프로그램으로 시작하기
│  ├─ 어깨
│  ├─ 가슴
│  ├─ 팔
│  ├─ 하체
│  └─ 다이어트
├─ 운동 직접 고르기
│  ├─ 검색
│  ├─ 상황별 추천
│  └─ 부위별 추천
└─ 빠른 시작
   ├─ 지난 운동
   ├─ 내 루틴 (저장된 루틴이 있을 때)
   └─ 4분부터 시작하는 전신 인터벌
```

첫 화면의 주 행동은 프로그램과 검색이다. 빠른 시작은 재사용 또는 즉시 실행
기능이므로 시각적 단계를 한 단계 낮춘다.

## 5. 운동 추가 첫 화면

```text
운동 추가
오늘 운동을 어떻게 시작할까요?

┌──────────────────────────┐
│ GND 추천                  │
│ 프로그램으로 시작하기      │
│ 목표만 고르면 6주 계획을   │
│ 달력에 자동으로 담아요      │
│                [3D 이미지] │
└──────────────────────────┘

┌──────────────────────────┐
│ [검색 아이콘]              │
│ 운동 직접 고르기           │
│ 검색·상황·부위별로         │
│ 오늘 운동을 추가해요        │
└──────────────────────────┘

빠른 시작
[지난 운동] [내 루틴]

[4분부터 시작하는 전신 인터벌]
음악에 맞춰 20초 운동 · 10초 휴식
```

### 시각 규칙

- 프로그램 카드와 검색 카드는 첫 화면에서 모두 보여야 한다.
- 프로그램 카드는 검정·골드 3D 이미지를 사용하고 `GND 추천` 배지를 붙인다.
- 검색 카드는 중립 배경과 단순 검색 아이콘을 사용해 기능을 즉시 인식하게 한다.
- 프로그램 카드가 권장 경로이지만 검색 카드의 높이와 전체 터치 영역을 지나치게
  줄이지 않는다.
- 별도의 상단 장식 이미지는 제거하고 프로그램 카드의 이미지로 흡수한다.
- 골드 채움이나 강한 글로우는 화면당 한 곳만 사용한다.

## 6. 프로그램 카탈로그

첫 출시 목표는 아래 다섯 프로그램이다. 모두 `주 3회 · 6주 · 총 18회`이며 전신
기본 운동을 유지하고 목표 부위의 주간 운동량을 높인다.

| 목표 | 헤드라인 | 프로그램명 | 카드 이미지 방향 |
|---|---|---|---|
| 어깨 | `시선이 머무는 어깨` | `상체의 틀을 넓히는 6주` | 등·어깨가 보이는 3/4 실루엣 |
| 가슴 | `옷태를 세우는 가슴` | `상체 앞면을 단단하게 만드는 6주` | 정면 상체와 절제된 가슴 림 조명 |
| 팔 | `소매를 채우는 팔` | `팔의 두께와 윤곽을 만드는 6주` | 자연스럽게 굽힌 팔의 측면 실루엣 |
| 하체 | `실루엣을 완성하는 하체` | `하체의 힘과 균형을 세우는 6주` | 허벅지·둔근이 보이는 역동적 자세 |
| 다이어트 | `몸은 가볍게, 인상은 선명하게` | `근육을 지키는 체지방 관리 6주` | 움직이는 전신과 절제된 속도감 |

### 배치

- 어깨 프로그램을 첫 대표 카드로 전폭 배치한다.
- 나머지 가슴·팔·하체·다이어트는 2×2 카드로 배치한다.
- 개인화 근거가 생기기 전에는 `나에게 딱 맞는 추천`이라고 말하지 않는다.
- 네 개의 새 프로그램은 운동 처방과 안전 문구가 완성되기 전까지 운영 화면에
  빈 카드나 `준비 중`으로 노출하지 않는다. 다섯 개가 모두 실제 선택 가능한 상태로
  출시하거나, 검수 완료된 카드만 노출한다.

### 이미지 체계

- 같은 인물 계열, 카메라 높이, 검정 배경, 골드 림 조명을 사용한다.
- 이미지 안에 글자·버튼·로고·워터마크를 넣지 않는다.
- 성적 대상화나 과장된 전후 비교를 사용하지 않는다.
- 체중계·줄자·복부 클로즈업으로 수치 불안을 자극하지 않는다.
- 이미지는 목표를 구분하는 보조 수단이며 텍스트보다 먼저 결정을 강요하지 않는다.

## 7. 프로그램 상세 화면

정보 순서는 모든 프로그램에서 같다.

1. 헤드라인과 대표 이미지
2. `주 3회 · 6주 · 18회 · 회당 시간`
3. `이런 사람에게 맞아요` 세 문장 이하
4. 전신 기본 운동과 집중 부위 설명
5. 실제 하루 구성 한 회 미리보기
6. 최근 기록 기반 무게·반복·휴식 자동 설정 설명
7. 안전·통증 안내와 근거 요약
8. 하단 고정 버튼 `요일과 시간 정하기`

결과를 보장하는 `넓어진다`, `살이 빠진다`, `호감을 얻는다`는 쓰지 않는다.
헤드라인은 욕구를 자극하되 본문은 사용자가 받는 실제 기능을 사실대로 설명한다.

## 8. 일정 등록

입력 흐름은 세 단계다.

### 1단계: 시작일

- `이번 주 시작`, `다음 주 시작` 빠른 선택을 제공한다.
- 오늘 이전 날짜는 선택할 수 없다.
- 선택한 시작일부터 첫 번째 가능한 운동일을 계산한다.

### 2단계: 요일과 시간

- 권장 조합 `월·수·금`, `화·목·토`를 먼저 보여준다.
- `직접 선택`도 허용하되 회복일 없는 연속 3일은 선택할 수 없다.
- 기본은 세 요일에 같은 시간을 한 번 입력한다.
- 필요한 사용자만 요일별 시간을 따로 수정한다.
- 최근 운동 시간대가 있어도 제안만 하고 자동 확정하지 않는다.

### 3단계: 18회 미리보기

- 긴 18행 목록 대신 6주 × 3회 표로 묶는다.
- 기존 계획과 겹치는 회차만 표시하고 가까운 빈 날짜·시간을 제안한다.
- 기존 일반 계획·루틴·인터벌 계획은 삭제하거나 덮어쓰지 않는다.
- 마지막 버튼은 `18회 계획을 달력에 담기`로 구체적으로 쓴다.
- 버튼을 누르기 전에는 DB를 변경하지 않는다.
- 저장은 전부 성공하거나 전부 취소되는 원자적 동작이어야 한다.

### 등록 완료

```text
6주 계획이 준비됐어요

다음 운동
8월 17일 월요일 · 오후 7:00
1주차 1회 · 밀고 세우기

[운동 계획 확인하기]
```

달력의 좁은 칸에서는 `어깨 · 1주차 1회`처럼 줄이고, 날짜 상세에서 프로그램명과
종목·세트·반복·권장 무게·휴식시간을 모두 보여준다.

## 9. 운동 직접 고르기

```text
← 운동 직접 고르기

[ 운동 이름 검색                         ]

빠르게 찾기
[상황별 추천] [부위별 추천]

자주 한 운동
[벤치프레스] [랫풀다운] [레그프레스]

검색 결과
[기구 이미지] 벤치프레스 · 가슴 · 웨이트 [추가]

선택한 운동 3개
[세트·무게 설정하기]
```

- 이 경로를 직접 고른 사용자는 검색 의도가 있으므로 입력창을 즉시 활성화한다.
- 상황별·부위별 추천은 검색을 대체하는 첫 화면 카드가 아니라 빠른 탐색 수단이다.
- 검색 전에는 자주 한 운동을 한 줄로 보여주고 결과 목록을 밀어내지 않는다.
- 카드 전체를 선택할 수 있고 선택 상태는 체크·테두리·배경으로 함께 표현한다.
- 선택 수와 다음 행동을 화면 하단에 고정한다.

## 10. 전신 인터벌 명칭

사용자에게 보이는 주 명칭은 다음으로 확정한다.

```text
4분부터 시작하는 전신 인터벌
음악에 맞춰 20초 운동 · 10초 휴식
4분 · 8분 · 16분
```

- 좁은 빠른 시작 칩에서만 `4분 인터벌`로 줄인다.
- 상세 화면에서 `타바타 방식`을 보조 설명으로 사용할 수 있다.
- 내부 코드·도메인·기존 기록의 `tabata`는 변경하지 않는다.
- `4분 만에 살 빠짐`, `지방 폭발` 같은 근거 없는 결과 문구를 사용하지 않는다.

## 11. 컴포넌트 경계

기존 `ExercisePicker`가 모든 하위 화면을 계속 직접 떠안지 않게 책임을 나눈다.

- `ExerciseEntryHub`: 프로그램·검색·빠른 시작의 첫 화면만 담당
- `ProgramCatalog`: 다섯 프로그램 카드와 선택만 담당
- `ProgramDetail`: 선택한 프로그램 정보와 일정 설정 진입만 담당
- `ProgramScheduleSetup`: 시작일·요일·시간·미리보기 상태만 담당
- 기존 `RecommendedPicker`: 상황별·부위별 선택을 그대로 담당
- 기존 검색 목록: 검색·자주 한 운동·선택 상태를 담당
- 기존 `TabataSheet`: 내부 동작을 유지하고 사용자 노출 문구만 새 명칭 사용

프로그램의 운동 처방, 일정 계산, 충돌 계산은 React 컴포넌트 밖의 순수 도메인
함수로 유지한다. 화면은 결과를 표시하고 사용자 확인을 받을 뿐이다.

## 12. 상태와 데이터 흐름

```text
운동 추가
→ 프로그램 선택
→ 정적 공식 프로그램 조회
→ 시작일·요일·시간 입력
→ 로컬에서 18회 미리보기 생성
→ 기존 계획과 충돌 조회
→ 대체안 표시
→ 사용자 최종 확인
→ enrollment + workout_plans 18개 원자적 저장
→ 달력과 다음 운동 갱신
```

검색 경로는 기존 오늘 운동 초안에 종목을 추가한다. 프로그램 경로는 오늘 초안을
바로 바꾸지 않고 달력 계획을 만든다. 두 경로의 쓰기 대상을 섞지 않는다.

## 13. 오류와 안전장치

- 진행 중인 같은 공식 프로그램이 있으면 새 등록보다 `진행 중인 프로그램 보기`를
  먼저 제공한다.
- 최근 성공 무게가 없으면 값을 추측하지 않고 목표 반복과 1~2회 여유 기준을 말한다.
- 일정 저장 실패 시 사용자가 고른 날짜·요일·시간을 유지한다.
- 충돌이 새로 생기면 일부만 저장하지 않고 최신 충돌 상태를 다시 보여준다.
- 이미지 로드 실패 시 이미지 영역만 숨기고 제목·설명·버튼은 유지한다.
- 외부 운동 지침 링크가 실패해도 GND 핵심 안내는 남는다.
- 통증은 노력 피드백으로 취급하지 않고 운동 중단·전문가 상담 안내로 분리한다.

## 14. 접근성·반응형·성능

- 360·390·430px에서 가로 스크롤과 하단 버튼 가림이 없어야 한다.
- 주요 카드와 버튼의 터치 영역은 최소 44×44px다.
- 선택 상태를 골드 색 하나로만 표현하지 않고 체크와 문구를 함께 사용한다.
- 제목·본문·보조 문구의 대비를 검정 배경에서 확인한다.
- 프로그램 대표 이미지는 화면 진입에 필요한 첫 장만 우선 로드한다.
- 2×2 카드 이미지는 지연 로딩하고 표시 크기의 2배 내외 자산을 사용한다.
- 모션 감소 설정에서는 광택 이동과 큰 전환 애니메이션을 끈다.

## 15. 검증

### 자동 검사

- 첫 화면에 프로그램과 검색 두 핵심 카드가 모두 렌더된다.
- 기존 상황별·부위별·지난 운동·내 루틴·인터벌 진입이 남아 있다.
- 사용자 화면에 주 명칭 `타바타`가 남지 않고 새 명칭이 표시된다.
- 프로그램 카드 5종의 카피와 실제 이미지 경로가 일치한다.
- 이미지 실패 뒤에도 카드 제목과 버튼이 남는다.
- 요일·시간 입력으로 정확히 18회가 만들어진다.
- 연속 요일과 기존 계획 충돌을 안전하게 막는다.
- 저장 실패와 재시도에서 입력값이 보존된다.

### 개발 서버 직접 조작

1. `/record`에서 운동 추가를 열고 핵심 카드 두 개와 빠른 시작을 센다.
2. 프로그램에서 다섯 목표가 모두 실제 선택 가능한지 확인한다.
3. 프로그램 상세 → 일정 설정 → 18회 미리보기 → 등록을 끝까지 누른다.
4. 기존 계획과 겹치게 만들어 대체안과 원본 보존을 확인한다.
5. 검색 경로에서 검색·상황·부위별 추천으로 각각 운동을 추가한다.
6. 지난 운동·내 루틴·전신 인터벌을 각각 열어 기존 기능이 유지되는지 확인한다.
7. 360·390·430px에서 잘림과 하단 버튼 가림을 확인한다.
8. 이미지 한 장을 실패시켜 텍스트와 버튼이 남는지 확인한다.

코드 변경이 끝나면 개발 서버 직접 조작 뒤 lint·typecheck·전체 test·build를 각각
한 번 실행한다. 사용자 승인 없이는 운영 배포하지 않는다.

## 16. 성공 지표

- 운동 추가 첫 화면 → 프로그램 또는 검색 선택률
- 첫 화면을 닫고 이탈한 비율
- 프로그램 상세 → 일정 설정 진입률
- 일정 설정 → 18회 등록 완료율
- 검색 진입 → 오늘 운동 1개 이상 추가율
- 프로그램 등록 뒤 7일 내 첫 운동 시작률
- 1주차 세 회 중 두 회 이상 완료율
- 전신 인터벌 카드 → 실제 시작률

개인화가 없는 첫 출시에서는 클릭률만으로 프로그램 품질을 단정하지 않는다. 등록
완료와 첫 운동 시작, 1주차 수행까지 함께 본다.

가슴·팔·하체·다이어트 네 프로그램의 정확한 종목, 주차별 세트, 반복 범위, 휴식,
초보/경험 분기를 별도 근거 검토로 완성해야 한다. 운동 처방이 비어 있는 프로그램은
