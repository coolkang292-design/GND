# 타바타 모드 설계

## 목표

사용자 제작 타바타 음원(권리 확인 완료 2026-07-19)을 앱에 내장하고, **시작 1탭 → 음원 들으며 운동 → 음원 종료 시 자동 기록 → 인증샷**의 무조작 흐름을 만든다. 구조는 사용자 확정: 타바타 선택 → **운동 4개 선택** → 재생.

## 흐름

1. 기록 탭 준비 화면의 **"🔥 타바타"** 버튼 → 타바타 시트: 트랙("4분 전신 타바타") + "구성 운동 4개 고르기" (기존 ExercisePicker 재사용, 정확히 4개 선택 시 시작 활성).
2. **시작** (사용자 제스처에서 `audio.play()` — iOS 요건): 기존 세션 흐름 그대로 `createDraftSession`+`start_workout` 자동 실행. 재생 화면: 진행바·남은 시간·선택 운동 4개·중단 버튼. Wake Lock으로 화면 꺼짐 방지 시도(실패 무해).
3. **음원 ended** → 4개 운동 각 1세트를 완료 처리 후 기존 완료 파이프라인(`handleFinish` 경로) 실행 → 세션 자동 완료(운동 시간 = 실제 경과 = 음원 길이) → **기존 완료 화면에서 사진 촬영** → 피드·스트릭·챌린지·기록갱신 전부 기존 구조로 자동 반영.
4. **중단** 버튼 → 확인 후 세션 취소(기존 cancel 흐름), 소리 정지.

## 구성

- 음원: `public/audio/tabata-4min-total-body.mp3` (사용자 파일 복사, HTML5 `<audio>` — 미디어 재생이라 무음 스위치 무시).
- 트랙 정의는 상수 배열(`TABATA_TRACKS`: id·제목·파일 경로) — 추후 음원 추가는 항목 1줄.
- 도메인 TDD: `tabataDraftExercises(picked)` — 선택 4개를 각 1세트(0값) 임시운동으로 변환(키 주입). 재생·세션 연결은 record 페이지 통합.
- 진행 중 다른 운동 draft가 있으면 예정표와 같은 확인 후 교체. active 세션 중엔 타바타 시작 불가.

## 오류 처리

- 재생 실패·Wake Lock 실패는 화면 안내만, 세션은 시작 전이면 미생성.
- 재생 중 이탈(새로고침): 기존 draft 대사 로직이 active 세션을 복구 — 타바타 오버레이는 사라지고 일반 운동 화면으로 이어짐(수동 완료 가능). 자동 기록 보장은 화면 유지 전제.

## 테스트

- 도메인 TDD + 전체 게이트. 실기기: 4개 선택→시작→음원 재생(무음 스위치 상태 포함)→종료 시 자동 완료·사진 화면→피드 반영, 중단 취소 동작.

## 제외 범위

- 여러 트랙 UI(구조만 준비), 라운드 타이머 시각화(음원이 가이드), 백그라운드/화면잠금 재생 보장, 음원 스트리밍 업로드 관리
