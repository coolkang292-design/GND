# GND 이미지·레이아웃 품질 개선 설계 (2026-08-12)

## 1. 목표

GND의 검정·골드 개성은 유지하면서 사용자가 더 빠르게 화면을 이해하고 운동을
기록할 수 있도록 이미지의 역할, 크기, 강조 강도와 카드 레이아웃을 앱 전체에서
통일한다.

이번 설계의 핵심은 이미지를 더 많이 넣는 것이 아니다. 각 이미지가 아래 네 가지
일 중 하나를 분명히 수행하게 만드는 것이다.

1. 브랜드를 기억하게 한다.
2. 선택지를 빠르게 구분하게 한다.
3. 성취를 보상한다.
4. 사용자가 다음 행동을 이해하게 한다.

어느 역할도 하지 않는 이미지는 줄이거나 제거한다.

## 2. 승인된 방향

### 2.1 시각 강도

`입구는 시네마틱, 앱 안은 기능 중심`으로 확정한다.

- 로그인·온보딩, 중요한 성취·보상은 강한 3D 이미지를 유지한다.
- 홈·탐색·운동 추가·기록·설정처럼 자주 쓰는 화면은 제목과 행동이 이미지보다
  먼저 보이게 한다.
- 한 화면의 강한 골드 초점은 원칙적으로 한 개만 둔다.

### 2.2 이미지 제작 범위

기존 이미지를 전부 다시 만들지 않는다.

- 이미 품질과 역할이 맞는 이미지는 유지한다.
- 연결이 끊겼거나, 작은 크기에서 뭉개지거나, 다른 역할의 자산을 임시로 사용한
  곳만 선별 교체한다.
- 기존 Git 기록에 승인 가능한 이미지가 있으면 새로 생성하기 전에 먼저 복구해
  재사용한다.

## 3. 현재 상태와 핵심 진단

### 3.1 유지할 기반

- `public/onboarding/`의 화면별 통짜 이미지는 360·390·430px에서 가로 잘림과
  텍스트 겹침을 해결한 구조다. 전면 재작업하지 않는다.
- `public/record-assets/exercise-picker-hero.webp`는 운동 추가의 맥락을 설명하는
  대표 이미지로 유지할 수 있다.
- 캐릭터와 배지는 정체성·보상 역할에 적합하다.
- 검정·골드 색상 자체는 앱 전체에서 충분히 일관된다.

### 3.2 개선할 문제

- 시네마틱 이미지, 3D 기능 아이콘, 운동 썸네일, 캐릭터와 배지가 같은 수준의
  강조로 등장해 정보 계층이 약해질 수 있다.
- `public/ui-icons/`의 아이콘은 44개이고 여러 화면에서 13–44px로 축소된다.
  작은 크기에서 세부 묘사와 광택이 뭉개지는 아이콘은 선별 단순화가 필요하다.
- 현재 `EXERCISE_THUMBS`가 비어 있고 `public/exercise-thumbs/`도 없다. 따라서
  `처음 운동해요` 추천 카드는 썸네일 없이 텍스트 카드로 내려간다.
- 현재 렌더 경로는 `.png`를 조립하지만, Git 기록의 승인 후보 네 장은 `.webp`다.
  코드·파일·확장자가 서로 다른 상태다.

### 3.3 가장 싼 복구 경로

새 이미지를 만들기 전에 Git 기록의 다음 자산을 먼저 복구·검수한다.

- `8d3841c`: `chest-press-machine.webp`, `lat-pulldown.webp`, `leg-press.webp`,
  `shoulder-press.webp`
- `d7cccf2`: WebP 썸네일 연결과 실패 시 대체 화면 처리

이 자산이 현재 시각 기준을 충족하면 그대로 재사용한다. 불합격한 이미지만 다시
생성한다.

## 4. 이미지 역할 체계

### 4.1 브랜드·첫인상

- 대상: 로그인, 온보딩
- 표현: 강한 3D, 시네마틱 조명, 화면당 대표 이미지 한 개
- 규칙: 실제 문구와 버튼을 이미지 안에 굽지 않는다.

### 4.2 맥락·선택 안내

- 대상: 운동 추가 첫 화면, 기능 소개의 빈 상태
- 표현: 대표 이미지 한 개, 높이 120–160px
- 규칙: 제목과 설명보다 뒤에 놓고 선택 카드와 경쟁하지 않게 한다.

### 4.3 탐색·기능

- 대상: 탭, 허브 카드, 상황·부위 선택, 상태 아이콘
- 표현: 단순한 형태, 일관된 광택과 안전 여백
- 규칙: 탭 24–28px, 기능 아이콘 38–44px를 기준으로 한다.
- 선택 상태는 별도 장식 추가보다 색상·테두리·배경 차이로 표현한다.

### 4.4 운동 썸네일

- 대상: 추천 운동과 운동 검색 결과
- 표현: 실제 기구를 구분할 수 있는 3/4 시점의 검정·골드 제품 렌더
- 규칙: 카드에서는 64px 정사각형으로 표시하고 최소 2배 해상도로 내보낸다.
- 배경은 카드 검정 바탕과 자연스럽게 이어지는 단색 또는 매우 약한 그라데이션을
  사용한다.
- 배지·트로피·캐릭터를 운동 썸네일로 재사용하지 않는다.

### 4.5 보상·정체성

- 대상: 프로필 단계, 배지 획득, 챌린지 결과, 스트릭 보상
- 표현: 강한 3D를 허용하되 중요한 순간에만 크게 사용한다.
- 규칙: 일반 카드에서는 88px 이하, 획득·결과 모달에서는 88–120px를 기준으로
  한다.

## 5. 공통 레이아웃 규칙

- 화면 좌우 여백: 16px
- 카드 사이 간격: 8–12px
- 섹션 사이 간격: 16–24px
- 탭 아이콘: 24–28px
- 기능 아이콘: 38–44px
- 운동 썸네일: 64px
- 보상 이미지: 88–120px
- 대표 이미지: 높이 120–160px

정보 순서는 `제목 → 선택에 필요한 정보 → 보조 이미지 → 주요 버튼`으로 맞춘다.
골드 채움 버튼은 핵심 행동 하나에만 사용하고 나머지는 테두리나 중립 배경으로
단계를 낮춘다.

## 6. 이미지 제작 규칙

### 기능 아이콘

- 정사각형 투명 배경
- 같은 역할은 동일한 광택, 선 굵기와 피사체 안전 여백 사용
- 작은 크기에서 보이지 않는 장식과 글로우는 제거
- 이미지 안 글자·로고·워터마크 금지

### 운동 썸네일

- 정사각형 WebP
- 동일한 카메라 높이와 3/4 시점
- 검정 배경, 어두운 금속, 절제된 골드 림 조명
- 기구 종류를 한눈에 구분할 수 있어야 함
- 이미지 안 글자·로고·버튼·워터마크 금지

### 보상·캐릭터

- 기존 자산의 역할을 유지한다.
- 기능 아이콘이나 운동 썸네일의 임시 대체 자산으로 사용하지 않는다.

## 7. 구현 우선순위

### P0 — 운동 썸네일 연결 복구

1. Git 기록의 네 장을 현재 브랜치에 복구해 실제 카드 크기로 검수한다.
2. `EXERCISE_THUMBS`와 추천 카드 경로를 `.webp` 하나로 통일한다.
3. 이미지가 실패해도 운동명·설명·추가 버튼이 남는 대체 화면을 유지한다.
4. 코드가 가리키는 파일이 실제로 존재하는지 테스트로 고정한다.

주요 대상:

- `src/lib/domain/recommended-exercises.ts`
- `src/components/record/recommended-picker.tsx`
- `public/exercise-thumbs/`
- `src/components/record/recommended-flow.test.tsx`

### P1 — 자주 쓰는 운동 흐름 정리

대상 흐름은 `홈 → 운동 추가 → 추천 선택 → 기록`이다.

- 운동 추가 대표 이미지는 하나만 유지한다.
- 상황·부위 선택 아이콘의 실제 보이는 크기와 안전 여백을 맞춘다.
- 추천 운동 카드는 64px 썸네일, 정보, 추가 버튼의 고정 구조를 사용한다.
- 탭과 허브에서 같은 의미의 아이콘은 같은 이름·크기·상태 규칙을 사용한다.

주요 대상:

- `src/components/record/exercise-picker.tsx`
- `src/components/record/recommended-picker.tsx`
- `src/components/record/record-empty-state.tsx`
- `src/components/ui-icon.tsx`
- `src/components/tab-bar.tsx`

### P2 — 보상·정체성 화면 정리

- 프로필·배지·챌린지에서 일반 카드와 획득 순간의 이미지 크기를 분리한다.
- 모든 카드에 트로피나 강한 글로우를 반복하지 않는다.
- 잠김·진행 중·획득 상태는 이미지 크기보다 명도와 테두리 차이로 구분한다.

주요 대상:

- `src/components/profile/`
- `src/components/challenge/`
- `src/components/home/`
- `public/badges/`
- `public/characters/`

### P3 — 전체 화면 품질 검증

- 360·390·430px에서 가로 잘림과 버튼 가림을 확인한다.
- 이미지의 실제 표시 크기, 선명도, 대비와 로딩 실패 상태를 확인한다.
- 이미지 요청 수와 총전송량을 측정하고, 화면 진입 때 필요하지 않은 이미지는
  지연 로딩한다.
- 검정 배경 위 문구와 버튼의 대비를 확인한다.

## 8. 검증 방법

### 자산·코드 검사

- 코드에 적힌 이미지 경로가 실제 파일과 모두 일치한다.
- 운동 썸네일은 WebP 하나의 규약만 사용한다.
- 이미지 실패 테스트에서 텍스트와 버튼이 그대로 남는다.
- 배지·캐릭터가 운동 썸네일 경로에서 참조되지 않는다.

### 개발 서버 직접 조작

1. `/record`에서 운동 추가 화면을 연다.
2. 상황별 추천과 부위별 추천의 아이콘 개수와 선명도를 확인한다.
3. `상황별 추천 → 처음 운동해요`에서 운동 썸네일 네 장을 센다.
4. 카드 선택·해제, 추가 버튼과 다음 이동을 직접 누른다.
5. 홈·기록·프로필·챌린지의 대표 화면을 360·390·430px에서 확인한다.
6. 이미지 한 장을 의도적으로 실패시켜 텍스트 카드가 유지되는지 확인한다.

### 최종 검사

- 관련 컴포넌트 테스트
- `pnpm lint`
- `pnpm typecheck`
- `pnpm test`
- `pnpm build`

운영 배포는 이 설계 범위에 포함하지 않는다. 구현 후 개발 서버 직접 조작과 전체
검사가 끝나도 사용자 승인 없이는 배포하지 않는다.

## 9. 완료 기준

- 360·390·430px에서 가로 잘림이 없다.
- 깨진 이미지와 의도치 않은 텍스트 전용 추천 카드가 없다.
- `처음 운동해요`의 네 운동 썸네일이 실제 기구와 일치한다.
- 주요 화면의 강한 골드 초점은 한 개 이하이다.
- 기능 아이콘, 운동 썸네일, 배지와 캐릭터가 서로의 역할을 침범하지 않는다.
- 사용자가 실제 운동 추가 흐름을 끝까지 클릭할 수 있다.
