# GND 캐릭터 아이템 상점 클릭형 목업 설계

작성일: 2026-08-01
대상 저장소: `C:\Users\SAMSUNG\workout-app`

## 1. 목표

현재 GND의 내 정보 화면에 포인트 기반 캐릭터 꾸미기 진입점을 추가한다.
이번 단계의 목적은 실제 상점 시스템을 완성하는 것이 아니라, 사용자가 아래 흐름을
이해하고 매력을 느끼는지 개발 서버에서 가장 싸고 안전하게 검증하는 것이다.

```text
내 정보 → 아이템 상점 → 아이템 선택 → 목업 구매 → 장착 → 캐릭터 변화 확인
```

기존 성장·XP·배지·포인트 화면은 유지하며 별도 앱이나 독립 데모 사이트를 만들지
않는다.

## 2. 현재 상태

- 앱은 Next.js 16 App Router, React 19, TypeScript, Tailwind CSS v4를 사용한다.
- `/profile`의 `GrowthHub`가 캐릭터 성장, XP, 배지, 포인트 잔액과 내역을 표시한다.
- `user_wallet`과 `point_transactions`가 이미 있고 운동·배지·응원 포인트가 지급된다.
- 포인트 사유에는 `item_purchase`가 예약돼 있지만 아이템 카탈로그, 보유 목록,
  장착 목록, 구매·장착 RPC, 상점 UI는 아직 없다.
- 기존 성장 캐릭터 7장은 단계마다 자세와 배경이 달라 실제 의상 레이어를 같은
  좌표로 합성할 수 없다.
- 사용자가 새로 지정한 기본 사진은 `853×1280 JPG`이며 정면에 가까운 고정
  전신 자세라 장착 기준으로 적합하다. 다만 JPG는 투명도를 저장하지 못하므로 흰
  배경을 제거한 투명 PNG 마스터가 먼저 필요하다.
- 기존 `docs/avatar-item-asset-guide.md`의 좌우대칭 A포즈·신체 앵커는 이전
  제작안이다. 이번 목업에서는 사용자 지정 사진의 외형과 자세가 우선하며, 기존
  앵커 좌표를 함께 적용하지 않는다. 목업 합성이 통과한 뒤 새 마스터의 실제
  앵커를 측정해 자산 가이드를 갱신한다.
- `이미지 꾸미기` 폴더의 기존 준비 이미지는 캐릭터와 옷의 위치가 일치하지 않아
  정식 레이어 자산으로 바로 사용할 수 없다.

구현 전에 아래 자산을 용도별로 참고한다. 세 종류를 서로 섞어 최종 합성하지 않는다.

| `이미지 꾸미기/ChatGPT Image 2026년 7월 25일 오후 01_26_34.png` | `1024×1536`, 알파 채널, 상의 단독 레이어 | 아이템 위치 보존·분리 방식 참고 |

`이미지 꾸미기`의 투명 기본 캐릭터와 상의 두 장은 기술 구조 참고용이다. 서로
실루엣과 크기가 완전히 일치하는 최종 세트라는 보장은 없고, 새로 지정한 갈색
불독과도 외형이 다르므로 이번 목업의 실제 장착 자산으로 사용하지 않는다.

사용자가 새로 지정한 갈색 불독 JPG와 해시가 같은 파일은 저장소 안에 없다.
구현 시작 시 첨부 원본 한 장만 `docs/design-sources/avatar-shop/base-reference.jpg`로
복사한다. 루트의 미추적 이미지 폴더 전체를 Git에 추가하지 않는다.

## 3. 제1원칙 판단

**핵심 문제:** 상점 데이터 구조가 아니라, 포인트를 써서 캐릭터를 꾸미는 행동이
사용자에게 이해되고 매력적인지 확인하는 것이다.

**지켜야 할 사실:** 운영 Supabase에 연결된 개발 환경이므로 목업 구매가 실제
포인트나 사용자 데이터에 영향을 주면 안 된다.

**가장 작은 해결책:** 현재 앱 안에 한 개의 목업 경로를 추가하고 구매·장착 상태를
React 메모리에만 저장한다. 그 전에 지정된 기본 사진으로 투명 베이스 캐릭터 1장과
캡·후드티·반팔·신발 실제 투명 아이템 4장을 만들어, 진짜 레이어 합성과 같은
슬롯 교체가 자연스러운지 먼저 증명한다. 화면을 새로고침하면 구매·장착 상태는
모두 초기화된다.

## 4. 화면 구조

### 4.1 기존 내 정보 화면

`/profile`의 포인트 영역 아래에 `아이템 상점 둘러보기` 진입 카드를 추가한다.
카드에는 `목업` 표시를 넣어 정식 기능으로 오인하지 않게 한다. 기존 성장 허브의
나머지 섹션과 톱니 설정 화면은 바꾸지 않는다.

### 4.2 신규 목업 화면

경로는 `/profile/avatar-mock`으로 한다. 현재 앱의 하단 탭과 색상 토큰을 그대로
사용한다.

위에서 아래 순서는 다음과 같다.

1. 뒤로가기, `아이템 상점`, 목업 잔액 `12,840P`
2. `실제 포인트와 보유 목록은 바뀌지 않아요` 안내
3. 실제 투명 레이어가 합성되는 캐릭터 미리보기
4. 분류 필터: 전체, 의상, 신발, 액세서리, 배경
5. 아이템 카드 8개
6. 선택 아이템 상세와 현재 상태에 맞는 주요 버튼

목업 카탈로그는 첨부 화면의 가격과 구성을 따른다. 첫 합성 증명에는 `GND 캡`,
`GND 후드티`, `퍼포먼스 반팔`, `조던 1 레트로`를 사용한다. 머리·상의·신발처럼
서로 다른 슬롯의 동시 합성과 같은 `top` 슬롯 교체를 모두 확인하려면 실제 자산
4개가 필요하다. 이 네 자산이 합격하기 전에는 나머지 목업 카드를 열지 않는다.

| 아이템 | 분류 | 슬롯 | 가격 |
|---|---|---|---:|
| GND 캡 | 액세서리 | head | 500P |
| GND 후드티 | 의상 | top | 900P |
| 퍼포먼스 반팔 | 의상 | top | 700P |
| 조던 1 레트로 | 신발 | shoes | 1,200P |
| 스포츠 워치 | 액세서리 | wrist | 1,500P |
| 골드 체인 | 액세서리 | neck | 1,800P |
| GND 백팩 | 액세서리 | bag | 1,100P |
| 블랙 조거 팬츠 | 의상 | bottom | 800P |

실제 자산이 준비되는 첫 4개 카드는 구매·장착할 수 있다. 나머지 4개 카드는
`준비 중`으로 표시하고 구매 버튼을 비활성화한다. 이미지가 없는 아이템을 임시
아이콘으로 장착해 실제 합성처럼 보이게 하지 않는다.

## 5. 상호작용

- 시작 잔액은 실제 지갑과 구분되는 `목업 전용 12,840P`, 보유 아이템은 0개다.
- 아이템 카드를 누르면 선택 테두리와 상세 영역이 갱신된다.
- 미보유 아이템은 `구매하기`를 누르면 목업 잔액에서 가격만큼 차감되고 보유
  상태가 된다.
- 보유 아이템은 `장착하기`, 장착 중인 아이템은 `장착 해제`를 보여준다.
- 같은 슬롯의 다른 아이템을 장착하면 기존 장착 아이템을 자동 해제한다.
- 잔액이 부족하면 구매하지 않고 `포인트가 부족해요` 안내를 보여준다.
- 장착 상태는 캐릭터 미리보기의 실제 투명 PNG 레이어와 장착 목록에 즉시
  반영한다.
- 모든 목업 상태는 컴포넌트 메모리에만 존재하고 새로고침하면 초기화된다.

## 6. 이미지 제작과 합성 규칙

### 6.1 기본 캐릭터 마스터

- 사용자가 지정한 `853×1280 JPG`의 캐릭터 외형, 자세, 체형을 기준으로 한다.
- 원본은 구현 시작 전에 `docs/design-sources/avatar-shop/base-reference.jpg`로
  보존한다. 같은 폴더의 `README.md`에 제공일, 제공자, 출처와 사용 가능 범위를
  기록한다. 출처나 사용 권한을 확인할 수 없으면 개발 목업에서만 사용하고 운영
  배포 자산으로 사용하지 않는다.
- 장착용 마스터는 `1024×1536 PNG` 투명 캔버스로 정규화한다. 원본 비율은 2:3에
  가깝지만 정확히 같지는 않으므로 가로·세로를 따로 늘리지 않는다. 비율을 유지한
  단일 배율로 확대하고 중앙에 최대 1px 투명 여백을 둔다.
- 캐릭터의 위치와 크기, 팔·다리·머리 윤곽, 검은 기본 상의와 하의는 이후 모든
  아이템 제작에서 고정한다.
- 정식 7단계를 만들 때도 목 아래 체형과 자세는 픽셀 단위로 유지하고 표정만
  바꾼다. 그래야 아이템 한 장을 모든 단계에서 재사용할 수 있다.

### 6.2 장착 사진에서 아이템 분리

1. 기본 캐릭터 마스터를 잠긴 기준 레이어로 두고 아이템이 생길 영역만 선택해
   편집한다. 선택 영역 밖의 캐릭터 픽셀은 바꾸지 않는다.
2. 장착 완성본과 함께 사용한 선택 마스크를 저장한다. 완성 사진에서 마스크 안의
   아이템 픽셀만 분리해 투명 PNG로 만든다.
3. 아이템 PNG에 캐릭터 털·피부·기본 복장 픽셀이 섞이지 않았는지 흰색과 짙은
   회색 배경 양쪽에서 확인한다.
4. 아이템 PNG를 작게 잘라 별도 좌표로 옮기지 않는다. 기본 캐릭터와 같은
   `1024×1536` 전체 캔버스를 유지하고 원래 착용 위치를 그대로 보존한다.
5. `기본 캐릭터 + 분리 아이템`을 다시 겹친 결과가 장착 완성 사진과 일치하는지
   비교한다. 경계의 캐릭터 잔상, 흰 테두리, 기본 복장 노출이 있으면 자산을
   다시 분리한다.

아이템마다 다음 네 산출물을 보존한다.

| 산출물 | 위치 | 목적 |
|---|---|---|
| 장착 완성본 | `docs/design-sources/avatar-shop/composites/{item_key}.png` | 목표 외형 |
| 선택 마스크 | `docs/design-sources/avatar-shop/masks/{item_key}.png` | 분리 재현 |
| 전체 캔버스 마스터 | `docs/design-sources/avatar-shop/items/{item_key}.png` | 편집 원본 |
| 앱 표시 레이어 | `public/avatar-mock/items/{item_key}.png` | 개발 화면 합성 |

좌표를 데이터로 계산하지 않고 PNG 캔버스에 굽는 이유는 화면 크기가 바뀌어도
캐릭터와 아이템이 같은 비율로 함께 축소되기 때문이다. 잘라낸 작은 PNG에
`x/y/width/height`를 입력하면 기기 폭과 캐릭터 단계가 바뀔 때마다 오차가
누적된다.

### 6.3 화면 합성

미리보기 컨테이너는 `position: relative`를 사용하고 모든 레이어는 아래 규칙으로
동일한 영역에 겹친다.

```css
position: absolute;
inset: 0;
width: 100%;
height: 100%;
object-fit: contain;
```

기본 순서는 다음과 같다.

| z | 레이어 | 예시 |
|---:|---|---|
| 10 | 배경 아이템 | 펜트하우스, 전용기 |
| 20 | 캐릭터 뒤 아이템 | 백팩 뒤판, 가방끈 뒤쪽 |
| 30 | 기본 캐릭터 | 투명 베이스 캐릭터 |
| 40 | 하의 | 조거 팬츠 |
| 50 | 상의 | 후드티, 반팔 |
| 60 | 신발 | 조던 |
| 70 | 손목 | 시계 |
| 80 | 머리 | 모자, 안경 |
| 90 | 캐릭터 앞 아이템 | 손에 든 가방, 목걸이 전면 |
| 100 | 전경 아이템 | 차량 |

백팩, 손에 든 물건, 손목시계처럼 신체가 아이템의 앞뒤를 동시에 가리는 경우에는
아이템을 억지로 한 장에 담지 않는다. `back`과 `front` 두 레이어로 나눠 캐릭터
앞뒤에 배치한다.

아이템 명세는 `src/lib/domain/avatar-shop-mock.ts` 한 곳에서 관리한다.

```ts
type MockItem = {
  key: string;
  name: string;
  category: "clothing" | "shoes" | "accessory" | "background";
  slot: "head" | "top" | "bottom" | "shoes" | "wrist" | "neck" | "bag" | "prop";
  price: number;
  available: boolean;
  layers: { src: string; z: number }[];
};
```

한 아이템이 앞뒤 두 장이면 `layers`에 두 경로를 넣는다. UI는 슬롯 이름으로
z값을 추측하지 않고 명세에 적힌 레이어를 z 오름차순으로 그린다.

### 6.4 성능과 표시 방식

- 편집 원본은 `1024×1536 PNG`로 보존한다.
- 앱은 `next/image`로 기본 캐릭터와 현재 장착된 레이어만 렌더한다. 미장착
  고해상도 레이어 4개를 처음부터 모두 불러오지 않는다.
- 기본 캐릭터만 우선 로드하고 아이템 레이어는 장착 시 불러온다.
- 모바일 390px 기준 최적화 응답은 기본 캐릭터 300KB 이하, 아이템 한 장 200KB
  이하, 동시 3슬롯 합계 900KB 이하를 목표로 한다.
- 이미지가 준비되기 전에는 이름 카드만 보여주며 다른 그림을 대신 합성하지 않는다.

## 8. 오류와 오인 방지

- Supabase 쓰기 함수와 RPC를 호출하지 않는다.
- 실제 `getMyWallet()` 잔액을 구매 상태에 사용하지 않는다.
- 화면 상단과 구매 버튼 근처에 목업임을 반복해서 표시한다.
- 구매 후 `목업 구매 완료 · 실제 포인트는 그대로예요` 상태 문구를 보여준다.
- 이미지 로드가 실패해도 아이템 이름과 장착 상태는 확인할 수 있게 텍스트를
  유지한다.
- 기본 캐릭터와 아이템의 캔버스 크기 또는 비율이 다르면 개발 환경에서 경고를
  표시하고 해당 아이템을 장착하지 않는다.
- 미리보기 이미지는 장식용 빈 `alt`를 사용하고, 장착 상태는 별도 텍스트 목록으로
  전달한다. 아이템 버튼은 `aria-pressed`, 구매·오류 결과는 `aria-live` 영역을
  사용한다.
- 모든 주요 버튼은 최소 44px 높이를 유지하고, 선택·보유·장착 상태를 색만으로
  구분하지 않는다. 하단 고정 버튼은 iPhone 안전 영역을 침범하지 않는다.

## 9. 검증 기준

자동 검증:

- `node scripts/validate-avatar-mock-assets.mjs` — 기본 캐릭터와 실제 아이템 4개가
  `1024×1536`이며 알파 채널을 갖는지 확인
- 목업 상태 순수 함수 단위 테스트
- 레이어 순서와 같은 슬롯 교체 단위 테스트
- 목업 화면 컴포넌트 테스트
- 관련 테스트, typecheck, lint

### 9.1 이미지 합성 선행 게이트

아래 네 단계는 UI 구현보다 먼저 끝낸다.

1. 지정 사진을 투명 기본 캐릭터로 만든다.
2. 캡·후드티·반팔·신발 실제 레이어 4개를 만든다.
3. 단독 장착, 세 슬롯 동시 장착, 후드티→반팔 교체를 흰색·짙은 회색 배경에서
   확인한다.
4. 하나라도 흰 테두리, 캐릭터 잔상, 위치 이탈, 기본 복장 노출이 있으면 상점 UI
   구현을 중단하고 해당 자산을 다시 만든다.

이 게이트를 통과한 화면 캡처와 결과를 문서에 기록한 뒤에만 아래 사용자 흐름을
구현한다.

### 9.2 개발 서버 직접 확인

1. `/profile` 기존 성장·배지·포인트 화면이 그대로 보인다.
2. `아이템 상점 둘러보기`를 눌러 `/profile/avatar-mock`으로 이동한다.
3. 카테고리별 아이템 개수가 맞게 바뀐다.
4. 폭 320px, 390px, 430px에서 기본 캐릭터와 캡·후드티·신발의 위치가 함께
   줄어들며, 기준 장착 완성본의 윤곽과 비교해 390px 화면에서 1 CSS px 넘게
   어긋나지 않는다.
5. 캡·후드티·신발을 각각 그리고 동시에 장착했을 때 흰 테두리, 캐릭터 잔상,
   기본 검은 복장의 삐져나옴이 보이지 않는다.
6. GND 캡 구매 시 `12,840P → 12,340P`가 된다.
7. 구매한 캡을 장착하고 미리보기와 버튼이 `장착 해제` 상태로 바뀐다.
8. GND 후드티 장착 후 퍼포먼스 반팔을 장착하면 같은 `top` 슬롯에서 후드티가
   해제된다.
9. 새로고침하면 잔액과 보유·장착 상태가 처음 값으로 돌아온다.
10. 기존 `/profile`과 톱니 설정 화면으로 돌아가도 기존 기능이 유지된다.

### 9.3 목업 성공 판정

기술 검증이 끝난 뒤 사용자 한 명이 별도 설명 없이 다음을 수행한다.

1. 내 정보에서 상점을 찾아 60초 안에 아이템 하나를 구매하고 장착한다.
2. 실제 포인트가 차감되지 않았다는 점을 정확히 이해한다.
3. 실제 포인트가 있다면 사고 싶은 아이템을 최소 하나 고른다.

1~2가 실패하면 화면 구조와 문구를 수정한다. 3이 실패하면 아이템 수나 DB 범위를
늘리지 않고 상품 구성과 보상 동기부터 다시 검토한다.
