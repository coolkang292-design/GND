# 운동 추가·상황별 추천 이미지 적용 설계 (2026-08-07)

## 1. 목표

첨부 시안의 `운동 추가`와 `상황별 추천` 화면을 GND의 실제 기능 위에 재현한다.
화면 전체를 한 장의 이미지로 덮지 않고, **이미지가 필요한 부분만 개별 자산으로
제작**한다. 글자·버튼·선택 상태·검색·다음 이동은 지금처럼 실제 UI로 남긴다.

## 2. 현재 상태

- 운동 추가 허브와 상황별 추천 흐름은 이미 구현돼 있다.
- 추천 카드는 `public/exercise-thumbs/` 자산을 받을 구조지만 현재 이미지 목록과
  폴더가 비어 있다.
- 허브와 상황 선택 아이콘은 이모지라 첨부 시안의 통일된 골드 선형 아이콘과
  다르다.
- 이번 작업과 무관한 기존 파일과 추적되지 않은 이미지 작업물은 수정하거나
  스테이징하지 않는다.

## 3. 선택한 방식

### 개별 이미지 자산 + 실제 UI 조합

다음 대안은 사용하지 않는다.

- **화면 전체를 이미지로 사용:** 버튼을 실제로 누를 수 없고 글자 변경과 접근성이
  깨진다.
- **CSS·이모지만 사용:** 가볍지만 첨부의 입체적인 기구 이미지를 재현하지 못한다.

이미지는 앱 실행 중 생성하지 않는다. 한 번 제작·검수한 파일을 저장소의
`public/` 아래에 포함하고 배포 시 함께 제공한다.

## 4. 이미지 자산

### 4.1 1차 톤 승인용 2장

1. `public/record-assets/exercise-picker-hero.webp`
   - 덤벨·체크리스트·돋보기를 조합한 상단 일러스트
   - 피사체는 오른쪽, 왼쪽은 실제 UI 문구가 올라갈 빈 공간
2. `public/exercise-thumbs/chest-press-machine.webp`
   - 체스트프레스 머신 단독 썸네일

두 이미지를 먼저 생성해 사용자가 실제 결과를 확인한다. 톤이 다르면 한 가지
변경점만 지정해 다시 만든다.

### 4.2 톤 승인 후 3장

- `lat-pulldown.webp`
- `leg-press.webp`
- `shoulder-press.webp`

### 4.3 공통 미술 방향

- 첨부 시안을 참고한 프리미엄 검정·골드 3D 제품 렌더
- 거의 검은 배경, 절제된 골드 림 조명, 어두운 금속 재질
- 실제 운동기구 형태를 한눈에 구분할 수 있는 3/4 시점
- 이미지 안에 글자·로고·버튼·워터마크를 넣지 않는다
- 다섯 장의 카메라 높이, 배경, 광원 방향, 대비를 통일한다
- 투명 배경은 사용하지 않는다. 카드의 검은 바탕과 자연스럽게 이어지는 배경을
  이미지 자체에 포함한다.

생성은 기본 내장 이미지 생성 경로를 사용한다. 최종 파일은 WebP로 최적화하고,
화면에서 흐려지지 않는 범위에서 용량을 줄인다.

## 5. 화면 결합

### 운동 추가 허브

- 기존 허브 상단에 첨부처럼 넓은 소개 카드를 추가한다.
- 왼쪽은 실제 HTML 문구, 오른쪽은 `exercise-picker-hero.webp`다.
- 아래의 `상황별 추천`·`부위별 추천`·검색·지난 운동 카드는 기존 동작을 유지한다.

### 상황별 추천

- `처음 운동해요`의 체스트프레스 머신·랫풀다운·레그프레스·숄더프레스 카드에
  각각의 썸네일을 연결한다.
- 이미지가 로드되지 않아도 운동명·설명·추가 버튼은 그대로 보여야 한다.
- 카드 전체 선택, 선택 해제, 선택 개수, `다음` 동작은 변경하지 않는다.

### 아이콘

- 허브와 여섯 상황의 이모지를 골드 선형 아이콘으로 교체한다.
- 단순 아이콘은 AI 이미지가 아니라 코드 기반 SVG로 만든다. 작은 크기에서도
  선명하고 선택 상태의 색을 코드로 바꿀 수 있기 때문이다.

## 6. 실패 처리와 범위

- 생성 결과가 기구를 잘못 묘사하면 그 이미지만 다시 만들고 다른 승인 이미지는
  유지한다.
- 이미지 누락 시 깨진 이미지 표시 대신 텍스트 카드로 내려간다.
- DB·마이그레이션·추천 계산·세트 기본값은 변경하지 않는다.
- 부위별 추천 전체와 다른 상황의 추가 썸네일은 이번 1차 범위 밖이다.
- 운영 배포는 포함하지 않는다. 개발 서버 직접 확인과 전체 검사 후 별도로 사용자
  승인을 받아야 한다.

## 7. 검증

### 이미지 검수

- 이미지마다 기구 종류가 맞고 서로 혼동되지 않는다.
- 글자·로고·워터마크가 없다.
- 다섯 장의 배경과 골드 조명 톤이 일관된다.
- 실제 카드 크기에서 기구가 뭉개지거나 잘리지 않는다.

### 개발 서버 직접 조작

1. `/record`에서 `첫 운동 추가하기`를 누른다.
2. 상단 소개 이미지와 골드 아이콘이 보이는지 확인한다.
3. `상황별 추천` → `처음 운동해요`로 이동한다.
4. 추천 4개 모두 썸네일이 보이는지 개수를 센다.
5. 카드 몸통으로 선택·해제하고 선택 개수가 변하는지 확인한다.
6. `다음`을 눌러 설정 화면으로 이동한 뒤 돌아오기가 유지되는지 확인한다.

### 코드 검사

- 관련 컴포넌트 테스트
- `pnpm lint`
- `pnpm typecheck`
- `pnpm test`
- `pnpm build`

## 8. 완료 기준

- 첨부 시안과 같은 검정·골드 이미지 계층이 실제 운동 추가 흐름에 적용된다.
- 상단 이미지 1장과 `처음 운동해요` 추천 이미지 4장이 모두 실물로 보인다.
- 텍스트와 버튼은 이미지에 구워 넣지 않은 실제 UI이며 기존 동작이 유지된다.
- 개발 서버 직접 조작과 전체 검사 결과가 기록된다.
