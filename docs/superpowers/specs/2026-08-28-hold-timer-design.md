# 시간이 기록되는 종목의 세트 시계 — 설계

> 사장님 지시 (2026-08-28)
> 1. *"매달리기와 같이 시간으로 운동을 하는 종목은 … 운동중의 UI를 다르게 세팅해야
>    하는거 아닐까? 시작하고 타이머가 작동이 되고 끝난다면 시간을 기록하는 형태로?"*
> 2. *"기존 운동화면에서 시작 하면 운동시간이 카운팅되고 마침 하면 그 시간이 기록이
>    되게 세팅을 하고 싶은건데"*
> 3. *"매달리기 플랭크와 같은 운동들"*
> 4. *"트레드밀이나 유산소 운동등 시간이 기록되는 운동에 모두 적용하면 좋을거 같은데?"*

---

## 0. 무엇을 만들었나

**기존 운동 화면의 `±` 스테퍼 자리 하나**가 시계로 바뀐다. 새 화면도, 새 버튼 줄도
없다.

```
매달리기                          러닝
┌──────────────┐                 ┌────────┬──────────────┐
│    00:00     │                 │  거리  │    00:00     │
│  [ ▶ 시작 ]  │                 │  3.5   │  [ ▶ 시작 ]  │
└──────────────┘                 │ [-][+] │              │
       ↓ 시작                     └────────┴──────────────┘
┌──────────────┐                        ↓ 시작
│    00:37     │                 ┌────────┬──────────────┐
│  ● 재는 중    │                 │  거리  │    32:40     │
│ [✓ 마침 ·    │                 │  3.5   │  ● 재는 중    │
│   37초 기록] │                 │ [-][+] │  [ ■ 정지 ]  │
└──────────────┘                 └────────┴──────────────┘
   = 세트 완료                          ↓ 정지 후 거리 입력
                                   [ ✓ 운동 완료 ]
```

**대상**: 매달리기 · 플랭크 · 핸드스탠드 · 사이드 플랭크 · 월 싯 · **모든 유산소**.
웨이트와 횟수형 맨몸에는 안 붙는다.

## 1. 문제의 본질 — UI가 아니라 단위였다

시간 입력 칸은 `set-input.ts`의 `DURATION` 하나였다: `key: "durationMin"` ·
`unit: "분"` · `step: 1` · `inputMode="numeric"`.

> **매달리기 37초를 기록할 수단이 앱에 없었다.** `0분`이나 `1분` 둘 중 하나다.
> 반올림으로 뭉개진 게 아니라 **애초에 표현이 안 됐다.**
> 러닝도 32분 40초에서 **40초를 잃었다.**

그런데 DB는 처음부터 초다:

```sql
-- 0004_workout_core.sql:124
duration_seconds int check (duration_seconds is null or duration_seconds >= 0),
```

챌린지 집계도 이미 초를 읽는다(`challenge.ts:900`). **기록 화면 한 겹만 뒤처져
있었다.** 그래서 이 작업은 **마이그레이션이 0건**이다.

## 2. 설계 판단 네 가지

### 2.1 카운트**업**이다 — 목표에 닿아도 **멈추지 않는다**

카운트다운·자동종료는 목표를 **상한**으로 만든다. 30초를 목표로 잡고 37초를 버텨도
30초까지밖에 못 담아 **기록 갱신이 죽는다.** 러닝도 `30분 계획`에 32분을 뛰면 32분이
맞다. 근력 운동에서 목표는 하한이고, **더 한 것이 기록**이다.

**목표에 닿으면 비프 1회만 낸다** (사장님 결정 2026-08-28, B안). 매달리는 동안에는
화면을 못 보므로 소리가 유일한 채널이다. 화면 문구도 `● 재는 중` →
`● 목표 달성 — 더 가요`로 바뀌지만 **시계는 계속 간다.**

| | 매달리기 | 계획대로 하는 플랭크 | 러닝 |
|---|---|---|---|
| 자동 종료(택하지 않음) | ❌ 37초를 못 담음 | 편함 | ❌ 32분 뛰어도 30분 |
| **알림만(택함)** | 알고서 더 버틴다 | 소리 듣고 `마침` | 문제없음 |

구현: `goalReachedBeep()` 순수 함수 + 기존 `playRestCountdownBeep`.
**새 소리도 새 타이머도 만들지 않았다.**

⚠️ **한 세트에 한 번만 운다**(`alreadyPlayed`). 없으면 목표를 넘긴 뒤 매 초 운다.
⚠️ **목표는 시작 시점에 굳힌다**(`timer.targetSec`). 매 렌더 세트에서 다시 읽으면
목표가 잰 시간을 따라다녀 영영 도달하지 않는다.
⚠️ **오디오는 `▶ 시작` 탭에서 깨운다**(`prepareRestCountdownAudio`). 브라우저는
사용자 제스처 뒤에만 소리를 허용해서, 목표 시점에 처음 부르면 아무 소리도 안 난다.

### 2.2 홀드는 `마침` = 세트 완료, 유산소는 `정지` ≠ 완료

매달리기·플랭크는 시간 말고 적을 것이 없다 → `마침` 한 번이 시간 확정이자 완료다.
유산소는 **거리가 남는다.** 뛰면서 거리를 넣을 수 없으니 멈춘 뒤에 넣어야 하고,
정지가 곧 완료면 그 기회가 사라진다.

판정 근거는 유형이 아니라 **남은 입력 칸 수**다 — `stopFinishesSet(fieldCount)`.

### 2.3 새 필드 `durationSec` — `durationMin`을 소수로 열지 않았다

`0.5분`으로도 30초는 담긴다(계획 검증·RPC 전부 통과). 파일 수는 절반이다.
그런데 그러면 `AmountField`에 "저장 단위와 표시 단위가 다르다"는 환산 규칙이 생기고
스테퍼·빠른칩·spread 배너·계획 요약이 각자 지켜야 한다. 한 곳만 빠뜨려도 화면에
`0.75분`이 뜬다. **필드 하나에 뜻 하나**를 택했다.

⚠️ **`durationMin`은 지우지 않았다.** 달력 계획·루틴·공식 프로그램 JSON이 그 키를
쓰고 서버 RPC가 `?&`로 **존재를 검사**한다(0066·0069·0070·0073). 지우면 계획 저장이
통째로 거부된다. 경계는 `durationSecondsOf()` 하나가 잇는다.

### 2.4 새 타이머 훅을 만들지 않았다

`useIdleGuard`가 이미 1초마다 `nowMs`를 준다. 시계는 **시작 시각만 들고** 매 렌더
`Math.floor((nowMs - startedAtMs)/1000)`으로 다시 센다 — 브라우저가 백그라운드에서
틱을 늦춰도 실제 시간대로 흐른다(`use-rest-countdown.ts`가 이미 값을 치르고 배운
교훈: *"90초 휴식이 5분이 됐다"*).

⚠️ **무동작 정지(`pausedSeconds`)는 빼지 않는다.** 세션 경과 시간과 일부러 다르다.
버티거나 뛰는 동안 화면을 안 만지는 것이 **정상**이라 5분 무동작 정지가 걸리는데,
그걸 빼면 진짜 30분 뛴 러닝이 5분으로 기록된다.

### [미검증] — 화면 확인이 남았다

Playwright는 스크래치 폴더에 설치해 붙였고(`/onboarding`까지 실물 렌더 확인),
개발 서버가 바뀐 코드를 서빙하는 것도 번들에서 확인했다(`재는 중`·`set-timer-card`·

번들 grep은 화면 검증이 아니다. 배포 전에 §6 표를 눌러 봐야 한다.

## 6. 화면 확인 항목 (배포 전 필수)

| # | 조작 | 기대 |
|---|---|---|
| 1 | 매달리기 담고 `운동 시작` | `±` 스테퍼 **없음** · `▶ 시작` 있음 |
| 2 | `▶ 시작` → 5초 대기 | `00:00` → `00:05`로 **올라감** · `● 재는 중` |
| 3 | 목표(30초) 도달 | **삐 1회** · `● 목표 달성 — 더 가요` · **안 멈춤** |
| 3b | 계속 두고 40초 | `00:40` · 비프는 **다시 안 울림** |
| 4 | `✓ 마침 · 40초 기록` | 세트 완료 + 휴식 시작 |
| 5 | 2세트 진입 | `00:00`부터 — **1세트 시간이 안 이어짐** |
| 6 | 운동 종료 후 상세 | **`0분`이 아니라 `40초`** |
| 7 | 러닝 담고 시작 → `▶ 시작` | 거리 칸은 그대로 · 시간 칸만 시계 |
| 8 | 러닝에서 `■ 정지` | **`마침`이 아님** · 거리 입력 가능 |
| 9 | 거리 넣고 `✓ 운동 완료` | 거리·시간 둘 다 기록 |
| 10 | 벤치프레스 | 스테퍼 그대로 · 시계 **없음** |

재는 중에 시간 칩이 **안 보이는지**.

### 적용 범위 — 카탈로그 9종 (2026-08-28 사장님 확인)

이름이 아니라 `exercise_type`/`measure`로 붙는다.

| 구분 | 종목 |
|---|---|
| 유산소 전부 | 러닝 · 걷기 · 사이클 · 로잉 |
| `measure='time'` | 플랭크 · 사이드 플랭크 · 매달리기 · 핸드스탠드 · 월 싯 |

⚠️ **카탈로그를 바꾸지 않기로 했다**(사장님 결정, 1번). 마운틴 클라이머·점핑잭·
하이 니·플러터 킥 등은 시드에서 `measure='reps'`라 시계가 안 붙는다. 실제로는
시간으로 하는 경우가 많지만 측정 단위 변경은 제품 결정이라 보류한다.
바꿀 때는 `exercise_catalog` UPDATE 마이그레이션이 필요하고, 과거 기록은
`workout_exercises.measure`가 세션별로 자기 값을 들고 있어 **뒤바뀌지 않는다**.

## 7. 남은 것

- **계획은 아직 분이다.** 달력에서 `매달리기 30초`를 담으려면 `PlanSet`에도
  `durationSec`가 필요하고, `parsePlanExercises`가 화이트리스트라 **저장 포맷이
  바뀐다.** 별도 작업으로 뺐다. 지금은 계획을 분으로 담고 기록 화면이
  `durationSecondsOf`로 초로 읽어 끊기는 곳이 없다
- **Wake Lock 없음.** 화면이 꺼져도 시계는 시각 기반이라 정확하다
