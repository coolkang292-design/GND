# 피드 사진 복구와 개별 운동 불러오기 설계

## 목표

1. 사진이 정상 등록된 공개 운동을 피드에서 큰 사진 카드로 표시한다.
2. 사용자가 운동 카드별 `불러오기` 버튼을 눌러 같은 종목의 가장 최근 완료 기록으로 현재 세트를 교체한다.

## 확인된 현재 상태

- 최신 공개 완료 운동에는 `workout_images` 행과 사진 경로가 정상 저장돼 있다.
- `workout_sessions`와 `workout_images`의 관계가 세션당 한 장으로 정의되어, 피드 조회 결과의 `workout_images`가 단일 객체로 반환된다.
- 현재 피드 변환 코드는 `workout_images[0]` 배열 형태만 처리해 사진 경로를 잃는다.
- 운동 추가 화면은 종목을 추가한 직후 `getLastRecordedSets`를 자동 호출하지만, 사용자가 동작을 선택하거나 결과를 확인할 버튼이 없다.

## 설계

### 1. 피드 사진

- 피드 조회 행의 `workout_images` 타입을 단일 객체, 배열, `null`을 모두 허용하도록 변경한다.
- 사진 경로를 읽는 작은 변환 함수에서 객체와 배열을 하나의 경로 값으로 정규화한다.
- 경로가 있으면 기존 비공개 저장소 서명 주소 생성 과정을 그대로 사용한다.
- 경로가 없거나 주소 생성이 실패하면 사진 없는 요약 카드로 표시한다.
- 데이터베이스 구조, 저장소 정책, 업로드 순서는 변경하지 않는다.

### 2. 개별 운동 불러오기

- 각 운동 카드의 요약 줄 오른쪽에 `↻ 불러오기` 버튼을 표시한다.
- 버튼은 운동 시작 전에만 활성화한다. 운동 중에는 비활성화하여 진행 기록을 덮어쓰지 않는다.
- 버튼을 누르면 현재 사용자와 해당 운동 이름으로 `getLastRecordedSets`를 호출한다.
- 기록이 있으면 현재 세트 목록 전체를 직전 기록의 세트 목록으로 교체한다.
- 중량, 세트 수, 횟수, 거리, 시간이 모두 복사 대상이다.
- 완료 여부는 모두 `false`로 초기화한다.
- 불러온 종목을 기준으로 `오늘의 한 번 더` 메시지를 갱신한다.
- 기록이 없으면 현재 입력값을 유지하고 `아직 불러올 직전 기록이 없어요`를 표시한다.
- 종목 추가 직후 실행되던 자동 직전 기록 조회는 제거한다.

## 사용자 흐름

1. 사용자가 `운동 추가`에서 종목을 선택한다.
2. 새 운동 카드는 기본 빈 세트로 표시된다.
3. 사용자가 카드의 `↻ 불러오기`를 누른다.
4. 앱이 같은 이름의 가장 최근 완료 운동을 찾는다.
5. 기록이 있으면 세트 전체가 교체되고 완료 체크는 해제된다.
6. 노력 메시지와 `직전 기록을 불러왔어요` 안내가 표시된다.

## 오류 처리

- 직전 기록 없음: 입력값 유지, 안내 메시지 표시.
- 조회 실패: 입력값 유지, 기존 오류 안내 방식으로 표시.
- 사진 경로 없음: 일반 피드 카드 유지.
- 사진 주소 생성 실패: 일반 피드 카드 유지하며 다른 피드 항목 조회를 막지 않는다.

## 테스트

- 단일 객체 형태의 사진 관계에서 사진 경로를 추출한다.
- 배열 형태와 `null`도 기존 동작을 유지한다.
- 사진 경로가 있는 피드 항목이 사진 카드로 렌더링된다.
- 개별 불러오기 성공 시 세트 수와 값이 전체 교체되고 완료 상태가 해제된다.
- 기록 없음과 조회 실패 시 기존 입력값이 보존된다.
- 운동 중에는 불러오기 버튼이 비활성화된다.
- 전체 테스트, 타입 검사, 코드 규칙 검사, 빌드를 실행한다.
- 로컬 모바일 화면에서 실제 사진 피드와 개별 불러오기 흐름을 확인한다.

## 제외 범위

- 데이터베이스 변경
- 사진 여러 장 지원
- 특정 과거 날짜 선택
- 직전 기록과 현재 입력값 병합
- 운영 배포
