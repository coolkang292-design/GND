# 홈 통합 카드 · 챌린지 CTA — 설계 (2026-08-13)

> 사용자 지시: 홈에서 **친구 상태와 운동 시작 버튼을 한 카드로 합치고**, 기존 위치의
> 친구 카드는 없앤다. 챌린지 화면의 **빠른 시작 프리셋(주 3회 / 웨이트 12일 / 1:1 대결)은
> 도입하지 않는다.**
>
> 범위 확정 (2026-08-13 사용자 선택): 챌린지는 **가벼운 것만**(오늘 운동하기 CTA · 공정성
> 안내 접기), 홈 챌린지 요약은 **얇은 요약**(이름·D-day·오늘 반영·링크).

---

## 0. 먼저 바로잡은 사실

**목업에 있는 것 ≠ 앱에 있는 것.** 사용자가 ✗ 표시한 `빠르게 시작하기 / 주 3회 /
웨이트 12일 / 1:1 대결`은 **저장소 어디에도 없다** — `main`과 워크트리 5개 전량 검색
결과 0건. 같은 목업의 `진행 중 / 참여 가능 / 지난 챌린지` 탭, `오늘의 가장 작은 목표`,
`오늘 운동하기`, `공정성 안내` 접기도 전부 미구현이다.

즉 그 줄은 **제거 작업이 아니라 "만들지 않기로 한 결정"**이다. 이 문서가 그 결정의
기록이다 — 안 적어 두면 다음 사람이 같은 제안을 다시 가져온다.

⚠️ `참여 가능` 탭은 화면 작업이 아니다. 지금 RLS는 *내가 참가자인 챌린지*만 읽게 하므로
(`getMyChallenges`가 `challenge_participants`를 경유한다), 남의 챌린지를 목록으로
보여주려면 **새 RPC + 정책 마이그레이션**이 필요하다. 이번 범위 밖이다.

## 1. 문제의 본질

**핵심 문제:** 홈이 "지금 운동할 이유"와 "운동을 시작하는 수단"을 화면의 위아래로
갈라 놓았다. 이유(친구가 오늘 했는가)를 보는 순간 누를 것이 없고, 버튼을 보는
순간에는 이유가 없다.

실측 근거 — 현재 `home-client.tsx`의 순서:

| # | 영역 | 역할 |
|---|---|---|
| 2 | 운동 시작하기 (금색) | **수단** |
| 3~6 | 성장 · 푸시 · 스트릭 · 주간 통계 | 사이에 낀 4개 |
| 7 | 진행 중 세션 | |
| 8 | 친구 목록 | **이유** |

수단과 이유 사이에 카드 5개가 있다.

**성공 기준**

1. 375×812에서 **스크롤 없이** 친구의 오늘 상태와 `운동 시작하기`가 같이 보인다
2. 홈에 같은 숫자가 두 번 나오지 않는다
3. 콕 · 운동 횟수 · 시간 · 연속일 · 배지 · 3명 접기가 **하나도 사라지지 않는다**
4. 친구 0명·챌린지 없음·조회 실패에서도 `운동 시작하기`가 **항상 있다**

## 2. 도전한 가정

| 가정 | 도전 | 판정 |
|---|---|---|
| CTA는 맨 위에 단독으로 커야 눌린다 | 크기와 클릭은 다른 축이다. 지금 CTA는 가장 크고 가장 위인데도 사용자가 구조를 바꾸자고 했다 — 큰 것이 부족한 게 아니라 **이유가 멀다** | 수정 |
| 친구 목록은 목록이니까 아래 | 이 카드는 열람용 목록이 아니라 **행동 신호**다. `상태 완료 / 운동 전`이 그 증거 | 폐기 |
| 홈에 챌린지 요약을 두면 2026-08-07 결정과 충돌한다 | 그날 옮긴 것은 **성과·순위 카드**(§6.7)다. "챌린지의 존재를 홈에서 말하지 마라"가 아니었다 | 수정 — **숫자는 탭, 존재·기한만 홈** |
| 프리셋 3개가 챌린지 진입 장벽을 낮춘다 | 챌린지 생성의 관문은 이름·기간이 아니라 **전원 KPI + 전원 동의**다(`start_challenge`). 프리셋은 그 관문을 하나도 건너뛰지 못한다 — 버튼만 3개 늘고 흐름은 그대로다 | 폐기 |
| 카드를 합치면 무조건 낫다 | 나 + 친구 3명이면 CTA가 접힘선 아래로 밀릴 수 있다. 그러면 **합친 목적 자체가 무너진다** | 조건부 — §6 실측 게이트 |
| 친구 카드 안에 CTA를 넣으면 된다 | ⚠️ **아니다.** `FriendBoardCard`는 조회가 끝나기 전 `return null`이다(`friend-board-card.tsx:519`). 그 안에 CTA를 넣으면 **로딩 동안 운동 시작 버튼이 사라진다** | 폐기 — §4.1 |

## 3. 근거 진실 (더 못 쪼개는 것)

1. **화면 세로는 유한하다.** 375×812에서 접힘선은 812px. 친구 행 하나는 이름 줄 + 지표 4칸 + 배지 줄이라 **실측이 필요하다**
2. **콕은 서버 규칙 둘로만 열린다** — 내가 오늘 운동했는가(`0028`), 24시간 안에 안 찔렀는가. 화면이 이 둘 밖의 조건을 더하면 막다른 길이 생긴다
3. **같은 숫자를 두 화면에 두면 언젠가 갈린다.** 이 저장소가 반복해서 당한 사고다(`CLAUDE.md` §같은 사실을 두 곳에 두지 않는다)
4. **친구가 0명인 사용자가 존재한다** (`NoFriendsCard`가 그 증거)
5. **진행 중 챌린지가 없는 사용자가 존재한다** (`getMyWeeklyGoalDays`가 `null`을 돌려주는 규약이 그 증거)

## 4. 근거에서 올라온 설계

### 4.1 통합 카드 — 껍데기가 먼저, 목록은 나중

GT4 · GT5에서 곧장 나온다: **CTA는 친구 조회의 성패와 무관해야 한다.**

그래서 `FriendBoardCard`의 네 갈래를 **전부 같은 `<section>` 안**에서 그린다.
지금처럼 `return null` / 실패 문구 / `NoFriendsCard`로 **카드를 통째로 갈아타면 안 된다.**

| 상태 | 친구 영역 | CTA |
|---|---|---|
| 조회 전 | 스켈레톤 행 1개 | **있다** |
| 실패 | `친구 정보를 불러오지 못했어요` | **있다** |
| 친구 0명 | `친구를 부르면 서로 기록이 보여요` + 크루 링크 | **있다** |
| 정상 | 내 행 + 친구 3명(+전체 보기) | **있다** |

⚠️ 이것이 이번 작업의 **가장 중요한 회귀선**이다. `친구 목록을 불러오는 중에도
운동 시작하기가 보인다`를 테스트로 박는다. 안 박으면 나중에 누가 early-return을
되살려 **홈에서 운동 시작 버튼이 깜빡 사라지는** 상태를 만든다.

### 4.2 카드 안 순서

사용자 지시 그대로:

```
[👥 오늘의 친구 N명]                    [전체 보기 ›]
  (내 행)  · 상태 · 운동 · 시간 · 연속 · 배지
  (친구1)  … 콕
  (친구2)
  (친구3)
─────────────────────────────────────
  🔥 운동 시작하기            30초면 기록돼요
```

- 헤딩 문구: `친구 N명` → **`오늘의 친구 N명`**
- 친구 0명이면 헤딩을 `오늘의 친구 0명`으로 두지 않는다 — `친구와 함께하면 더 강해져요`
- **N은 친구만 센다.** 내 행은 세지 않는다(기존 규약, `friend-board.ts:178` 주석)
- CTA 문구를 줄인다: 지금 3줄(`오늘의 운동` / `운동 시작하기` / `30초면 기록할 수 있어요. 친구들이 기다리고 있어요.`) → **2줄**. `친구들이 기다리고 있어요`는 바로 위 목록이 이미 말한다. 줄인 높이가 그대로 접힘선 여유가 된다

### 4.3 홈 챌린지 요약 — 숫자는 **한 함수**를 지난다

> ⚠️ **2026-08-13에 사용자가 시안으로 뒤집었다.** 처음 결정은 "얇은 요약(숫자 없음)"
> 이었고 근거는 GT3(같은 숫자를 두 곳에 두면 갈린다)이었다. 사용자가 진행률·종합점수가
> 들어간 시안을 첨부하며 그대로 해 달라고 했다. **결정은 사용자 것이므로 따르되,
> GT3는 다른 방법으로 지킨다 — 숫자를 두 곳에서 계산하지 않고 한 함수에서 받는다.**

```
🏆 개별 확인용 챌린지              [챌린지 보기 ›]
목표 진행률 40%              종합점수 10.7
[▓▓▓▓░░░░░░░░░░░]
🔒 5일 연속 시 성과 공개        결과 발표 D-15
```

**숫자가 갈리지 않게 하는 장치** (이번 작업에서 만든 것):

| 무엇 | 어디 | 누가 쓰나 |
|---|---|---|
| `scoreParticipant` | `domain/goal-score.ts` | 홈 카드 · 챌린지 탭 · **순위표** |
| `buildParticipantInput` | `lib/challenge.ts` | 홈 카드 · 챌린지 탭 · 랭킹 RPC |
| `getMyChallengeScore` | `lib/challenge.ts` | 홈 카드 |

⚠️ 옛 코드는 종합점수를 `overallScore(...) + completedGoalBonus(...)`로 **화면에서 손으로
조립**했고, 그 주석이 "순위 계산과 동일하게 보너스를 포함한다"고 스스로를 경고하고
있었다. 홈이 세 번째 조립을 만들 뻔했다. 이제 셋 다 같은 함수를 지난다.

⚠️ **카드를 쌓지 않는다** (2026-08-13 사용자 확정). 진행 중 챌린지가 여러 개면 대표
하나만 그리고 버튼을 `외 N개 ›`로 바꾼다. 수만큼 카드를 늘리면 3개일 때 351px라
성장·스트릭·주간 통계가 통째로 접힘선 밖으로 밀린다.

⚠️ **높이는 4줄이다** (2026-08-13 사용자 지시 "높이가 너무 높은 것 같아"). 첫 구현은
라벨 줄·이름 줄·숫자 2단 스택으로 6줄 ~170px였다. 지금은 **117px**(실측) —
숫자 라벨을 값 왼쪽에 붙여 2단 스택을 한 줄로 접은 것이 가장 큰 절약이다.

- 조회: `getMyChallenges(userId)` **1건만 추가**. `pickPrimaryRow`로 대표를 고른다
  — ⚠️ 챌린지 탭과 **같은 함수**를 써야 두 화면이 다른 챌린지를 가리키지 않는다
- ⚠️ **조회는 카드가 아니라 `home-client`가 한다.** 카드가 스스로 부르면 네 번째
  독립 워터폴이 생기고, 표시 규칙을 테스트하려면 매번 Supabase를 흉내 내야 한다.
  카드는 **표시 전용**으로 두고 재료를 prop으로 받는다(`FriendBoardBody`와 같은 규약)
- ⚠️⚠️ **`.catch(() => [])`를 반드시 붙인다.** `home-client.tsx:47`의 `Promise.all`은
  하나가 던지면 전부 실패하고 `catch`가 `completedAts = []`로 떨어진다. 그냥 넣으면
  **챌린지 조회 실패 하나로 스트릭·주간 통계·내 행이 통째로 사라진다.** 옆의
  `getMyWeeklyGoalDays(...).catch(() => null)`이 정확히 같은 이유로 달려 있다
- `오늘 반영` 판정: 홈이 **이미 가진** `completedAts` + `workedOutToday`. 추가 조회 0
- 링크는 `/challenge?open=<id>` — 그 파라미터를 챌린지 페이지가 이미 소비한다
  (`challenge/page.tsx:202`). 대표가 흔들려도 홈이 보여준 그 챌린지가 열린다
- **진행 중(`active`) 챌린지가 없으면 아무것도 그리지 않는다.** 빈 카드로 자리를
  차지하면 그 아래 성장·스트릭이 통째로 밀린다
- ⚠️ **달성률·참여율·종합점수를 여기 넣지 마라.** 부정 단언으로 테스트를 건다

### 4.4 D-day의 타임존 — 홈과 탭이 같은 날을 써야 한다

⚠️ **홈과 챌린지 탭은 지금 서로 다른 타임존으로 "오늘"을 정한다.**

| 화면 | 오늘의 근거 |
|---|---|
| 챌린지 탭 | `profile.timezone \|\| Intl…\|\| "Asia/Seoul"` (`challenge/page.tsx:322`) |
| 홈 | `DEFAULT_TIMEZONE` 상수 (`home-client.tsx:117`, `weekly-stats.tsx:63`) |

Asia/Seoul 사용자에겐 같지만 해외 타임존이면 **같은 챌린지가 홈에서 D-15, 탭에서
D-14**로 보인다. 숫자를 두 곳에 두지 않겠다면서 D-day라는 숫자를 두 곳에 두는 셈이다.

**규칙:** 요약 카드는 **챌린지 탭과 같은 타임존**(`profile.timezone` 우선)으로 D-day와
`오늘 반영` 여부를 **둘 다** 계산한다. `getMyProfile`이 이미 `timezone`을 돌려주는데
홈이 지금 버리고 있다(`home-client.tsx:58` — nickname·avatar만 꺼낸다). 그 필드를 같이 꺼내면 조회는 늘지 않는다.

⚠️ 카드 **안에서** 두 값이 같은 타임존을 써야 한다. D-day만 프로필 tz로 고치고
`오늘 반영`을 `DEFAULT_TIMEZONE`으로 두면 카드 한 장이 자기모순이 된다.

📌 홈 **전체**(스트릭·주간 통계)의 타임존 통일은 이번 범위 밖이다. 기존 동작이고
이번 변경으로 나빠지지 않는다 — 다만 별도 과제로 남긴다.

### 4.6 챌린지 화면 (가벼운 것만)

**(a) `오늘 운동하기` CTA** — `active` 진행 카드 안 하단.

지금 챌린지 탭에는 "그래서 오늘 뭘 하면 되나"의 답이 **없다**. 달성률만 보여주고
운동으로 가는 문이 없어서 탭을 나갔다 다시 들어와야 한다. `/record` 링크 하나로 끝난다.

⚠️ 목업의 `상세 보기` 버튼은 **넣지 않는다.** 그 버튼 바로 아래가 이미 상세
(내 목표 진행률 · 참가자 성과 · 참여자 명단)다. 자기 자신을 가리키는 버튼이 된다.

**(a-2) 진행 카드 높이 축소 + `＋ 챌린지 추가하기` 대비** (2026-08-13 사용자 지시)

- 진행 카드: `p-5` + 6줄 → `px-3.5 py-3` + 4줄. **169px**(실측, CTA 포함).
  홈 카드와 같은 방법 — 숫자 라벨을 값 왼쪽에 붙여 2단 스택을 한 줄로 접고,
  `내 목표 N개`·`참여율`·`결과 발표`를 한 줄로 합쳤다.
  결과: `챌린지 참가자 성과` 카드가 **스크롤 0에서 보인다**(실측).
- `＋ 챌린지 추가하기`: `border-line bg-surface text-muted` → `border-accent/40
  bg-accent-weak text-accent`. 옛 스타일은 어두운 배경에서 **비활성 버튼처럼**
  보였는데, 챌린지가 하나라도 있는 사람에게는 **새 챌린지를 만드는 유일한 입구**다.
  ⚠️ 금색으로 **채우지는** 않는다 — 채우면 진행 카드의 `오늘 운동하기`와 주·부가 겨룬다.

**(b) 공정성 안내 접기** — `🔒 공정성을 위해 기간 중에는 내 진행률만 볼 수 있어요`.

⚠️ **통째로 접지 않는다.** 이 배너는 "왜 남의 점수가 안 보이나"의 답이라, 접으면
그 질문이 다시 생긴다. `CrewCard`가 이미 쓰는 규약을 그대로 따른다 —
**한 줄은 남기고 상세만 펼친다**(`crew-card.tsx:75-83`의 접힘 규약).

**(c) 빠른 시작 프리셋** — 만들지 않는다. 근거는 §2.

## 5. 작업 단계 (커밋 단위)

각 단계는 그 자체로 초록이어야 한다. 중간에 멈춰도 화면이 깨지지 않는다.

**1단계 — 날짜 계산 통합 (동작 변화 0)**

⚠️ **이미 두 벌이 있다** (착수 직전 실측 — 처음 계획은 세 번째를 만들 뻔했다):

| 어디 | 무엇 |
|---|---|
| `domain/challenge-time.ts` | `challengeDaysLeft(today, end)` — 오늘 포함 남은 일수, 지났으면 0 |
| `challenge/page.tsx:69` | `periodDays(start, end)` — 지역 함수. **같은 산수를 다시 짰다** |

그러니 새 파일을 만들지 않는다. **`challenge-time.ts`로 모은다** — 이름이 이미 그 뜻이고,
`time.ts`는 순간↔달력 변환(타임존)을 다루는 곳이라 성격이 다르다.

- `inclusiveDays(startKey, endKey)` — 기간 일수 (양끝 포함). `("08-13","08-13") = 1`.
  **하한을 걸지 않는다** — 자르는 판단은 부르는 쪽이 한다
- `challengeDday(todayKey, endKey)` — 표시용 D-day. `inclusiveDays - 1`. 종료 당일 `0`, 지나면 **음수**
- `challengeDaysLeft`는 **남기되 `Math.max(0, inclusiveDays(...))`로 다시 짠다.**
  동작이 같으므로 기존 테스트 4건이 그 증거가 된다. 지우지 않는 이유는
  `participant-performance-card.tsx:130`(열람권)이 쓰고 있고, 그쪽엔 전용 회귀
  스크립트(`peek-reset-check.mjs`)가 걸려 있어 의미를 바꿀 이유가 없기 때문이다
- ⚠️ 셋이 1씩 어긋나므로 **표를 주석에 박는다.** 안 박으면 다음 사람이 아무거나 고른다
- 표기 규약도 한 곳에 둔다: **음수면 `종료`**. 챌린지 탭의
  `endedByDate ? "종료!" : D-${Math.max(0, dday)}`와 같은 답을 내야 한다
- 테스트: 같은 날 = 1일/D-0 · 지난 날 = 음수 · **월말·연말 경계**(`08-31→09-01`,
  `12-31→01-01`) · 윤년(`2028-02-28→03-01`)
- ⚠️ 이 함수들은 **`YYYY-MM-DD` 문자열만 받는다.** `Date`를 받으면 타임존이 다시
  끼어든다 — 오늘이 무슨 날인지는 부르는 쪽이 `dayKey`로 이미 정한다

**2단계 — 통합 카드 (`friend-board-card.tsx`)**
- `FriendBoardCard`에 `cta: ReactNode` prop 추가
- **네 갈래를 같은 `<section>` 안으로 통합** (§4.1) — early-return 제거
- 헤딩 `친구 N명` → `오늘의 친구 N명`, 0명 갈래 문구
- `NoFriendsCard`는 카드 안 문구로 흡수 (독립 카드 폐지)
- ⚠️ `if (!configured || !ready) return null`의 **"깜빡임 방지" 주석을 같이 고친다.**
  이제 깜빡임은 스켈레톤이 막는다 — 주석만 남으면 다음 사람이 early-return을 되살린다
- **깨질 것을 미리 센다** (실측):
  - `friend-board-card.test.tsx:590` — `친구 4명` 단언. `오늘의 친구 4명`으로 갱신
  - `NoFriendsCard`를 직접 렌더하는 `describe`(같은 파일 557행) — 카드 안 문구로 이동
- 테스트: 로딩 중에도 CTA가 있다 / 실패해도 있다 / 0명이어도 있다 /
  3명 접기·전체 보기·콕·배지·4칸 지표는 그대로 (기존 단언 유지)
- ⚠️ **가짜 통과 점검** (`CLAUDE.md` §테스트가 진짜 테스트인지): `cta` prop을 일부러
  안 그리게 고쳤을 때 위 세 단언이 **정말 빨개지는지** 눈으로 확인하고 되돌린다

**3단계 — 홈 재배치 (`home-client.tsx`)**
- 단독 CTA 블록 삭제, 통합 카드로 이동, §4.5 순서로 정렬
- `ActiveWorkoutCards` 위치 주석 갱신
- ⚠️ 여기서 **§6 실측 게이트를 통과해야** 4단계로 간다

**4단계 — 홈 챌린지 요약 (신규 `home/challenge-summary-card.tsx`)**
- 조회는 `home-client`의 기존 `Promise.all`에 `getMyChallenges(userId).catch(() => [])`
  **한 줄로** 더한다 (§4.3 — `.catch` 없으면 홈 절반이 같이 죽는다)
- `getMyProfile` 응답에서 **`timezone`을 같이 꺼낸다** (§4.4). 조회는 안 늘어난다
- 카드는 **표시 전용**: `{ challenge, timezone, completedAts }`를 받아 그리기만 한다
- 테스트: 진행 중 없으면 안 그린다 / **달성률·참여율·종합점수 문구가 없다**(부정 단언) /
  대표 선택이 `pickPrimaryRow`와 같다 / 링크에 `open=<id>`가 붙는다 /
  종료일이 지난 active는 `종료`로 그린다

**5단계 — 챌린지 화면 (`challenge/page.tsx`)**
- `오늘 운동하기` CTA + 공정성 안내 한 줄/자세히
- `page.test.tsx`에 CTA 존재 단언 추가

**6단계 — 검증 · 문서**
- §6 실측 → `PROGRESS.md` · 이 문서 갱신
