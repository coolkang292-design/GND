# 운동 중 세트 값 적용 확인 · 지난번 기록 노출 — 설계

- 날짜: 2026-08-24
- 대상 화면: 운동 중 오버레이 (`ActiveSessionOverlay`) — 입력 화면과 휴식 화면
- 사용자 지시: 2026-08-24 대화

---

## 1. 무엇을 고치는가

세 가지다. 셋 다 운동 중 오버레이 안에서 일어난다.

| # | 지금 | 바꾼 뒤 |
|---|---|---|
| ① | 스테퍼를 누르는 **즉시** 뒤 세트 전부에 조용히 반영되고 토스트가 뜬다 | 지금 세트만 바꾸고, **휴식 화면에서 물어본 뒤** 적용한다 |
| ② | 지난번에 몇 kg 몇 회를 했는지 운동 중에는 어디에도 없다 | 입력·휴식 **양쪽**에 지난번 무게·횟수를 띄우고 "한 번 더"로 유도한다 |
| ③ | 휴식 화면의 `2세트 남음`이 11.5px 보조 문구다 | **34px**로 키운다 (휴식 타이머와 같은 크기) |

곁들여 **죽은 버튼 하나를 걷어낸다** (§5).

## 2. ① 값 바꾸면 물어보고 적용

### 지금 동작

`page.tsx`의 `applyAmountFromHere()`가 스테퍼 콜백에서 바로 `propagateAmount()`를
불러 **뒤에 남은 세트 전부**를 덮어쓰고 토스트를 띄운다. 2026-08-09 지시
("운동중 무게 수정하면 다음 세트부터 일괄 적용하게")로 들어온 동작이다.

### 바뀐 흐름

```
스테퍼 조작  →  지금 세트만 바뀐다 (뒤 세트 그대로)
     ↓
'운동 완료'  →  세트 done, 휴식 타이머 즉시 시작   ← 타이머를 막지 않는다
     ↓
휴식 화면    →  카드 안에 적용 배너
```

```
┌──────────────────────────────────┐
│ 이번 세트는 12.5kg 10회로 했어요    │
│ 남은 2세트도 이렇게 할까요?         │
│   [ 적용하기 ]        [ 이번만 ]   │
└──────────────────────────────────┘
```

휴식 시작 **전에** 팝업으로 막지 않는다 (사용자 결정). 세트를 막 끝내고 숨이 찬
순간에 버튼을 하나 더 누르게 하지 않고, 답할 때까지 휴식 시간이 안 도는 것도 막는다.

### "바꿨다"를 어떻게 판정하는가 — ⚠️ 값 비교만으로는 안 된다

지금 세트와 뒤 세트의 값이 다르다는 것만으로 배너를 내면 **피라미드·드롭세트를
매번 붙잡는다.** 담기 단계(`ExerciseCard`)는 세트마다 다른 값을 **일부러** 넣는
자리다. 사용자가 아무것도 안 건드렸는데 "다르네요?"라고 묻는 것은 거짓 알림이다.

그래서 **오버레이 스테퍼로 실제로 건드린 항목만** 후보로 삼는다.

- `page.tsx`가 `touchedFields: Set<AmountFieldKey>`를 들고 있는다
- `운동 완료` 시점에 후보 중 **뒤에 남은(미완료) 세트와 값이 다른 항목**만 골라 제안을 만든다
- 하나도 없으면 배너를 내지 않는다

⚠️ **제안은 `운동 완료` 시점에 계산해서 `spreadOffer` 상태로 굳힌다.** `touchedFields`를
휴식 화면에서 읽으면 안 된다 — `toggleDone()`이 `advanceSetFocus()`로 포커스를 **이미
다음 세트로 옮긴 뒤**라, 그때 `touched`를 비우면 배너가 읽을 것이 없고, 안 비우면 다음
세트에 옛 흔적이 남는다. 순서는 이렇다:

```
운동 완료
  → buildSpreadOffer(...)  ← 포커스를 옮기기 전, 방금 끝낸 세트 기준
  → setSpreadOffer({ exerciseKey, fromIndex, offer })
  → touchedFields 비우기
  → advanceSetFocus() · 휴식 시작
```

`spreadOffer`는 **어느 종목 몇 번째 세트에서 나왔는지**를 같이 들고 있어야 한다.
포커스가 이미 움직였으므로 화면의 `focusedExercise`로는 대상을 못 찾는다.

`spreadOffer`가 비는 때: `적용하기`/`이번만`을 누를 때, 다음 세트를 완료해 **새 제안이
덮어쓸 때**, 운동을 끝내거나 취소할 때.

### 새 도메인 모듈 — `src/lib/domain/set-spread.ts`

판정을 순수 함수로 뺀다. 화면 없이 테스트할 수 있어야 한다.

```ts
export type SpreadOffer = {
  /** 배너에 실을 항목들 — 실제로 뒤 세트와 값이 다른 것만 */
  fields: { key: AmountFieldKey; label: string; unit: string; value: number }[];
  /** 바뀔 세트 수 — "남은 N세트도" 문구의 근거 */
  targetCount: number;
};

export function buildSpreadOffer(input: {
  sets: LocalSet[];
  fromIndex: number;
  touched: AmountFieldKey[];
  fields: AmountField[];
}): SpreadOffer | null;
```

- `touched`가 비면 `null`
- 뒤에 미완료 세트가 없으면 `null` (마지막 세트에서는 물을 이유가 없다)
- 적용 자체는 **기존 `propagateAmount()`를 항목마다 부른다** — 새로 짜지 않는다

### 테스트 (`set-spread.test.ts`)

1. 안 건드렸으면 `null` — 값이 세트마다 달라도 (피라미드 회귀)
2. 무게만 건드렸으면 무게만 실린다 — 횟수는 안 실린다
3. 뒤 세트가 이미 같은 값이면 `null`
4. 완료한 세트는 `targetCount`에서 빠진다
5. 마지막 세트면 `null`

## 3. ② 지난번 무게·횟수 + "한 번 더"

### 비교 기준 (사용자 결정)

**같은 번호 세트끼리** 본다. 오늘 1세트 ↔ 지난번 1세트.

| 상황 | 표시 |
|---|---|
| 지난번 같은 번호 세트가 있고 **무게가 같다** | 지난번 값 + `한 번 더` 유도 (지난번 횟수 +1) |
| 지난번 값은 있는데 **무게를 올렸다** | 지난번 값만. 횟수 도전은 **걸지 않는다** |
| 지난번에 그 번호 세트가 없다 | 표시 생략 |
| 그 종목 첫 기록 | `이 종목은 오늘이 첫 기록이에요` |

⚠️ **무게를 올린 날에 횟수까지 요구하지 않는다.** 둘을 동시에 올리라는 것은
과부하를 권하는 것이다.

### 휴식 화면 — `다음 운동` 블록

사용자가 목업에서 짚은 자리다. 지금 칩 하나만 덩그러니 있는 왼쪽 빈 공간에
`지난번` 칩을 놓고, 기존 칩을 `오늘`로 이름 붙여 나란히 둔다.

```
              다음 운동
          체스트프레스 머신

    ┌───────────┐   ┌───────────┐
    │   지난번    │   │    오늘    │
    │  10kg 10회  │   │  10kg 11회 │
    └───────────┘   └───────────┘

   [ 🔥 지난번보다 한 번 더 — 11회로 ]   ← 누르면 다음 세트가 11회가 된다

        [ ▶ 다음 운동 시작 ]
```

- `오늘` 칩은 **다음 세트에 실제로 담긴 값**을 그대로 보여준다. 도전 횟수를 미리
  넣어 두지 않는다 — 그러면 칩이 실제 값과 다른 말을 한다
- 화이팅 줄이 **누를 수 있는 자리**다. 누르면 그때 다음 세트 횟수가 지난번+1이 되고,
  `오늘` 칩이 따라 바뀐다
- 무게를 올렸으면 칩 둘만 나란히, 문구는 `무게를 올렸어요 — 횟수는 무리하지 말고`
  (누를 수 없다)
- 지난 기록이 없으면 지금과 똑같이 칩 하나만 (`오늘` 라벨 없이)

### 입력 화면 — 한 줄로 조용히

종목의 **첫 세트 앞에는 휴식 화면이 없다.** 휴식 화면에만 두면 매 종목 1세트는
지난 기록 없이 시작한다 — 무게를 정하는 가장 중요한 순간이 빈다. 그래서 입력
화면에도 둔다. 다만 여기는 이미 붐비므로 **한 줄**이다.

```
        지난번 1세트 · 10kg × 10회
        [ 🔥 한 번 더 — 11회 ]
```

`한 번 더` 칩을 누르면 지금 세트의 횟수가 지난번+1로 채워진다. 누르지 않으면
아무것도 바뀌지 않는다 — 값을 몰래 바꾸지 않는다.

### 새 도메인 모듈 — `src/lib/domain/previous-set.ts`

```ts
export type PreviousSet = { weightKg: number; reps: number };

export type PreviousSetHint = {
  previous: PreviousSet;
  /** 무게가 같을 때만 채워진다. 다르면 null */
  challengeReps: number | null;
  /** 화이팅 문구 — 화면이 문자열을 짓지 않는다 */
  cheer: string;
};

export function previousSetHint(input: {
  previousSets: PreviousSet[] | null;
  setIndex: number;
  currentWeightKg: number;
}): PreviousSetHint | null;
```

문구는 이 모듈이 유일한 출처다. 화면에 문자열을 박으면 두 화면이 갈라진다.

### 테스트 (`previous-set.test.ts`)

1. 무게가 같으면 `challengeReps === previous.reps + 1`
2. 무게가 다르면 `challengeReps === null`, 문구가 도전형이 아니다
3. 지난번에 그 번호 세트가 없으면 `null`
4. `previousSets`가 `null`이면 `null`
5. 지난번 횟수가 0이면 도전을 걸지 않는다 (기록이 사실상 없는 것)

### 자료 조달 — 쿼리 2번

`src/lib/workout.ts`에 `getPreviousCompletedSetsByExercise()`를 새로 만든다.
`getPreviousExerciseRecords()`와 같은 2쿼리 방식이다.

```ts
export async function getPreviousCompletedSetsByExercise(
  userId: string,
  exerciseNames: string[],
  excludeSessionId: string,
): Promise<Map<string, PreviousSet[]>>;
```

- 종목마다 `getLastRecordedSets()`를 부르면 5종목에 **쿼리 10번**이 나간다. 그러지 않는다
- **완료 세트가 있는 가장 최근 세션**을 고른다 — 계획만 하고 안 한 세션은 건너뛴다
- 타바타 세션은 뺀다 (세트 실적이 0이라 정상 기록을 가린다)
- 부르는 시점: 운동 **시작할 때** 오늘 담은 종목 전부. 운동 중 종목을 바꾸거나
  더하면 **그 종목만** 추가로 받는다
- 실패해도 운동을 막지 않는다 — `catch`해서 빈 Map으로 둔다. 지난 기록은 참고지 필수가 아니다

⚠️ `getProgramLoadEvidence()`를 재사용하지 않는다. 그쪽은 지난 **체감**을 실어
오는데, 그 값이 draft에 들어가면 피드백 시트가 영영 안 뜬다 (`workout.ts:742` 주석).

## 4. ③ 남은 세트 34px

휴식 화면의 종목 블록을 뒤집는다.

```
지금                          바꾼 뒤
─────────────────────       ─────────────────────
체스트프레스 머신             체스트프레스 머신
1세트 / 3세트   ← 강조         ┌─────────────────┐
2세트 남음      ← 11.5px       │  2  세트 남음     │  ← 34px, 강조색
                               └─────────────────┘
                               1세트 / 3세트 완료   ← 보조로 내려온다
```

⚠️ **`active-session-overlay.tsx`의 2026-08-07 주석을 같이 고친다.**
"휴식 화면에서 제일 큰 숫자는 지금 세고 있는 휴식 시간이어야 한다"고 적혀 있는데,
이제 남은 세트가 **같은 34px**로 동급이 된다 (2026-08-24 사용자 결정). 주석을
안 고치면 다음 사람이 이 변경을 회귀로 보고 되돌린다.

## 5. 죽은 버튼 제거 — `이전 기록 불러오기`

오버레이 입력 화면의 `이전 기록 불러오기`는 **눌러도 아무 일도 일어나지 않는다.**
토스트조차 없다.

- `page.tsx:3198`이 `loadLastExercise()`를 부른다
- `loadLastExercise()`는 `if (active || loadingExerciseKey !== null) return;`으로 시작한다
- 오버레이는 `overlayOpen = active && !minimized && !intervalPlaying` — 즉 **항상 `active`**
- 도메인 쪽 `applyLastRecordedSetsToExercises()`도 `if (active) return { loaded: null }`로 한 번 더 막는다

운동 중에 이걸 살리는 것은 답이 아니다. 지금 세트 값을 통째로 덮어써서 이미 정한
무게가 날아간다. 세트마다 지난 기록이 보이면(§3) 이 버튼의 용무는 끝난다.

**오버레이에서만 제거한다.** `ExerciseCard`(담기 단계, `page.tsx:2433`)의 같은
버튼은 **그대로 둔다** — 거기는 `active`가 아니라 정상 동작한다.

### 검증 — 제거는 부정 확인이 증거다

운동 중 오버레이에 `이전 기록 불러오기` 문구가 **없는지** 눈으로 본다. 새 문구가
보이는 것만 확인하면 제거를 검증한 게 아니다 (`CLAUDE.md` 규약).

## 7. 화면 확인 항목 (배포 전, 계정 A 하나로 충분)

상대가 필요한 기능이 아니다 — 두 계정을 쓰지 않는다 (`CLAUDE.md` §사회적 기능).

| 조작 | 기대 |
|---|---|
| 3세트 종목 시작 → 1세트 입력 화면 | `지난번 1세트 · N kg × M회` 한 줄이 보인다 |
| `한 번 더` 칩을 누른다 | 횟수 칸이 M+1로 바뀐다 |
| 누르기 **전** 휴식 화면 `오늘` 칩 | 다음 세트의 실제 값과 같다 (미리 안 바뀐다) |
| 휴식 화면에서 `한 번 더`를 누른다 | `오늘` 칩이 M+1로 따라 바뀐다 |
| 배너를 답하지 않고 다음 세트를 완료한다 | 새 배너가 옛것을 덮어쓴다 (둘이 겹치지 않는다) |
| 무게를 12.5로 올리고 `운동 완료` | 휴식 화면에 적용 배너가 뜬다. `남은 2세트` 숫자가 맞다 |
| 배너에서 `적용하기` | 2·3세트 무게가 12.5가 된다 (오버레이를 접고 카드에서 확인) |
| 배너에서 `이번만` | 2·3세트가 원래 값 그대로다 |
| **아무것도 안 건드리고** `운동 완료` | 배너가 **안 뜬다** ← 피라미드 회귀 |
| 휴식 화면 | `지난번`·`오늘` 칩 둘이 나란히, 화이팅 문구가 붙는다 |
