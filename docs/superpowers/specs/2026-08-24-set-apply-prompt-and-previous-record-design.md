## 1. 무엇을 고치는가

세 가지다. 셋 다 운동 중 오버레이 안에서 일어난다.

| # | 지금 | 바꾼 뒤 |
|---|---|---|
| ① | 스테퍼를 누르는 **즉시** 뒤 세트 전부에 조용히 반영되고 토스트가 뜬다 | 지금 세트만 바꾸고, **휴식 화면에서 물어본 뒤** 적용한다 |
| ② | 지난번에 몇 kg 몇 회를 했는지 운동 중에는 어디에도 없다 | 입력·휴식 **양쪽**에 지난번 기록을 띄우고 "한 번 더"로 유도한다 |
| ③ | 휴식 화면의 `2세트 남음`이 11.5px 보조 문구다 | **34px**로 키운다 (휴식 타이머와 같은 크기) |

곁들여 **죽은 버튼 하나를 걷어낸다** (§7).

### 건드리지 않는 것

- **`ExerciseCard`(담기 단계)의 전파는 그대로 둔다.** `updateSetFromCard()`
  (`page.tsx:1399`)는 **처방 있는 종목만** 조용히 전파하고 토스트를 안 띄운다.
  전 세트가 한 화면에 보여서 값이 바뀌는 게 그대로 보이기 때문이다 — 그 주석에
  이유가 적혀 있다. 오버레이와 규칙이 달라도 된다. 근거가 다르다.
- **`ExerciseCard`의 `이전 기록 불러오기`도 그대로 둔다.** 거기는 `active`가
  아니라 정상 동작한다 (§7).
- `propagateAmount()` 자체는 손대지 않는다. 부르는 **시점**만 옮긴다.

## 2. ① 값 바꾸면 물어보고 적용

### 2.1 지금 동작

`applyAmountFromHere()` (`page.tsx:1432`)가 스테퍼 콜백에서 바로
`propagateAmount()`를 불러 **뒤에 남은 세트 전부**를 덮어쓰고 토스트를 띄운다.
2026-08-09 지시("운동중 무게 수정하면 다음 세트부터 일괄 적용하게")로 들어왔다.

### 2.2 바뀐 흐름

```
스테퍼·빠른칩·'한 번 더'  →  지금 세트만 바뀐다 (뒤 세트 그대로)
     ↓
'운동 완료'              →  세트 done, 휴식 타이머 즉시 시작   ← 타이머를 막지 않는다
     ↓
휴식 화면                →  카드 안에 적용 배너
```

```
┌──────────────────────────────────┐
│ 이번 세트는 12.5kg로 했어요         │
│ 남은 2세트도 이렇게 할까요?         │
│   [ 적용하기 ]        [ 이번만 ]   │
└──────────────────────────────────┘
```

휴식 시작 **전에** 팝업으로 막지 않는다 (사용자 결정). 세트를 막 끝내고 숨이 찬
순간에 버튼을 하나 더 누르게 하지 않고, 답할 때까지 휴식 시간이 안 도는 것도 막는다.

⚠️ **배너는 실제로 건드린 항목만 말한다.** 무게만 바꿨으면 `12.5kg로 했어요`지
`12.5kg 10회로 했어요`가 아니다. 안 건드린 횟수까지 말하면 `적용하기`가 횟수도
바꿀 것처럼 읽힌다.

### 2.3 "바꿨다"를 어떻게 판정하는가 — ⚠️ 값 비교만으로는 안 된다

지금 세트와 뒤 세트의 값이 다르다는 것만으로 배너를 내면 **피라미드·드롭세트를
매번 붙잡는다.** 담기 단계는 세트마다 다른 값을 **일부러** 넣는 자리다. 사용자가
아무것도 안 건드렸는데 "다르네요?"라고 묻는 것은 거짓 알림이다.

그래서 **오버레이에서 사용자가 실제로 바꾼 항목만** 후보로 삼는다.

`touched`에 들어가는 것 — 셋 다 들어간다:

| 조작 | 왜 |
|---|---|
| `–`/`+` 스테퍼 | 명시적 변경 |
| 빠른 조절 칩 (`+2.5`·`-1` …) | 같은 `onChangeAmount` 콜백이다. 뺄 이유가 없다 |
| **`한 번 더` 칩** (§3) | 사용자가 눌러서 바꾼 값이다. "남은 세트도 11회로?"는 오히려 유용하다 |

`fillProgramLoads()`가 넣는 자동 무게는 **들어가지 않는다** — 사용자가 바꾼 게 아니다.

### 2.4 ⚠️ 제안은 '운동 완료' 시점에 굳힌다

`touchedFields`를 휴식 화면에서 읽으면 안 된다. `toggleDone()`이
`advanceSetFocus()`로 포커스를 **이미 다음 세트로 옮긴 뒤**라, 그때 `touched`를
비우면 배너가 읽을 것이 없고, 안 비우면 다음 세트에 옛 흔적이 남는다.

```
운동 완료
  → buildSpreadOffer(...)                       ← 포커스를 옮기기 전, 방금 끝낸 세트 기준
  → setSpreadOffer({ exerciseKey, fromIndex, offer })
  → touchedFields 비우기
  → advanceSetFocus() · 휴식 시작
```

`spreadOffer`는 **어느 종목 몇 번째 세트에서 나왔는지**를 같이 든다. 포커스가 이미
움직였으므로 화면의 `focusedExercise`로는 대상을 못 찾는다.

`spreadOffer`가 비는 때: `적용하기`/`이번만`을 누를 때 · 다음 세트를 완료해 **새
제안이 덮어쓸 때** · 운동을 끝내거나 취소할 때 · 종목을 바꾸거나 뺄 때.

⚠️ **적용 시점에 대상이 없으면 조용히 무시한다.** `exerciseKey`가 사라졌거나
(종목 빼기) `fromIndex`가 범위를 벗어났으면(세트 삭제) 아무 일도 하지 않고 배너만
닫는다. 토스트로 실패를 알리지 않는다 — 사용자가 방금 그 종목을 뺀 것이라 당연한
결과다.

⚠️ **`spreadOffer`는 localStorage에 넣지 않는다.** 새로고침하면 배너 하나를
놓치지만, draft 버전(`version: 7`)을 올리면 승격 코드가 는다. `minimized`가 같은
이유로 상태에만 있다(`page.tsx:349` 주석). 같은 판단을 따른다.

### 2.5 새 도메인 모듈 — `src/lib/domain/set-spread.ts`

판정을 순수 함수로 뺀다. 화면 없이 테스트할 수 있어야 한다.

```ts
export type SpreadOfferField = {
  key: AmountFieldKey;
  label: string;   // "무게"
  unit: string;    // "kg"
  value: number;
};

export type SpreadOffer = {
  /** 배너에 실을 항목 — 건드렸고 **또한** 뒤 세트와 값이 다른 것만 */
  fields: SpreadOfferField[];
  /** 실제로 바뀔 세트 수 — "남은 N세트도" 문구의 근거 */
  targetCount: number;
};

export function buildSpreadOffer(input: {
  sets: LocalSet[];
  fromIndex: number;
  touched: AmountFieldKey[];
  /** `amountFields()` 결과 그대로 — 유형 분기를 여기서 하지 않는다 */
  fields: AmountField[];
}): SpreadOffer | null;
```

- `touched`가 비면 `null`
- 뒤에 미완료 세트가 없으면 `null` (마지막 세트에서는 물을 이유가 없다)
- `touched`에 있어도 뒤 세트가 이미 같은 값이면 그 항목은 뺀다. 다 빠지면 `null`
- `fields`에 없는 키는 무시한다 — 유형이 안 쓰는 칸을 배너에 실으면 안 된다
- 적용은 **기존 `propagateAmount()`를 항목마다** 부른다. 새로 짜지 않는다

## 3. ② 지난번 기록 + "한 번 더"

### 3.1 비교 기준 (사용자 결정)

**같은 번호 세트끼리** 본다. 오늘 1세트 ↔ 지난번 1세트.

### 3.2 ⚠️ 종목 유형마다 다르다 — 초안이 빠뜨린 것

`amountFields()`는 유형별로 칸이 다르다. `{weightKg, reps}`만 다루면 러닝에서
`0kg × 0회`가 뜬다. **판정도 표시도 `fields`를 따른다.**

| 유형 | `amountFields()` | 지난번 표시 | `한 번 더` |
|---|---|---|---|
| `weight` | 무게·횟수 | `10kg × 10회` | **무게가 같을 때만** |
| `bodyweight` (`reps`) | 횟수 | `12회` | **항상** (무게 조건이 없다) |
| `bodyweight` (`time`) | 시간 | `45초` | **없음** |
| `cardio` | 거리·시간 | `3.2km · 25분` | **없음** |

도전을 거는 조건은 하나로 적을 수 있다:

```
fields에 reps가 있다
  AND 지난번 reps > 0
  AND (fields에 weightKg가 없다  OR  지금 무게 == 지난번 무게)
```

시간·거리 종목에 "한 번 더"는 뜻이 안 통한다. 지난번 값만 보여준다.

### 3.3 문구표 — ⚠️ 무게를 *내린* 경우도 있다

초안은 `무게를 올렸다`만 있어서 60→50kg으로 내린 날에도 "올렸어요"가 떴다.

| 상황 | 문구 | 누를 수 있나 |
|---|---|---|
| 도전 조건 충족 | `🔥 지난번보다 한 번 더 — {N}회로` | **예** |
| 무게를 올렸다 | `무게를 올렸어요 — 횟수는 무리하지 말고` | 아니오 |
| 무게를 내렸다 | `무게를 낮췄어요 — 자세부터 챙겨요` | 아니오 |
| 시간·거리 종목 | 문구 없음. 지난번 값만 | 아니오 |
| 지난번 그 번호 세트가 없다 | 표시 자체를 생략 | — |
| 그 종목 첫 기록 | `이 종목은 오늘이 첫 기록이에요` | 아니오 |

⚠️ **무게를 올린 날에 횟수까지 요구하지 않는다.** 둘을 동시에 올리라는 것은
과부하를 권하는 것이다.

⚠️ `첫 기록이에요`는 **그 종목의 1세트에만** 낸다. 3세트 내내 같은 말을 반복하면
잔소리가 되고, 2세트째부터는 이미 오늘 기록이 생겨서 사실도 아니다.

### 3.4 휴식 화면 — `다음 운동` 블록

사용자가 목업에서 짚은 자리다. 칩 하나만 덩그러니 있던 왼쪽 빈 공간에 `지난번`
칩을 놓고, 기존 칩을 `오늘`로 이름 붙여 나란히 둔다.

```
              다음 운동
          체스트프레스 머신

    ┌───────────┐   ┌───────────┐
    │   지난번    │   │    오늘    │
    │  10kg 10회  │   │  10kg 10회 │
    └───────────┘   └───────────┘

   [ 🔥 지난번보다 한 번 더 — 11회로 ]   ← 누르면 다음 세트가 11회가 된다

        [ ▶ 다음 운동 시작 ]
```

- `오늘` 칩은 **다음 세트에 실제로 담긴 값**을 그대로 보여준다. 도전 횟수를 미리
  넣어 두지 않는다 — 그러면 칩이 실제 값과 다른 말을 한다
- 화이팅 줄이 **누를 수 있는 자리**다. 누르면 그때 다음 세트 횟수가 지난번+1이 되고,
  `오늘` 칩이 따라 바뀐다
- 지난 기록이 없으면 지금과 똑같이 칩 하나만 (`오늘` 라벨 없이)
- ⚠️ **`다음 운동`이 다른 종목이면 그 종목의 지난 기록을 본다.** 방금 끝낸 종목이
  아니다. `nextUp`이 가리키는 종목·세트 번호가 기준이다

### 3.5 입력 화면 — 한 줄로 조용히

종목의 **첫 세트 앞에는 휴식 화면이 없다.** 휴식 화면에만 두면 매 종목 1세트는
지난 기록 없이 시작한다 — 무게를 정하는 가장 중요한 순간이 빈다. 그래서 입력
화면에도 둔다. 다만 여기는 이미 붐비므로 **한 줄**이다.

```
        지난번 1세트 · 10kg × 10회
        [ 🔥 한 번 더 — 11회 ]
```

누르지 않으면 아무것도 바뀌지 않는다 — 값을 몰래 바꾸지 않는다.

### 3.6 ⚠️ 휴식 화면 세로 길이

휴식 화면에 이제 여섯 덩어리가 들어간다. **`▶ 다음 운동 시작`이 스크롤 밖으로
밀리면 안 된다** — 휴식 중 가장 많이 누르는 버튼이다.

배치 순서를 고정한다:

```
● 휴식 중  /  전체 운동 진행률  /  ⏱ 운동 시간
┌ 종목 블록 ─ 2 세트 남음 (34px) ─┐
[ 적용 배너 ]        ← 있을 때만. 종목 블록 **바로 아래**
─────────
휴식 시간 (34px) + 프리셋
다음 운동 → [지난번][오늘] → [🔥 한 번 더]
[ ▶ 다음 운동 시작 ]
```

배너를 종목 블록 바로 아래 두는 이유: 방금 끝낸 세트 이야기라 종목 블록과 붙어
있어야 문맥이 맞다. 휴식 타이머 아래로 내리면 스크롤 밖으로 밀린다.

확인은 **375×667(iPhone SE)** 에서 한다 (§10).

### 3.7 새 도메인 모듈 — `src/lib/domain/previous-set.ts`

⚠️ **이 모듈은 문자열을 만들지 않는다.** `formatSetAmount()`
(`src/lib/domain/set-display.ts`)가 네 유형을 이미 다 처리하고, 그 주석이
**"표기 규칙이 두 벌이 되면 화면과 공유 텍스트의 수치가 갈라진다"**고 못박고 있다.
초안은 `summary` 문자열을 자체 생성하려 했다 — 그 규칙 위반이다.

```ts
/** 지난번 세트 한 줄 — `LocalSet`의 값 네 칸만 */
export type PreviousSet = {
  weightKg: number;
  reps: number;
  distanceKm: number;
  durationMin: number;
};

export type PreviousSetHint = {
  /** 지난번 값 — 화면이 `formatSetAmount()`에 그대로 넣는다 */
  previous: PreviousSet;
  /** 도전 조건(§3.2)을 만족할 때만. 그 밖에는 null */
  challengeReps: number | null;
  /** 화이팅·안내 문구 (§3.3). 없으면 빈 문자열이 아니라 null */
  cheer: string | null;
};

export function previousSetHint(input: {
  previousSets: PreviousSet[] | null;
  setIndex: number;
  current: Record<AmountFieldKey, number>;
  /** `amountFields()` 결과 그대로 — 유형 분기를 여기서 하지 않는다 */
  fields: AmountField[];
}): PreviousSetHint | null;
```

⚠️ **문구(`cheer`)는 이 모듈이 유일한 출처다.** 입력 화면과 휴식 화면 두 곳이
쓰므로, 화면에 문자열을 박으면 둘이 갈라진다.

### 3.7.1 오버레이에는 **계산된 hint를 넘긴다**

오버레이가 원본 `previousSets`를 받아 스스로 판단하게 하지 않는다. 이 컴포넌트의
기존 패턴은 부모가 `lastSetMessage`·`completionMessage`를 **미리 계산해** 넘기는
것이다. 같은 방식으로 간다 — prop 두 개면 끝난다.

| prop | 무엇 |
|---|---|
| `previousHint` | 입력 화면용 — 지금 세트 기준 |
| `nextUpPreviousHint` | 휴식 화면용 — `nextUp`이 가리키는 종목·세트 기준 |

⚠️ **`nextUp`에 `setNumber`가 이미 있다** (`next-up.ts`의 `NextUp`). 다음 세트가
몇 번째인지 새로 계산하지 마라. `page.tsx:3177`이 `{exerciseName, amount}`만
넘기고 있을 뿐이므로 **넘기는 항목을 넓히면 된다.**

### 3.9 자료 조달 — ⚠️ 새 함수를 만들지 않는다

초안은 `getPreviousCompletedSetsByExercise()`를 새로 만들려 했다. **필요 없다.**
`getPreviousExerciseRecords()` (`workout.ts:534`)가 이미 하는 일이 그대로다:

- 쿼리 **2번**으로 종목 이름 여러 개를 한 번에 처리한다
- 타바타 세션(`tabata_minutes`)을 이미 뺀다
- 세트마다 `weightKg`·`reps`·`distanceKm`·`durationMin`·`isCompleted`를 준다 —
  §3.7의 `PreviousSet`에 필요한 네 칸이 다 있다

**딱 하나 모자란 것: 세트 순서.** 지금 `row.workout_sets`를 정렬 없이 매핑한다.
"같은 번호 세트끼리" 비교하려면 `set_number` 순서가 필요하다. 반환 타입에
`set_number`가 없어 호출자가 정렬할 수 없으므로 **함수 안에서 정렬한다.**

```ts
// workout.ts:588 근처 — sets 매핑 전에
sets: (row.workout_sets ?? [])
  .slice()
  .sort((a, b) => (a.set_number ?? 0) - (b.set_number ?? 0))
  .map((s) => ({ ... }))
```

⚠️ **기존 호출자에게 무해하다.** `page.tsx:2115`의 완료 흐름은
`exerciseImprovementNote()`·`exerciseMetric()`로 **합계를 비교**한다 — 순서를
안 본다. 오히려 정렬이 없던 쪽이 우연에 기대고 있었다.

**호출자 쪽에서 하는 것:**

- `isCompleted`인 세트만 걸러 `PreviousSet[]`로 만든다 (§3.7)
- 완료 세트가 **0개**면 그 종목은 "지난 기록 없음"이 아니라 **"표시 생략"**이다.
  `첫 기록이에요`를 띄우면 거짓말이 된다 (계획만 하고 안 한 세션이 있었다는 뜻)

**받아들이는 손해:** 가장 최근 세션에 완료 세트가 없으면 **더 옛 세션으로
거슬러 올라가지 않는다** (`getLastRecordedSets()`는 올라간다). 그 경우 지난번
표시가 안 뜬다. **틀린 값을 보여주는 게 아니라 안 보여주는 쪽**이고, 새 DB 함수
하나를 안 만드는 값이 더 크다. 실제로 자주 걸리면 그때 폴백을 더한다.

**부르는 시점 셋:**

| 언제 | 무엇을 |
|---|---|
| 운동 시작 직후 (`sessionId`가 생긴 뒤) | 오늘 담은 종목 전부 |
| 운동 중 종목 추가·교체 | 그 종목만 |
| **새로고침으로 세션을 복구했을 때** | 오늘 담은 종목 전부 ← 초안 누락 |

⚠️ **`excludeSessionId`가 필요하므로 `draft.sessionId`가 채워진 뒤에 부른다.**
시작 RPC 응답 전에는 오늘 세션이 후보에 섞여 "지난번"이 오늘이 된다.

⚠️ **결과는 React state로만 든다. draft(localStorage)에 넣지 않는다.** 넣으면
`version: 7`을 올려야 하고 승격 코드가 는다. 새로고침 때 다시 받으면 된다.

⚠️ 실패해도 운동을 막지 않는다 — `catch`해서 빈 Map. 지난 기록은 참고지 필수가 아니다.

⚠️ `getProgramLoadEvidence()`를 재사용하지 않는다. 그쪽은 지난 **체감**을 실어

## 7. 죽은 버튼 제거 — `이전 기록 불러오기`

오버레이 입력 화면의 이 버튼은 **눌러도 아무 일도 일어나지 않는다.** 토스트조차 없다.

- `page.tsx:3198`이 `loadLastExercise()`를 부른다
- `loadLastExercise()`는 `if (active || loadingExerciseKey !== null) return;`으로 시작한다
- 오버레이는 `overlayOpen = active && !minimized && !intervalPlaying` — 즉 **항상 `active`**
- 도메인 쪽 `applyLastRecordedSetsToExercises()`도 `if (active) return { loaded: null }`로 한 번 더 막는다

운동 중에 이걸 살리는 것은 답이 아니다. 지금 세트 값을 통째로 덮어써서 이미 정한
무게가 날아간다. 세트마다 지난 기록이 보이면(§3) 이 버튼의 용무는 끝난다.

**오버레이에서만 제거한다.** `ExerciseCard`(`page.tsx:2433`)의 같은 버튼은 그대로
둔다 — 거기는 `active`가 아니라 정상 동작한다.

⚠️ **`loadLastExercise()`·`applyLastRecordedSetsToExercises()`는 지우지 않는다.**
`ExerciseCard` 경로가 쓴다. 지우면 담기 단계 기능이 통째로 없어진다.

### 검증 — 제거는 부정 확인이 증거다

운동 중 오버레이에 `이전 기록 불러오기` 문구가 **없는지** 눈으로 본다. 새 문구가
보이는 것만 확인하면 제거를 검증한 게 아니다 (`CLAUDE.md` 규약).
