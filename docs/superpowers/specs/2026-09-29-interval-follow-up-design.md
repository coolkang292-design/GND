> 확정일: 2026-09-29

## 4. 계약 — "인터벌 블록 = 앞 4개" (계획·draft·세션 공통)

`tabata_minutes`가 있는 계획·draft·세션에서:

- **0~3번 = 인터벌 블록** (`TABATA_EXERCISE_COUNT`). 음원이 이 4종을 번갈아 돈다.
- **4번~ = 이어하기 종목.** 일반 세트 규칙 그대로.
- 계획은 ChatGPT가 쓰고, draft·세션은 앱이 쓴다. 세션은 `saveSessionExercises`가
  draft 순서대로 `sort_order: i`를 넣으므로 계약이 자동으로 이어진다.

⚠️ 예전에 "앞 4개로 추정하면 틀어진다"고 봤던 것은 규칙이 아니라 **구현** 문제였다.
수요일이 틀어진 원인은 "목록 전체에서 카탈로그에 있는 4개"를 고른 것이다. 이 설계는
**앞 4개에서만** 고르고, 카탈로그에 없으면 빈칸으로 둔다(뒤에서 끌어오지 않는다).

규칙은 한 곳에 둔다: `tabata.ts`에 순수 함수 `splitIntervalPlan(exercises)` →
`{ block: 앞 4개, followUps: 나머지 }`, `isIntervalBlockIndex(tabataMinutes, index)`.
다른 파일은 숫자 4를 직접 쓰지 않는다.

## 5. 흐름

```
달력·기록 탭 "🔥 전신 인터벌 시작하기"
  → 인터벌 시트: 코스 + 인터벌 4종 + "인터벌 뒤에 이어서: 흉추 익스텐션 외 3종"
  → 시작 (draft = 인터벌 4종[tabataDraftExercises] + 이어하기[toDraftExercises])
  → 음원 (지금과 같음, 무동작 감지 꺼짐)
  → 음원 끝
      ├ 이어하기 없음 → 지금과 같이 바로 완료
      └ 이어하기 있음 → 인터벌 4종만 ✓ · 활동 시각 갱신 · 휴식 1회 · 시트 닫힘
                         → 운동중 화면이 이어하기 첫 종목으로 열림 (무동작 감지 켜짐)
                         → 세트·휴식 평소대로 → 완료 1회 → 완료 화면·AI 코치·피드 1회
```

**휴식 1회**는 세트를 끝냈을 때와 같은 호출이다:
`startRest(마지막 인터벌 세트 key, restSecondsForExercise(undefined, draft.restSeconds))`.
인터벌 종목에는 처방이 없으므로 평소 세트 간 휴식 시간(기본 90초, 마지막으로 바꾼 값)이다.
±10초·프리셋·"다음 운동 시작"·끝났을 때 토스트/자동 완료 판정이 전부 같다.

| `page.tsx` `handleFinish` 기록 갱신 판정 | **이번 세션의** 인터벌 블록 4종을 비교 대상에서 뺀다. 인터벌의 "반복"은 실제 횟수가 아니라 라운드 수(8분 = 각 4)라, 지난 일반 기록이 그보다 작으면 "4회 더 하셨어요"라는 가짜 갱신이 뜬다(순수 인터벌에도 있던 문제 — 함께 고친다). 원칙: **인터벌 블록은 세트 기록 비교의 양쪽 어디에도 쓰지 않는다** |
| 운동중 화면 | 인터벌 블록 4종은 **교체·삭제·건너뛰기 불가** — 순서가 밀리면 `sort_order < 4` 계약이 깨진다 |

서버 함수(`complete_workout_v2`·`is_valid_workout`)는 **바꾸지 않는다.** 인터벌 표시가 있는 세션은
완료만으로 유효하고, 이어하기 세트는 일반 세트로 저장된다. 인터벌 세션은 원래 '기록 보너스 +10'이
없으므로 섞인 세션도 없다 — 그대로 둔다.

지난 기록 조회는 **일반 세션과 인터벌 세션을 따로** 가져온다(각각 20·40세션 한도). 한 조회로
합치면 인터벌 세션이 한도를 먹는다. 예: 주 7회(인터벌 4 + 웨이트 3)면 AI 코치의 40세션이
8주가 아니라 약 5.7주에서 찬다. 따로 가져오면 **일반 세션 조회 결과는 지금과 한 줄도 같고**,
인터벌 세션에서는 4번 이후 행만 쓴다. 뒤 종목이 없는 순수 인터벌 세션은 아무 행도 남지 않아
AI 코치 입력에서 빠진다(지금과 같음).

⚠️ 설계를 확정할 때 넣었던 `CHECK (tabata_minutes is null or jsonb_array_length(exercises) >= 4)`는
**구현 계획 조사에서 뺐다** (2026-09-29):

1. 앱의 "지난 인터벌 기록 → 계획 복사"(`handleScheduleFromPast`)는 지워진 커스텀 종목이 있으면
   1~3개짜리 인터벌 계획을 저장한다(`picked.length === 0`일 때만 막는다). 제약이 이 경로를 저장 실패로 바꾼다.
2. `scripts/workout-plan-test.mjs`가 1종목짜리 인터벌 계획을 저장해 코스 분수를 검사한다.
3. 얻는 것이 없다. 1~3개짜리는 시트가 빈칸(3/4)으로 열어 채우게 한다. "앞 4개가 인터벌인가"는
   어차피 DB가 판정할 수 없다.

그래서 0113은 **열 설명만** 바꾼다. 데이터·제약·권한은 그대로이고, 배포 전후 아무 때나 Run해도 된다.

## 8. ChatGPT 작성 규칙 (`docs/chatgpt-plan-rules.md`)

사용자가 ChatGPT 프로젝트 지침에 붙여 넣는 한 단락. 요지:

- 인터벌(음원) 계획: `tabata_minutes` = 4·8·16. `exercises` **앞 4개**가 인터벌 종목(각 1세트,
  맨몸 동작만 — 20초 운동/10초 휴식이 4종을 번갈아 돈다). 인터벌 **뒤에** 할 운동은 5번째부터.
- 인터벌 **전에** 할 운동(워밍업 등)은 같은 날 **별도 계획**으로, 예정 시각을 더 이르게.
- 종목 이름은 `exercise_catalog`에 있는 이름 그대로. 없으면 먼저 `is_custom=true`,
  `created_by=사용자 id`로 만든다.

## 9. 데이터 보정 1회 (오뎅끼데스까)

카탈로그에 없는 4종을 이 계정의 직접 만든 운동으로 등록한다 (종류·부위·측정은 계획 행 값):
`Scapular Push-up Plus`(어깨·맨몸·횟수) · `흉추 익스텐션`(등·맨몸·횟수) ·
`도어웨이 가슴 스트레칭`(가슴·맨몸·시간) · `Wall Slide`(어깨·맨몸·횟수).
하지 않으면 수요일마다 인터벌 칸 하나가 비어 직접 채워야 한다. 계획 행은 건드리지 않는다.

## 10. 범위 밖 / 알려진 한계

- 섞인 **과거 기록**을 📋 복사·"지난 운동 불러오기"로 다시 쓰면 인터벌 4종만 옮겨진다.
  계획은 ChatGPT가 넣으므로 드문 경로. 필요해지면 따로.
- 인터벌을 건너뛰고 이어하기만 하기 — 세션 인터벌 표시(`tabata_minutes`, insert 전용 grant)를
  지울 수 없어 "인터벌 한 날"로 잘못 집계된다.
- 이어하기 종목을 앱에서 편집하기 — 편집은 인터벌 4종만, 이어하기는 보존만 한다.
- ~~AI 코치가 **이번 세션의** 인터벌 종목도 분석에 넣는 것은 바꾸지 않는다~~ → **섞인 세션은 뺀다**
  (2026-09-29 개발 서버 확인에서 뒤집음). 픽스처 A로 섞인 세션을 끝내고 리포트를 받았더니
  "푸시업 30회 → 2회, 크게 줄었다 · 이전 수준으로 회복하세요"가 떴다 — 인터벌을 한 날마다 뜰 틀린
  주의다. `supabase-deps.readSessionExercises`가 `coachSessionRows`로 블록을 뺀다.
  **순수 인터벌은 예전 그대로** 둔다 — 빼면 분석할 종목이 하나도 안 남고, 그때 코치가 무엇을 말할지는
  이번 범위가 아니다.
- 페이지가 인터벌 음원 **도중에** 새로고침되면 음원은 이어지지 않는다(지금과 같음).
