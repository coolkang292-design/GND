# 종목별 기록 갱신 판정 설계

작성 2026-07-21. 사용자 확정: 종목별 비교 · 알림 1건으로 묶기 · 개선폭 문턱 없이 전부 발송.

## 목표

기록 갱신 판정을 **세션 총합 비교**에서 **종목별 비교**로 바꾼다. 그러면 종목 구성이 달라도 판정할 수 있고, 알림 문구가 "볼륨 +300kg" 같은 추상적 수치 대신 "벤치프레스를 2회 더 하셨어요"처럼 사람 말이 된다.

## 지금 방식의 한계 (교체 이유)

`2026-07-21-beep-boost-praise-badges-design.md`로 구현해 배포한 현재 판정은:

- **종목 이름 집합이 정확히 같은** 직전 세션을 찾아 세션 전체 합계를 비교한다. 종목을 하나만 바꿔도 판정 자체가 일어나지 않는다.
- 합계 비교라서 **종목을 빼면 유리해진다** — 지난번 벤치+스쿼트를 했고 오늘 벤치만 하면 스쿼트는 비교에서 빠지고 벤치만 평가된다.
- 문구가 "볼륨 +300kg"이라 어느 종목이 늘었는지 알 수 없다.
- 완료할 때마다 내 완료 이력 전체를 무제한 조회한다.

종목별 비교는 이 넷을 한 번에 해결한다. 종목을 뺀 건 그 종목을 평가받지 않는 것일 뿐 다른 종목 성적에 영향을 주지 않으므로 악용 경로가 사라진다.

## 판정 규칙

### 비교 대상

오늘 완료한 **종목 각각**에 대해, **그 종목의 직전 기록**을 찾아 비교한다.

- 최근 20개 완료 세션 범위에서 찾는다(기존 `getLastRecordedSets`와 같은 범위).
- **방금 완료한 세션은 제외**한다. 자기 자신과 비교하게 된다.
- **타바타 세션은 제외**한다. 타바타는 세트 실적이 0으로 기록되므로, 후보가 되면 정상 기록을 가린다.
- 직전 기록이 없는 종목(오늘 처음 하는 종목)은 판정에서 제외한다.

### 종목별 개선 판정

유형에 맞는 지표 하나로 환산해 비교한다. **완료 세트만** 센다.

| 유형 | 지표 |
|---|---|
| 웨이트 | 볼륨 = Σ(무게 × 횟수) |
| 맨몸 (measure=reps) | 총 횟수 |
| 맨몸 (measure=time) | 총 시간(분) |
| 유산소 | 거리 km. 거리가 양쪽 다 0이면 시간(분) |

직전 지표가 0 이하면 비교하지 않는다(개선율이 무한대가 된다). 이번 지표가 직전보다 크면 개선이다.

**개선폭 문턱은 두지 않는다.** 1회만 더 해도 갱신이다(사용자 확정).

### 문구 생성

판정은 위 지표로 하되, **문구는 실제로 변한 항목**으로 쓴다. 웨이트는 우선순위대로 첫 번째로 늘어난 항목을 쓴다.

| 유형 | 조건 | 문구 |
|---|---|---|
| 웨이트 | 완료 세트 수 증가 | `{종목}을 {N}세트 더 하셨어요` |
| 웨이트 | 최대 무게 증가 | `{종목}을 {N}kg 더 무겁게 드셨어요` |
| 웨이트 | 총 횟수 증가 | `{종목}을 {N}회 더 하셨어요` |
| 웨이트 | 위 어느 것도 아님 | `{종목} 볼륨이 {N}kg 늘었어요` |
| 맨몸(횟수) | — | `{종목}을 {N}회 더 하셨어요` |
| 맨몸(시간) | — | `{종목}을 {N}분 더 버텼어요` |
| 유산소 | 거리 기준 | `{종목}을 {N}km 더 뛰었어요` |
| 유산소 | 시간 기준 | `{종목}을 {N}분 더 뛰었어요` |

소수는 소수점 2자리까지만 남기고 정리한다(기존 `trimNumber` 재사용).

**조사 처리:** 종목 이름 뒤의 목적격 조사는 받침 유무에 따라 갈린다 — "벤치프레스**를**"(받침 없음) vs "랫풀다운**을**"(받침 있음). 고정하면 "랫풀다운를"처럼 어색해지므로 마지막 글자의 종성을 보고 고른다. 한글 음절은 `(코드 − 0xAC00) % 28 !== 0`이면 받침이 있다. 한글이 아닌 이름(영문·숫자로 끝나는 커스텀 종목)은 "를"로 처리한다.

**시간 입력 제약(알려진 한계):** 시간은 분 단위 정수로만 입력된다(`exercise-card.tsx`). 따라서 플랭크 60초→90초 같은 개선은 표현할 수 없고 1분→2분이 되어야 잡힌다. 이번 범위에서 입력 UI는 바꾸지 않는다.

### 여러 종목이 개선된 경우

**알림은 세션당 1건**으로 묶는다.

- 대표 종목 = **개선율(비율)이 가장 큰 종목**. 동률이면 운동 순서상 앞선 종목.
- 1종목: `벤치프레스를 2회 더 하셨어요`
- 2종목 이상: `벤치프레스를 2회 더 하셨어요 외 2종목 갱신`

## 저장 형식과 알림 문구

`workout_sessions.record_note`에 **닉네임 없는 서술 문구**를 저장한다. 예: `벤치프레스를 2회 더 하셨어요 외 2종목 갱신`

그러면 각 표시 지점이 자연스럽게 조립된다.

- **크루 알림 body**: `{닉네임}님이 {문구}. 칭찬 한마디 남겨주세요! 👏`
  → `민수님이 벤치프레스를 2회 더 하셨어요 외 2종목 갱신. 칭찬 한마디 남겨주세요! 👏`
- **크루 알림 title**: `🏅 기록 갱신! 칭찬해주세요` (변경 없음)
- **완료 화면**: `🏅 기록 갱신! {문구}`
- **피드·달력 배지**: `🏅 {문구}`

현재 RPC는 문구를 40자로 제한하는데 새 문구가 길어지므로 **80자**로 늘린다. 종목 이름이 긴 경우("바벨 인클라인 벤치프레스")까지 감안한 값이다.

## 구성 요소

1. **`lib/domain/record-beaten.ts` 교체** — 세션 총합 기반 `effortTotals`·`recordBeatenNote`·`findComparableSession`(과 타입 `EffortTotals`·`ComparableCandidate`)은 **완전히 삭제**한다. `record/page.tsx` 외에는 쓰는 곳이 없음을 확인했으므로 죽은 코드를 남기지 않는다. 해당 테스트도 함께 지운다. 새 순수함수:
   - `exerciseMetric(exercise)` → 유형별 지표 하나
   - `exerciseImprovementNote(previous, current)` → 종목 하나의 문구 또는 null
   - `recordBeatenSummary(comparisons)` → 개선된 종목들을 받아 대표 문구 + 개선 종목 수
2. **배치 조회 `lib/workout.ts`** — `getPreviousExerciseRecords(userId, exerciseNames, excludeSessionId)`. 쿼리 2회로 끝낸다: ①최근 완료 세션 20개(타바타·제외 세션 뺀 것) ②그 세션들의 `workout_exercises` 중 이름이 일치하는 행 + 세트. 클라이언트에서 종목별 최신 1건을 고른다. 기존의 "완료 이력 전체 무제한 조회"를 대체하므로 백로그 항목도 함께 해소된다.
3. **완료 흐름** — `handleFinish`에서 `draft.sourceSessionId` 특례를 없앤다. 종목별 비교는 복사 여부와 무관하게 동작하므로 분기가 필요 없다. 판정·RPC 실패가 완료를 막지 않는 원칙은 유지한다.
4. **0021 마이그레이션** — `mark_record_beaten`의 알림 body 템플릿을 `{닉네임}님이 {문구}. 칭찬 한마디 남겨주세요! 👏`로 바꾸고 문구 길이 제한을 80자로 올린다. 배지 지급 로직은 그대로 둔다.

배지 시스템(0020)과 푸시 배관(0016)은 변경하지 않는다. 갱신 횟수 집계가 `record_note is not null` 기준이므로 그대로 동작한다.

## 테스트

### unit (TDD)

- `exerciseMetric`: 유형별 환산 · 미완료 세트 제외 · 유산소 거리 0이면 시간 사용.
- `exerciseImprovementNote`: 세트 증가 · 무게 증가 · 횟수 증가 · 볼륨만 증가(폴백) · 맨몸 횟수 · 맨몸 시간 · 유산소 거리 · 유산소 시간 · 동률은 null · 직전 0이면 null · 소수 정리 · **조사 선택**(받침 있는 이름 "랫풀다운을", 받침 없는 이름 "벤치프레스를", 영문 이름은 "를").
- `recordBeatenSummary`: 1종목 · 2종목 이상 "외 N종목" · 개선율 최대 종목 선택 · 동률이면 앞선 종목 · 개선 없음이면 null · 문구 80자 초과하지 않음.

### 실 DB

- `scripts/record-beaten-test.mjs`: 새 문구 템플릿에 맞춰 단언을 갱신한다.
- `scripts/badge-test.mjs`: 배지 로직은 그대로이므로 문구만 새 형식으로 맞춘다.

### 실기기

같은 종목을 지난번보다 1회 더 하고 완료 → 완료 화면에 종목 이름이 든 문구 · 피드 배지 · 크루 폰에 "○○님이 △△를 N회 더 하셨어요" 푸시.

## 제외 범위 (YAGNI)

- 개선폭 문턱(10% 등) — 사용자가 문턱 없이 전부 보내기로 확정
- 종목별 개인 최고기록(PR) 추적 — 직전 기록 대비만 본다
- 시간 입력을 초 단위로 바꾸는 것
- 알림에 종목별 상세 목록 전부 넣기 — 대표 1종목 + "외 N종목"

## 마이그레이션 요약

**0021_record_note_wording.sql** — `mark_record_beaten` 교체: 알림 body 템플릿 변경 + 문구 길이 제한 40 → 80. 사용자가 SQL Editor에 1회 적용한다. **0001~0020은 적용 완료이므로 재실행하지 않는다.**
