# 홈 재편 — 친구 목록(상태·콕) + 챌린지 탭 통합 (설계)

작성 2026-08-07 · 방법론 `first-principles` · 마이그레이션 **0건**

사용자 지시 5건:

1. 홈에 **친구 리스트**를 넣고 친구의 **레벨 · 운동 횟수 · 운동시간 · 배지 갯수**를 보여준다
2. 친구를 클릭하면 **그 친구의 성과**를 확인할 수 있게 한다
3. 기본 **3명**만 표시하고 **전체 보기**를 누르면 전부 보인다
4. **챌린지 내용은 챌린지 탭으로 통합**한다
5. 친구 리스트에 **상태 표시 + 콕 찌르기**를 넣는다 *(2026-08-07 추가)*

사용자 확정 4건:

- 집계 기간은 **누적 전체**
- 챌린지 성과 카드는 **기능을 유지한 채 챌린지 탭으로 이동**
- 전체 보기는 **그 자리에서 펼치기**
- **순위·등수는 표시하지 않는다** *(2026-08-07 추가 — 메달·"현재 N위"를 넣지 않는다)*

> ⚠️ **지시 5는 홈에 찌르기를 두 곳 만든다.** 콕은 지금 크루 카드에 있고 대상이 같은 사람들이다.
> 이 문서는 **찌르기를 친구 목록 한 곳으로 옮기는 안**을 택했다(§6.6). 크루 카드에도 남기려면
> 그 절의 이유를 먼저 보라 — 상태를 공유하지 않으면 실제로 어긋난다.

## 1. 문제의 본질

**핵심 문제:** 홈이 "나 혼자 얼마나 했나"만 말한다. 지금 홈에서 친구가 등장하는 곳은 크루 카드의
이름 칩(콕 찌르기용)과, 5일 연속 운동해야 2시간만 열리는 잠긴 챌린지 순위판뿐이다. **평소에는
친구가 얼마나 하고 있는지 볼 방법이 아예 없고**, 콕은 이름만 있는 칩에 붙어 있어 *왜 이 사람을
찔러야 하는지*가 화면에 없다.

**성공 기준 (측정 가능):**

- 홈을 열면 친구 한 명당 **네 숫자(레벨·누적 횟수·누적 시간·배지 수)** 와 **오늘 상태**가 보인다
- 친구가 4명 이상이면 기본 **3행**, '전체 보기' 후 **전원**이 보인다 (행 수를 센다)
- 친구를 누르면 그 사람의 성과 상세가 열린다
- **같은 목록에서 콕을 찌를 수 있고**, 누른 뒤 잠기며, 앱을 다시 켜도 잠긴 채로 있다
- **순위·등수·메달이 화면에 없다** (부정 확인)
- 홈에서 `🏆 챌린지 참가자 성과`가 **사라지고**, 챌린지 탭에서 **같은 기능이 동작한다**

## 2. 착수 실측 — 이미 있는 것과 없는 것

계획을 세우기 전에 저장소·운영 스키마에서 직접 확인했다. **여섯 가지가 예상과 달랐다.**

| 필요한 것 | 실측 결과 | 새로 만들 것 |
|---|---|---|
| 친구 명단 | `get_my_crew()` RPC가 **id·닉네임·아바타·total_xp·level을 한 번에** 준다 (`crew-link.ts:47`) | 없음 |
| 친구 레벨 | 위 RPC의 `total_xp` | 없음 |
| 친구 운동 횟수·시간 | `workout_sessions` RLS가 크루의 완료·공개 세션을 열어 준다. `duration_minutes`가 행에 있다 | 질의 1개 |
| 친구 배지 수 | ⚠️ `user_badges` RLS는 **본인 행만**. 정의자 RPC `get_crew_member_profile(id)`로만 뚫린다 — **1인 1콜** | 없음(호출 N회) |
| 친구 성과 상세 시트 | `MemberProfileSheet`가 이미 있다 — 레벨·XP·보유 배지를 그린다 | 성과 블록 추가 |
| **오늘 운동 상태 · 콕** | `poke_user` RPC · `getMyRecentPokeTargets()`(0053) · 오늘 운동 판정까지 **크루 카드에 전부 있다** | **재배치**(새 기능 0) |
| 챌린지 성과 카드 | `home/challenge-performance-card.tsx` 220줄, **홈에만** 있다. 챌린지 탭엔 없다 | 이동 + 배선 변경 |

**⚠️ 그냥 만들었으면 깨졌을 자리 7개**

1. **레벨을 두 가지 방식으로 계산하고 있다.** `crew-list.tsx:95`는 DB 캐시값 `current_level`을 쓰고,
   `progression.ts:157`은 **`total_xp`로 다시 계산**하며 그 이유까지 주석에 박아 뒀다("내 정보 화면과
   같은 함수를 써야 두 화면의 숫자가 어긋나지 않는다"). 새 카드가 캐시값을 쓰면 **홈은 Lv.7,
   친구 시트는 Lv.8**이 될 수 있다 → 새 카드는 `getLevelProgress(totalXp)`를 쓴다.
2. **친구 간 비교의 자가 다르다.** RLS는 친구 세션을 `visibility='group'`으로 좁히지만 **내 세션은
   전부** 보여준다 → 목록 숫자는 `.eq("visibility","group")`을 **일괄 적용**한다.
   `0004_workout_core.sql:74`가 기본값을 `'group'`으로 두고 `src`에 `'private'`을 쓰는 코드가
   **한 줄도 없으므로 오늘 눈에 보이는 변화는 0**이다.
3. **챌린지 성과 카드는 자기가 볼 챌린지를 스스로 고른다** (`getMyChallenges` → `pickPrimaryRow`).
   그런데 챌린지 탭에는 **사용자가 고른 챌린지**(`selectedId`)가 따로 있다. 그대로 옮기면 탭에서
   B 챌린지를 보는데 카드만 A 챌린지를 그린다 — 0044에서 이미 당한 종류다 →
   **`challengeId`를 prop으로 받게 바꾸고 내부 조회를 걷어낸다.**
4. **`badge_metrics(uuid)`를 재활용하면 안 된다.** 이 정의자 함수는 `workout_count`·`total_minutes`를
   이미 계산하지만 **visibility를 보지 않는다**(`db-current-schema.sql:508`). 지금은 결과가 같지만
   **같은 값이 나온다고 같은 함수가 아니다** → 쓰지 않는다.
5. **행 전체를 버튼으로 감싸면 버튼이 중첩된다.** 크루 카드가 이미 겪고 주석까지 달아 뒀다
   (`crew-card.tsx:133` "콕 버튼과 형제로 둔다") → 친구 행도 *시트 열기* 버튼과 *콕* 버튼을
   **형제로** 둔다. 감싸면 HTML이 유효하지 않고 눌리는 곳이 브라우저마다 달라진다.
6. **내가 오늘 운동했는지를 목록 질의로 판정하면 안 된다.** 목록 질의는 `visibility='group'`으로
   좁히는데 서버 `poke_requires_workout`은 **내 세션 전부**를 본다(`0028:39`). 좁힌 값으로 판정하면
   *서버는 허용하는데 버튼만 흐릿한* **막다른 길**이 생긴다 → 홈이 이미 들고 있는
   `completedAts`(무필터)로 판정한다. **새 조회 0.**
7. **찌르기 상태를 두 벌 두면 반드시 어긋난다.** 성과판에서 콕을 눌러 잠가도 크루 카드의 같은
   버튼은 열린 채로 남는다 — `poked` Set이 컴포넌트마다 따로이기 때문이다. "눌렀는데 또 눌린다"가
   되고, 두 번째 누름은 서버가 `poke_cooldown`으로 막아 **에러 토스트로만 알게 된다** → §6.6.

그리고 **자물쇠 설계가 이미 두 겹으로 갈려 있다는 것**이 이번 재편의 열쇠였다 (§4 G5).

## 4. 근본 사실 (Ground Truths)

- **G1.** 친구 = `crew_links`의 상호 수락 상대. 다른 원천은 없다
- **G2.** `user_badges`·`user_progress`는 RLS상 **본인 전용**이다. 남의 값은 `SECURITY DEFINER`
  함수를 통해서만 나올 수 있다 — 우회로가 존재하지 않는다
- **G3.** `workout_sessions`는 크루의 **완료 + `visibility='group'` + 미삭제** 세션을 열어 준다.
  운동 횟수·시간·오늘 여부·스트릭은 **이미 읽을 수 있는 데이터**다
- **G4.** `profiles`는 크루에게 전체 행이 열려 있다 (`weekly_goal`·`timezone`까지)
- **G5. 이 앱의 자물쇠는 "챌린지 점수"에만 걸려 있다.**
  - 잠김: 챌린지 달성률·순위 → `challenge/page.tsx:984` `🔒 공정성을 위해 기간 중에는 내 진행률만`,
    참여자 목록도 나 빼고 전부 `🔒`(`:1006`)
  - **안 잠김:** 크루원의 레벨·누적 XP·보유 배지 전량 → `MemberProfileSheet`가 크루 카드·피드에서
    아무 조건 없이 연다 (`get_crew_member_profile`은 `is_crew_with`만 본다)
- **G6. 콕은 양쪽 조건이 다 맞아야 눌린다** (`poke_user`, 0028→0039 현행):
  ① 내가 **오늘** 운동을 마쳤고 ② 상대가 크루이며 ③ 24시간 안에 안 찔렀고
  ④ 상대가 찌르기를 끄지 않았다(`pokes_disabled`) ⑤ 나 자신은 못 찌른다(`self_poke`).
  **서버가 최종 판정자다** — 화면은 그 규칙을 앞당겨 보여줄 뿐 새로 만들지 않는다

**G5가 홈/챌린지 분리의 근거다.** 목록이 보여줄 네 숫자는 **전부 "안 잠긴 쪽"**이다.
잠긴 쪽(챌린지 점수)은 손대지 않고 챌린지 탭으로 간다. 지시 ①과 ④는 서로 다른 두 일이 아니라
**하나의 선을 긋는 일**이다 — *크루 성장은 홈에서 항상, 챌린지 경쟁은 챌린지 탭에서 규칙대로.*

## 5. 추론 사슬

```
G1 (친구 = crew_links)
  └→ get_my_crew() 1콜로 명단·닉네임·아바타·total_xp                   [새 DB 작업 0]
G3 (세션이 이미 읽힌다)
  └→ 친구 id로 세션 1질의 → 횟수·시간·오늘여부·스트릭을 전부 계산       [새 DB 작업 0]
       └→ 크루 카드의 getTodaysWorkoutUserIds 질의가 필요 없어진다 (질의 -1)
G2 (배지는 정의자 함수뿐)
  └→ 기존 get_crew_member_profile(id)를 사람 수만큼 병렬 호출          [새 DB 작업 0]
G6 (콕 규칙은 서버가 판정)
  └→ 상태·콕을 목록 행에 얹는다. 상태가 곧 "왜 찌르는가"의 근거다
       └→ 상태가 한 곳에만 있어야 잠금도 한 곳이다 → 크루 카드에서 콕을 뺀다
G5 (자물쇠는 챌린지 점수에만)
  └→ 네 숫자는 잠그지 않는다 · 챌린지 성과 카드는 자물쇠가 있는 탭으로
       └→ 그 카드는 "🔒 종료일 공개" 목록의 **자물쇠를 푸는 장치**다. 자물쇠 바로 위가 제자리다
```

**최소 해:** 조회 RPC 2 + 질의 1 + 배지 N · 새 컴포넌트 1 · 순수 모듈 1 · **SQL 0줄.**
크루 카드의 질의 1개가 **줄어든다**(오늘 운동 여부를 목록이 이미 계산한다).

```ts
export function formatTotalMinutes(min: number): string;                // 3180 → "53시간"
```

**정렬 — 순위표가 아니라 "지금 할 수 있는 일" 순이다.**

```
① 오늘 아직 운동 안 한 친구  →  ② 최근 운동 시각 ↓  →  ③ 닉네임
```

- 순위를 안 보여주기로 했으므로 **성과순으로 줄 세우지 않는다.** 성과순은 등수를 안 적어도
  자리 자체가 등수다
- ①인 이유는 **콕이 접힌 3행 안에서 살아 있어야** 하기 때문이다. 최근 운동순으로만 두면
  오늘 완료한 사람이 위를 채우고 **찌를 수 있는 사람이 '전체 보기' 뒤로 숨는다**
- **나는 목록에 넣지 않는다.** 순위가 빠지면서 비교 기준이라는 존재 이유가 사라졌고, 내 레벨은
  바로 위 성장 카드에, 주간 기록은 주간 통계에 이미 있다. 콕도 자기 자신에겐 못 한다(G6-⑤)
  → *뒤집으려면 `buildFriendRows`에 내 행을 더하고 콕 버튼만 빼면 된다. 한 곳이다*
- **`badgeCount: number | null`** — `0개`와 "못 받았다"를 **타입으로 구별한다.** 2026-08-02에
  `routines`를 `[]`로 초기화했다가 조회 실패를 0개로 착각해 실버그가 났다. 같은 실수를 막는다
- `formatTotalMinutes`는 누적이라 값이 크다. 60분 미만 `48분`, 이상 `53시간`

### 6.3 `lib/friends.ts` — I/O 계층

```ts
export async function getFriendBoard(myUserId: string): Promise<FriendRow[]>
```

1. `getMyCrew()` — 친구 id·닉네임·아바타·`totalXp` (RPC 1콜)
2. `workout_sessions` 1질의 — `select("user_id, completed_at, duration_minutes")`
   `.in("user_id", 친구ids)` `.eq("status","completed")` **`.eq("visibility","group")`**
   `.is("deleted_at", null)` `.not("completed_at","is",null)`
3. 배지 — `Promise.allSettled(ids.map(getCrewMemberProfile))` + `getBadgeCatalog()` 1콜.
   개수는 **`earnedBadgeCount(catalog, badges)`를 그대로 재사용** → 시트의 `보유 배지 N / M`과
   목록의 `🏅N`이 **정의상 어긋날 수 없다**. 한 명이 실패해도 그 행만 `badgeCount: null`
4. `getMyRecentPokeTargets()` — 24시간 안에 찌른 상대 (RPC 1콜, 0053). 앱을 다시 켜도 `✅ 찌름` 유지

**⚠️ 레벨은 `getLevelProgress(totalXp).currentLevel`로 계산한다** — 캐시값이 아니다(⚠️1).
**⚠️ 내가 오늘 운동했는지는 이 질의로 판정하지 않는다** — 홈의 `completedAts`를 쓴다(⚠️6).
**⚠️ 홈의 기존 `getCompletedSessions(userId)`는 건드리지 않는다** — 스트릭·주간 통계용이고
visibility 필터가 없다(내 전체 기록이 맞다). 목적이 달라 합치지 않는다. 합치면 스트릭이 조용히 바뀐다.

### 8.2 개발 서버 화면 확인 — **A·B 두 계정 필수**

찌르기·알림이 걸리므로 전역 지침상 **두 계정**이다 (크롬 = A, 엣지 = B).
`node scripts/dev-fixture.mjs create` → `status`로 크루 연결 확인.

| 조작 | 기대 |
|---|---|
| A 홈을 연다 | 친구 목록에 **B 행**. B의 횟수·시간이 B 화면의 실제 기록과 **숫자가 같다** |
| B로 운동을 완료한다 | A 홈 새로고침 → B 행이 `✅ 오늘 완료`로 바뀌고 **콕 버튼이 사라진다**, 횟수 **+1** |
| A가 오늘 운동 전 상태 | B 행의 콕이 **흐리게**, 안내 문구가 뜬다 |
| A가 오늘 운동을 마친다 | 콕이 **활성**된다 |
| A가 B를 콕 찌른다 | A 버튼이 `✅ 찌름`으로 잠기고 → **B 화면 알림 벨에 뜬다** ← 받는 쪽을 본다 |
| A가 앱을 새로고침한다 | `✅ 찌름`이 **그대로 잠겨 있다**(0053 서버 기록) |
| A가 B 행을 누른다 | 시트에 B의 레벨·누적 성과·보유 배지. **배지 수가 목록의 🏅N과 같다** |
| 친구 4명 이상 상태 | 기본 **3행**, `전체 보기` → **전원**, `접기` → 3행 ← **행 수를 센다** |
| 친구 0명 계정 | 빈 상태 + `/crew` 이동. `전체 보기`가 **없다** |
| **A 홈 전체를 훑는다** | ① `🏆 챌린지 참가자 성과`가 **없다** ② 크루 카드에 `👉 콕`이 **없다** ③ **등수·메달이 없다** ← 부정 확인 3건 |
| A 챌린지 탭(active) | 같은 카드가 `🔒 공정성을…` 아래에 뜬다. 5일 미달이면 블러+자물쇠, 달성이면 참가자 선택 → 순위 |
| 챌린지가 2개인 계정 | 탭에서 챌린지를 바꾸면 **카드도 같이 바뀐다**(⚠️3) |

⚠️ **`전체 보기` 경로는 친구가 4명 이상이어야 존재한다.** 현재 픽스처는 A·B 2개뿐이라 그대로는
**이 경로를 검증할 수 없다** — 확인용 계정 2개를 더 만들어 A의 크루로 붙인 뒤 확인하고 정리한다.
붙이지 못하면 "3명 초과 경로 [미검증]"으로 남기고 배포 판단을 사용자에게 넘긴다.

| 성능·확장 | 15 | 10 | 세션 전량 질의의 **행 상한을 검토하지 않았다**(B1) |
| 화면·상태 설계 | 15 | 9 | 로딩·부분 도착·깜빡임·카드 순서·접근성이 전부 미정의(B4·B5·B6) |
| 실행 가능성 | 15 | 11 | 구현 순서·롤백·픽스처 4명 절차가 없다(B8) |

### B1. 세션 질의에 상한을 명시한다

누적 집계라 `limit`을 못 건다고 넘어갔는데, **PostgREST는 응답 행 수에 상한을 걸 수 있고 초과분은
조용히 잘린다.** 잘리면 오류 없이 **숫자만 틀린다** — 가장 나쁜 실패 모양이다.

- 실측 총 79행(§8.4)이라 **지금은 위험이 없다.** 그래서 RPC로 서둘러 옮기지 않는다
- 대신 `.limit(FRIEND_SESSION_ROW_LIMIT = 2000)`을 **명시**하고, 받은 행이 상한과 같으면
  `truncated: true`를 함께 돌려준다. 카드는 그때만 `일부 기록만 반영된 수치예요`를 덧붙인다
- **배지 N+1과 같은 시점에 같은 함수로 접힌다** — 상한에 닿거나 크루가 10명을 넘으면
  `get_crew_board()` 정의자 함수 하나(0061)로 둘 다 해결된다

### B2. 상태는 **3단계**다 — "운동 중"이 빠지면 화면이 자기모순이 된다

홈 위쪽 `ActiveWorkoutCards`가 "B 15분째 운동 중 🔥"을 띄우는 동안, 아래 목록은 같은 사람을
**`운동 전` + `👉 콕`** 으로 그린다. 운동 중인 사람을 찌르라고 권하는 화면이다.

- `getActiveCrewSessions`는 **홈이 이미 부르고 있다**(`active-workout-cards.tsx:44`, 60초 폴링)
- → **`HomeClient`가 한 번 불러 두 곳에 내려준다.** `ActiveWorkoutCards`에는 **선택적 prop**으로
  넣어 값이 없으면 지금처럼 스스로 조회한다 — **피드 페이지 사용처가 안 깨진다**
- 상태: `✅ 오늘 완료` / `🔥 운동 중` / `운동 전`. **운동 중이면 콕 버튼을 숨긴다**
- 정렬 ①의 "오늘 아직 운동 안 한 친구"에서 **운동 중인 사람은 뺀다** (찌를 수 없으므로)

### B3. 찌르기 실패 문구를 채운다

크루 카드는 `poke_cooldown`·`poke_requires_workout` 둘만 문구가 있고 나머지는
"찌르기를 보내지 못했어요"로 뭉갠다. `notification_settings`는 **본인만 읽을 수 있어**
(`db-current-schema.sql:2706`) 상대가 찌르기를 껐는지 **화면이 미리 알 방법이 없다** — 그래서
서버 응답으로만 알 수 있고, 그 응답에 맞는 문구가 필요하다.

| 코드 | 문구 |
|---|---|
| `poke_cooldown` | 24시간 안엔 한 번만 찌를 수 있어요 |
| `poke_requires_workout` | 오늘 운동을 마쳐야 콕 할 수 있어요 💪 |
| **`pokes_disabled`** | **상대가 찌르기 알림을 꺼 뒀어요** |
| **`not_crew`** | **크루가 아니에요** |
| 그 외 | 찌르기를 보내지 못했어요 |

### B4. 로딩·부분 도착 규약

- `configured && ready`가 아니면 **카드를 렌더하지 않는다** (크루 카드와 같은 규약 — 깜빡임 방지)
- 목록은 **명단+세션이 오면 그린다.** 배지는 늦게 와도 되므로 `badgeCount: null`이면 `🏅—`로
  **자리를 미리 차지한다** → 값이 채워져도 행 높이가 안 변한다(레이아웃 이동 없음)
- 조회 전체 실패 → 카드를 숨기지 않고 한 줄 안내(성장 카드 규약)

### B5. 접근성

- 행의 왼쪽 버튼 `aria-label="{닉네임} 성과 보기"` · 콕 `aria-label="{닉네임} 찌르기"` ·
  잠긴 콕은 `aria-label="{닉네임} 찌름 완료"` (크루 카드가 쓰던 문구를 그대로 옮긴다)
- 펼치기 토글에 `aria-expanded`
- 상태는 색·점이 아니라 **글자**로 적는다 (`오늘 완료`·`운동 중`·`운동 전`)

### B6. 홈 카드 순서 (확정)

```
헤더 → 운동 시작하기 → 성장(레벨) → 푸시 유도 → 스트릭 → 주간 통계
     → 진행 중 운동 → 👥 친구  ← 새 카드
     → 크루(이름·인원·초대 링크) → 로그인 상태
```

진행 중 카드 **바로 아래**가 친구 목록이다 — "운동 중"이 위에서 아래로 이어 읽힌다.

### B7. 크루 카드 회귀 테스트를 **새로 만든다**

### B8. 구현 순서 · 롤백 · 픽스처

## 9.5 구현 실측 (2026-08-07)

계획대로 7단계를 다 밟았다. **계획에서 달라진 것 3개와 구현 중 드러난 것 2개**를 적는다.

### 계획과 달라진 것

1. **B4의 "배지 늦게 채우기"를 실제로 그렇게 짰다** — `getFriendBoardBase()`(명단·세션·찌른기록)와

2. **`workedOutToday`를 순수 함수로 뽑았다** — 계획에선 `HomeClient`의 `useMemo` 안에 있었는데,
   그러면 ⚠️6(내 오늘 여부를 어떤 자료로 판정하는가)을 **테스트로 고정할 수 없다.** 변이 6이
   실제로 실패하는지 확인하려면 도메인에 있어야 한다.
3. **챌린지 전환 시 상태 초기화를 `key`로 바꿨다** — effect 본문에서 `setState`를 부르니
   `react-hooks/set-state-in-effect`가 막았다(렌더 연쇄). 부모가 `key={challenge.id}`로

### 구현 중 드러난 것

4. **첫 테스트 실행이 실버그를 잡았다.** 정렬 tiebreak에서 `lastWorkoutAt`이 없는 사람끼리
   비교할 때 `-Infinity - -Infinity = NaN`이 되고, **비교 함수가 NaN을 돌려주면 정렬 결과가
   정의되지 않는다** — 닉네임 갈래로 넘어가지도 못한다. `null`을 명시적으로 다루도록 고쳤다.
5. **계획의 변이 4·6에는 테스트가 없었다.** `visibility='group'`(I/O 계층)과 내 오늘 여부
   판정이 어느 테스트에도 안 걸려 있었다 — "변이를 넣으면 실패한다"고 적어 놓고 **실패할 그물이
   없는** 상태였다. `src/lib/friends.test.ts`(질의 불변식)를 신설하고 3번으로 메웠다.

## 10. 결론

**권고안:** 친구 = 크루라는 기존 사실 위에, **이미 읽을 수 있는 데이터만으로** 홈 친구 목록을
만든다. SQL 0줄. 콕은 그 목록으로 **옮겨서 한 곳에만 둔다.** 챌린지 성과 카드는 지우지 않고
자물쇠가 있는 챌린지 탭으로 옮긴다.

**핵심 통찰 둘:**

1. 지시 ①(친구 성과)과 ④(챌린지 통합)는 별개가 아니다. 이 앱은 **크루 성장 데이터는 이미 열어 두고
   챌린지 점수만 잠가 왔다**(G5). 둘을 각자 자리로 보내는 **하나의 작업**이다
2. 지시 ⑤(콕)는 기능 추가가 아니라 **재배치**다. 콕이 필요로 하는 것(상태·근거)이 새 목록에 있고,
   두 곳에 두면 잠금이 갈라진다. **더하는 게 아니라 옮기는 것**이 정답이다

**받아들이는 절충:** 배지 수는 당분간 1인 1콜이다. 크루가 커지면 정의자 함수 하나로 접되,
그날 바뀌는 코드는 `lib/friends.ts` 내부뿐이다.
