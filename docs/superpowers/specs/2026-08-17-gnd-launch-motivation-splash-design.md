# GND 실행 동기부여 스플래시 설계 (2026-08-17)

> 사용자 목표: GND 앱을 완전히 닫았다가 다시 실행할 때마다, 피지컬 100처럼
> 강한 운동 자극을 주되 GND만의 블랙·골드 이미지와 문구를 1.5초간 보여준다.

---

## 1. 목표와 성공 기준

앱을 여는 첫 순간을 매일의 운동 시작 의식처럼 만든다. 사용자가 별도 버튼을
찾거나 읽지 않아도, 같은 대표 이미지와 GND 이름을 반복해서 보며 브랜드와 운동
의지를 함께 떠올리게 하는 것이 목표다.

성공 기준은 다음과 같다.

1. 새 앱 실행 세션의 일반 GND 화면 진입 시 대표 화면이 정확히 한 번 보인다.
2. 이미지가 준비된 뒤 1.5초가 지나면 자동으로 홈 화면이 보인다.
3. 화면 어디든 터치하면 즉시 넘어간다.
4. 같은 실행 세션에서 화면 이동이나 새로고침을 해도 반복되지 않는다.
5. 앱 창을 완전히 닫고 새로 실행하면 다시 보인다.
6. 이미지 로딩이나 브라우저 저장소가 실패해도 앱 진입을 막지 않는다.

## 2. 확정된 사용자 경험

### 2.1 노출 시점

- `하루 1회`가 아니라 **새 실행 세션마다 1회**다.
- 앱 실행 세션 동안 `sessionStorage`에 `gnd:launch-splash:shown=1`을 저장한다.
- `sessionStorage`는 같은 창의 새로고침에는 남고 창을 닫으면 끝나므로, 사용자가
  요구한 동작에 가장 가깝다.
- 모바일 운영체제가 앱을 종료하지 않고 백그라운드에 보존했다가 복귀시키면 같은
  세션으로 본다. 이때는 다시 띄우지 않는다.
- 모바일 웹은 실제 종료 순간을 신뢰성 있게 감지할 수 없으므로 `unload`나
  `beforeunload`로 키를 지우지 않는다.

근거:

- [MDN — sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage)
- [Chrome for Developers — Page Lifecycle API](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)

### 2.2 포함·제외 화면

- 일반 탭 앱 셸인 `/home`, `/feed`, `/record`, `/challenge`, `/profile`과 그 하위
  화면에서만 스플래시 부품을 마운트한다.
- `/login`, `/auth/callback`, `/onboarding`, `/invite/*`, `/account`, `/crew`,
  `/whats-new`, `/admin/*` 직접 진입에는 표시하지 않는다.
- 신규 사용자가 `/home`으로 들어왔다가 온보딩으로 이동하는 경우에는 최초 일반 앱
  진입으로 간주한다. 스플래시가 끝난 뒤 온보딩 화면을 보게 된다.

### 2.3 시간과 조작

- 이미지가 실제로 표시된 시점부터 `1,500ms` 뒤 종료한다.
- 전체 화면을 하나의 건너뛰기 버튼으로 만들어 어디든 터치할 수 있다.
- 종료할 때 `180ms`로 짧게 사라진다.
- `prefers-reduced-motion` 사용자는 사라지는 애니메이션 없이 즉시 전환한다.
- 이미지 준비가 늦어도 전체 차단 시간은 최대 `3,000ms`를 넘지 않는다.

## 3. 대표 이미지 설계

### 3.1 장면

- 비가 막 그친 야외의 젖은 검은 바닥
- 탄탄한 체형의 성인 남녀 선수가 나란히 배틀로프를 힘껏 휘두르는 순간
- 차가운 공기와 뜨거운 체온이 만나 어깨와 몸 주변에 수증기가 피어오름
- 얼굴은 역광 그림자로 가려 특정 인물을 알아볼 수 없음
- 신체는 선정적으로 다루지 않고 운동선수의 힘·균형·동작을 강조
- 젖은 바닥에는 인물과 골드 조명이 낮고 길게 반사됨
- 세로 `9:16` 구도이며 두 인물은 중앙 안전 영역에 둔다
- 배틀로프는 전경을 향해 대각선 파도를 만들며 속도감을 준다

### 3.2 색과 조명

- 배경·바닥·의상: 깊은 블랙과 차콜
- 근육의 가장자리, 물방울, 바닥 반사: 따뜻하고 절제된 골드
- 밝은 노랑이나 화려한 주황은 쓰지 않는다.
- 피부 전체를 금색으로 칠하지 않고, 골드는 역광과 반사에만 사용한다.

### 3.3 브랜드와 문구

- 승인된 최종 배경 이미지 자체에는 상단 중앙의 큰 골드 `GND`만 둔다.
- 메인 문구는 앱이 하단에 실제 HTML 텍스트로 두 줄 표시한다.

  ```text
  지금은 같은 출발선.
  1년 뒤, 프로와 아마추어가 갈린다.
  ```

- `지금은 같은 출발선.`은 흰색,
  `1년 뒤, 프로와 아마추어가 갈린다.`는 골드로 강조한다.
- 폰트 디자인은 승인된 **굵고 앞으로 기울어진 전진형** 안을 이미지에 그대로
  유지한다.
- 생성형 이미지가 `같은`을 `갈은`으로 반복 왜곡했으므로 한글은 이미지에서 완전히
  제거한다. 앱은 실제 HTML 텍스트를 사용해 오타 없이 선명하게 표시한다.
- HTML 문구는 굵기 `900`, 앞으로 `-8deg` 기울기, 흰색 첫 줄·골드 두 번째 줄,
  왼쪽 속도선으로 승인된 역동적 인상을 재현한다.
- 보이는 실제 텍스트를 `aria-describedby`에 연결해 스크린 리더에도 같은 문구가
  읽히게 한다.
- 문구 아래 별도 영문 슬로건은 두지 않는다. GND와 메인 문구의 위계를 흐리지
  않도록 화면의 메시지를 둘로 제한한다.

### 3.4 저작권·브랜드 경계

- 첨부한 피지컬 100 포스터는 분위기 참고 자료로만 사용한다.
- 피지컬 100의 로고, 제목 글자, 넷플릭스 표기, 카피, 인물, 정확한 구도는 사용하지
  않는다.
- 최종 자산은 GND용으로 새로 생성하며 승인된 `GND` 외에 다른 브랜드 표식이나
  읽을 수 있는 글자가 이미지 안에 나타나지 않게 한다.

## 4. 컴포넌트 구조

### 4.1 `DailyMotivationSplash`가 아닌 `LaunchMotivationSplash`

노출 기준이 날짜가 아니라 실행 세션이므로 이름도 그 사실을 반영한다.

```text
src/components/launch-motivation-splash.tsx
  ├─ sessionStorage 판정
  ├─ 이미지 준비·오류 상태
  ├─ 1.5초 타이머와 3초 안전 타이머
  ├─ 터치 건너뛰기
  └─ 페이드 종료·접근성

src/app/(tabs)/layout.tsx
  └─ LaunchMotivationSplash 마운트

public/splash/gnd-launch-motivation-v3.png
  └─ 상단 GND만 포함하고 하단 문구 영역이 비어 있는 9:16 배경 이미지
```

DB, Supabase, 인증 상태, 서비스 워커 데이터는 바꾸지 않는다.

### 4.2 상태 흐름

```text
checking
  ├─ sessionStorage에 shown 있음 → hidden
  └─ 없음 → shown을 즉시 기록 → loading
                                  ├─ 이미지 준비 → showing → 1.5초/터치 → fading → hidden
                                  ├─ 이미지 실패 → fallback → 짧게 표시 → hidden
                                  └─ 전체 3초 초과 → hidden
```

- `checking` 동안에는 기존 앱 화면이 순간적으로 비치지 않도록 앱 배경과 같은 검은
  덮개를 렌더한다.
- `shown`은 이미지가 뜨기 전에 기록한다. 화면 이동이나 빠른 재렌더로 같은 세션에
  두 번 나타나는 것을 막는다.
- 저장소 접근이 거부되면 현재 자바스크립트 실행 동안의 메모리 플래그를 사용한다.
  저장소 오류 때문에 앱을 막거나 오류 화면을 띄우지 않는다.

## 5. 표시 품질과 접근성

- 이미지는 `object-fit: contain`으로 전체를 보여준다. 세로 승인 이미지의 위 `GND`와
  아래 문구가 가로 화면에서도 잘리지 않아야 하며 남는 영역은 검은 배경으로 둔다.
- 승인 PNG 원본을 변형하지 않고 저장하며 Next Image로 기기 크기에 맞게 최적화해
  시작 자산으로 우선 로드한다.
- 이미지의 상단 GND와 HTML 문구는 세로 화면의 중앙 안전 영역 안에 유지한다.
- 전체 덮개는 `button type="button"`으로 만들고 `aria-label="시작 화면 건너뛰기"`를
  제공한다.
- 생성 이미지는 장식 이미지로 처리하고, 카피는 보이는 실제 HTML 텍스트로 읽히게
  한다.
- 스플래시가 떠 있는 동안 아래 화면의 스크롤과 터치를 막는다.

## 6. 오류 처리

| 상황 | 동작 |
|---|---|
| 이미지 로딩 성공 | 1.5초 표시 후 전환 |
| 이미지 로딩 실패 | 검은 배경 + 골드 GND + 문구만 잠깐 표시 후 전환 |
| 3초 안에 이미지 상태 미확정 | 즉시 덮개 제거 |
| `sessionStorage` 읽기·쓰기 실패 | 메모리 플래그로 중복을 줄이고 앱은 계속 진입 |
| 사용자가 연속 터치 | 첫 번째 종료만 처리하고 이후 입력 무시 |
| 컴포넌트가 중간에 해제됨 | 모든 타이머 정리 |

## 7. 검증 설계

### 7.1 자동 테스트

- 세션 키가 없으면 스플래시가 표시되고 키가 즉시 기록된다.
- 세션 키가 있으면 이미지가 표시되지 않는다.
- 같은 실행 세션에서 새로고침을 모사해도 다시 표시되지 않는다.
- 세션 키를 지우면 새 실행처럼 다시 표시된다.
- 이미지 준비 후 1,500ms에 자동 종료한다.
- 1,500ms 전에 터치하면 즉시 종료한다.
- 이미지 오류 시 텍스트 대체 화면을 거쳐 종료한다.
- 저장소 예외와 3초 안전 타이머가 앱 진입을 막지 않는다.
- 접근성 이름과 reduced-motion 분기가 유지된다.

### 7.2 개발 서버 실제 화면 확인

프로젝트 규칙에 따라 자동 테스트만으로 완료하지 않는다.

1. 개발 서버의 `/home`을 새 실행 세션으로 열어 이미지가 **1개만** 보이는지 확인한다.
2. 배경의 `GND`와 HTML의 `지금은 같은 출발선.` /
   `1년 뒤, 프로와 아마추어가 갈린다.`가 오타 없이 한 번만 보이는지 확인한다.
3. 남녀 선수의 얼굴은 식별되지 않고 신체·수증기·젖은 바닥·블랙/골드 조명이
   의도대로 보이는지 확인한다.
4. 그대로 두어 1.5초 뒤 홈이 보이는지 확인한다.
5. 다시 새 세션을 열고 즉시 터치해 바로 홈으로 넘어가는지 확인한다.
6. 같은 세션에서 새로고침하고 탭을 이동해도 다시 나오지 않는지 확인한다.
7. 창을 완전히 닫고 새로 열어 다시 표시되는지 확인한다.
8. 개발자 도구로 세션 키를 지운 뒤 다시 표시되는지 확인한다.
9. 좁은 휴대폰 폭에서 GND·인물·문구가 잘리지 않는지 확인한다.

동작 코드 변경이므로 화면 확인 후 `pnpm lint`, `pnpm typecheck`, `pnpm test`,
`pnpm build`를 각각 한 번 실행한다. 개발 서버와 build는 `.next`를 공유하므로 동시에
실행하지 않는다.

## 8. 배포 게이트

- 이 기능은 화면 변경이므로 개발 서버에서 위 흐름을 직접 조작하기 전에는 배포하지
  않는다.
- 설치형 PWA에서 “완전 종료 후 재실행” 동작은 실제 휴대폰에서도 확인한다.
- 전체 검사 통과와 사용자 승인 후에만 프로젝트 지정 Vercel CLI 절차로 배포한다.
- 배포 후 `https://gnd-one.vercel.app`에서 이미지, GND, 문구, 자동 종료, 터치 건너뛰기를
  다시 확인한다.

## 9. 이번 범위에서 하지 않는 것

- 이미지 여러 장 순환
- 날짜·요일·운동 기록에 따른 문구 개인화
- 소리·진동·배경 음악
- 서버 저장이나 계정 간 노출 횟수 동기화
- 관리자용 이미지 교체 기능
- 피지컬 100 또는 다른 브랜드 자산 사용
- 백그라운드 복귀를 새 실행으로 추정하는 시간 기준 로직
