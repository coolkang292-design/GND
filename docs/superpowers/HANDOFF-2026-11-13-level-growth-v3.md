## 1. 한 줄 요약

'내 성장'을 "처음 3번 vs 최근 3번"에서 **"현재 단계에 들어올 때까지의 종목별 최고 기록 vs 이번 단계 최고 기록"**으로 바꿨다. 기준을 넘은 종목만 성장 기록이 되고 종합 평균 %는 없다. 진화(단계 상승)마다 기준이 새로 잡힌다. **서버 진화 판정·진화 카드 문구는 그대로다.**

## 6. 사용자 결정 대기 (설계 문서 §8 열린 질문)

1. `M` 보정 — 이전 단계에서 2일 이상 한 종목만 세는가?
2. `current_stage` 쓰기를 `apply_xp_and_progress`에서 별도 함수로 옮기는 것을 승인하는가(지시서 8절 예외)?
3. 단계 진입 기준을 스냅샷으로 고정할 것인가, 매번 재계산할 것인가(후자면 위 테이블·RPC drop 승인 필요)?
4. 미션 종류·단계별 개수, 인터벌·유산소 미션의 측정 방식.
5. 문턱 %·비율은 표본이 한 계정에 치우쳐 있다 → 출시 후 조정 절차.
6. 진화 대기 중 크루 알림 문구.
7. **진화 카드 ③ 칸 처리**: 플래그를 켜면 진화 카드의 옛 "+2.5% / +8.0%"와 새 '내 성장' 카드가 한 화면에 같이 보인다. (a) 설계 확정 때까지 둔다(새 카드는 플래그 끔 상태로 배포 보류) (b) 플래그가 켜졌을 때 ③ 칸만 "아래 '내 성장' 카드 참고" 안내로 바꾼다.
8. **옛 종목별 문턱 초안의 숫자 정정**: M=18에서 jump 제외 후 +8% 이상은 2종목이므로 옛 '종목마다 +8%' 방식이면 N=3/4 모두 미충족이었다. 이는 최신 **상위 N개 평균 목표**와 다른 방식이다. 최신 방식의 결과는 유산소까지 포함해 새 계획 Task 3에서 다시 계산한다. 진행 중인 단계를 최종 탈락으로 단정하지 않는다.
9. **점프 임계값(+100%)** 유지 여부 — 기구가 바뀐 경우 외에 정상 향상까지 제외하는 부작용 감수 여부.

## 10. 후속 구현계획 (2026-11-13)

- [후속 계획](plans/2026-11-13-evolution-gate-implementation.md)은 카드 마무리 → 유산소 포함·상위 N종목 평균·기구별 이름·점프/문턱 영향 분석 → 승인 후 서버 판정·실제 단계 표시 → 앱 배포와 규칙 활성화 분리 순서다. 서버 구현·적용은 아직 시작하지 않았다.
- 사용자 결정: **기구별로 종목 이름을 나누고, 과거 모호한 비교는 따로 검증한다.** 과거 기록 자동 변경·기구 입력 폼 추가는 하지 않는다. 현재 +100% 점프 제외의 유지·서버 적용 여부는 §6 질문 9와 별개다.
- 사용자 확정: **실제 성장 종목 최소 N개 + 상위 N개 평균 목표 동시 충족**. 필요3개에 +10/+8/+6이면 평균8%, 필요4개이면 빈 자리0으로 평균6%·종목 수 미달. N보다 많이 성장하면 상위 N개만 사용. 필요4개·목표8%에서 +20/+10/+1/+1은 통과하며 개별 종목마다8%일 필요는 없다. 자세한 알고리즘은 새 계획을 단일 기준으로 삼는다. 코드 미적용.
- 사용자 확정: **개노답→꿈틀러→시동러까지는 XP만으로 진화**, 시동러→꾸준러가 될 때부터 새 조건 적용. 유산소 트레드밀·사이클도 같은 시간에 더 멀리/같은 속도로 더 오래 한 성과를 성장에 포함. 인터벌 맨몸 블록은 제외. 유산소 비교 조건과 데이터 누락 처리도 새 계획에 명시했다. 코드 미적용.
- 추가 확인: `src/lib/progression.ts`가 본인·크루의 실제 서버 단계를 무시하고 XP로 단계를 재계산한다. `src/lib/level-growth.ts`도 XP 레벨의 단계 진입 시각을 사용한다. 단계 보류를 도입할 때 실제 단계·진입 이력 기준으로 함께 바꿔야 한다.
- 이번 후속 작업의 변경은 계획·인수인계·PROGRESS 문서뿐이다. DB 변경·운영 배포·푸시·알림 발송 없음. 다음 작업은 새 계획 Task 1(남은 마무리 검증).

## 11. 실제 구현 1차 — 평균·유산소·초기 XP 안내 (2026-11-13)

앞선 §5~10은 당시 기록이다. 최신 구현 상태는 이 절과 후속 구현계획의 실행 기록을 따른다. 기준 커밋 `1d38ce6`에서 아래 코드와 이 문서를 함께 커밋한다.

- `level-growth.ts`의 `computeEvolutionGrowthScore`: 상위 N개·고정 N분모·부족분0·실제 성장 수 조건. 같은 종목의 다른 지표로 N을 중복 채우지 않는다. M도 종목 이름으로 중복 제거.
- `cardio-growth.ts`: 같은 시간의 최고 거리, 같은 원본 속도의 최장 시간을 기준으로 성장 비교. 한 세션의 같은 종목은 합산하며 미완료·거리/시간 누락은 부풀려 합산하지 않는다. 같은 종목은 거리/시간으로 두 표를 받지 않는다. 유산소 원본을 수정하지 않는다.
- `evolution-gate.ts`: 시동러까지XP, 꾸준러 진입부터 N·평균 초안 미리보기. 수치는 아직 운영 확정값이 아니다. `level-growth-card`에 평균/성장filled/N/선택종목/빈자리0%·유산소 거리/시간 근거 표시. '현재 진화는 경험치 기준'이라고 정확히 안내.
- `domain/evolution.ts`는 목표2·3단계에 습관·성장 조건을 요구하지 않는다. 새 카드 플래그ON에서 옛 중앙값·3중조건 안내를 실제 서버 규칙처럼 표시하지 않게 정리했다.
- `progression.ts`의 본인/크루 프로필, `friend-board.ts`·`friends.ts`의 홈 크루는 서버 실제 단계로 이름·이미지를 표시한다. 레벨만 XP로 계산. 성장 조회도 실제currentStage를 받으며 요청 상태 키에 포함한다. **실제 진화 시각의 서버 이력/고정 기준은 아직 없음**(현재는 기존 레벨 이력을 읽음).
- 운영 읽기 전용 분석: 7명 진행도 조회 전후 일치. 오뎅끼데스까는 유산소1종목 포함 성장7종목·M19·N4·평균15.9023%. [분석표](evolution-gate-simulation-2026-11-13.md). 현재 구간 참고값이며 전체 진화 조건을 통과했다는 뜻은 아니다.
- 직접 Chrome 조작: 헬스장주주(꿈틀러Lv.10)의 시동러 안내에 XP만 표시되고 기존18일/6주/5일더 문구 없음. 실제 컴포넌트의 개발용 예시에서3/4=평균6%·빈자리0,4/4=평균8%, 목록3→4 펼침, 트레드밀30분3km→3.3km+10%와 조건불일치 문구를 확인. QA페이지는 검사 뒤 제거(최종build에 없음). 실제 운동/XP/알림은 만들지 않았다.
