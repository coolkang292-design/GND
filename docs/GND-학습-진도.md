## 모르는 말 수집 노트

작업 중 AI가 못 알아들을 말을 하면 **단어만 적지 말고 문장을 통째로** 적는다. 문맥이 빠지면 나중에 못 푼다.

**커리큘럼보다 이게 우선한다.** 실제로 막힌 문장이 가장 좋은 교재다.

| 날짜 | AI가 한 말 (그대로) | 관련 회차 | 풀었나 |
|---|---|---|---|
| 2026-08-11 | "RLS 정책 때문에 anon 키로는 조회가 안 됩니다" (예시) | 8 | ☐ |
| 2026-08-14 | "`autostart_due_challenges()`가 `start_date` 도래분을 자동으로 `active`로 바꿉니다" | 8·10 | ☑ DB 함수 = DB 안에 사는 판정 코드. 크론과 화면 진입 두 곳에서 부른다 |
| 2026-08-14 | "이 `Record`는 exhaustive가 아니라 유형을 늘려도 컴파일러가 안 잡아주고 `/home`으로 조용히 떨어집니다" | 3·10 | ☑ 컴파일러 = 앱 만들기 전 훑어보는 검사기. exhaustive = 모든 경우를 적었는지 검사기가 확인해 줌. 이 자리는 확인을 **안 해 주므로 사람이 손으로 챙겨야 한다** |
| 2026-08-14 | "화면 코드만 건드리므로 로직은 무변경입니다" | 2·3 | ☑ 화면 코드 = 무엇을 보여줄지(글자·색·버튼) / 로직 = 무엇을 계산·저장할지(점수·순위·날짜). 화면만 고치면 최악이 "글자가 어색하다" |
| 2026-08-14 | "앱과 DB의 판정이 갈리면 '열렸어요' 푸시를 받고 들어갔는데 자물쇠가 걸린 막다른 길이 됩니다" | 8·10 | ☑ 같은 규칙이 앱과 DB 두 곳에 적혀 있을 때 **한쪽만 고치면 사고**. `viewing-pass.ts:141`에 실제 경고가 있다 |
