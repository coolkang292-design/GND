# SNS 유입 이탈 원인 — 제1원리 분석 (Issue #2)

- 작성: 2026-10-11 (KST)
- 대상: 운영본 `origin/main` = `242c680` (운영 `https://gnd-one.vercel.app`)
- 근거: 운영 Supabase **읽기 전용** 조회 + 운영 화면 직접 조작(모바일 375px) + 운영본 코드
- 변경: **없음** (코드·DB·설정·배포 모두 그대로)
- 선행 문서: `docs/qa/social-oauth-onboarding-test-plan-2026-10-08.md`
  (브랜치 `docs/qa-install-gate-funnel-20261008`)

> 한 줄 결론: **사람들은 "OAuth가 고장 나서" 떠난 게 아니라, 앱이 무엇인지 보기도 전에
> 가입을 두 번 요구받고 버튼조차 가려진 화면을 봐서 떠났다.** 그리고 "유튜브 쇼츠 유입
> 13명"은 사람이 아니라 대부분 링크 검사 봇이다.

---

## 1. 문제의 본질

**핵심 문제:** 숏폼을 보고 호기심으로 들어온 사람이 *첫 1~3초 안에* "이게 뭐고 나한테
뭘 해 주는지"를 보지 못한 채 가입을 강요받는다.

**성공 기준:** 낯선 사람(지인 아님)이 SNS에서 들어와 **첫 운동 1회를 기록**한다.
정식 가입은 그 *뒤의* 일이다.

---

## 2. 사실 — 지표를 다시 셌더니 그림이 바뀌었다

### 2.1 "유튜브 쇼츠 유입 13명"은 사람이 아니다 `[확인]`

`source=youtube` 랜딩 13건의 세션 User-Agent를 특징만 분류했다(원문·IP 미노출).

| 묶음 | 건수 | 특징 | 판정 |
|---|---:|---|---|
| Windows PC 크롬 | 10 | **같은 초에 2건씩** 5쌍, 쌍마다 크롬 버전이 다름(109·150~153), Windows 7/10 혼재 | 자동 링크 검사기 `[추정]` |
| Linux 모바일 크롬 + `Google-Safety` 토큰 | 3 | Google 인프라 IP 대역 | **구글 안전검사 봇** `[확인]` |
| 아이폰·안드로이드 사람 | **0** | — | — |

캠페인명(`psr_b_park_comment_1004` 등)을 보면 링크를 **쇼츠 설명·댓글**에 넣었다.
유튜브는 2023-08부터 **쇼츠 설명·댓글 링크를 클릭 불가**로 바꿨다(외부 보도 기준,
현재 상태는 실물 확인 필요). 그러니 사람은 그 링크로 못 들어오고, 검사 봇만 들어온다.

→ **유튜브 쇼츠 경로의 "이탈률"은 측정된 적이 없다.** 쇼츠를 보고 온 사람이 있다면
주소를 직접 쳐서 들어왔고, 그래서 **출처 미표시**로 잡혔다.

### 2.2 진짜 사람 방문은 "출처 미표시"에 있다 `[확인]`

2026-10-04 20:54~20:56, **3분 사이에 사람 폰 7건**(안드로이드 크롬 4, 안드로이드 인앱 1,
iOS 웹뷰 1, iOS 사파리 1)이 출처 없이 들어왔다. 게시 직후의 실제 반응으로 보인다.
**7건 모두 온보딩 화면을 봤고, 가입 버튼을 누른 사람은 0명이다.** 세션 토큰이 한 번도
갱신되지 않았다 — 1시간 안에 떠났고 돌아오지 않았다.

### 2.3 9/15 이후 랜딩 전체를 사람/봇으로 나누면 `[확인]`

| UA 종류 | 랜딩 | 온보딩 표시 | 가입 버튼 클릭 | 정식 전환 |
|---|---:|---:|---:|---:|
| 안드로이드 크롬 | 17 | 16 | **0** | 0 |
| iOS 사파리 | 14 | 11 | **0** | 0 |
| iOS 크롬 / 기타 iOS 웹뷰 | 6 | 6 | 0 | 0 |
| **인스타 인앱** | 6 | 6 | **3** | **1** |
| 카카오톡 인앱 | 4 | 2 | 0 | 1 (기존 사용자) |
| 스레드 인앱 | 2 | 2 | 0 | 0 |
| PC (대부분 운영자·봇 추정) | 46 | 40 | 2 | 0 |
| 봇 (`Google-Safety` 등) | 18 | 7 | 0 | 0 |

- **클릭 자체가 거의 없다.** 사람 폰 약 50건 중 클릭 3건(전부 인스타 인앱).
  `identity_link_started`는 리다이렉트 직전 fire-and-forget이라 일부 유실될 수 있지만,
  유실됐더라도 OAuth가 성공했다면 `is_anonymous=false`로 남아야 하는데 그것도 없다.
  → **"눌렀는데 실패"보다 "안 눌렀다"가 압도적**이다.
- 인스타 클릭 3건: 1건 성공(9/19, 카카오) · 1건은 이슈 작성 시각(10/08 14:03)과 겹쳐 운영자
  테스트로 보임 · **1건(9/20 00:03)은 낯선 사람이 누르고 돌아오지 못함** — 제공자 미기록.
- 서비스 시작 이후 정식 프로필은 9개, 그중 SNS 출신은 **9/19의 1명뿐**이고 그 사람도
  운동 기록 0건이다.
- 인증 감사로그(`auth.audit_log_entries`)는 비어 있어 OAuth 왕복 단계를 서버에서 볼 수 없다.

### 2.4 신규 모바일 방문자가 실제로 보는 화면 `[확인 — 운영 화면 직접 조작]`

1. 시작 스플래시(1.5초) → `/record` → `/onboarding`으로 튕김
2. **첫 화면 = "먼저 로그인해 주세요 / 홈 화면에 놓기 전에 딱 한 단계예요" 시트.**
   카카오·구글 버튼을 **완전히 덮는다.** 밑의 화면은 어둡게 가려져 있다.
3. 시트의 유일한 버튼 "계정 연결하러 가기" → **`/account`** 로 이동.
   거기 보이는 것: *"계정 지키기 — 브라우저 데이터를 지우면 기록·XP·배지에 다시 접근할 수
   없어요"* 와 *"내 데이터 삭제 요청"* 버튼. 기록이 하나도 없는 사람에게 설정 화면이 뜬다.
4. 시트를 ✕로 닫아야 비로소 원래 온보딩이 보인다:
   *"지금 이 도전이 / 더 나은 나를 만든다"* + 카카오로 시작하기 + 구글로 시작하기 + 로그인.
   **GND가 무엇을 하는 앱인지 설명하는 문장이 없고, 가입 말고 갈 길이 없다.**

### 2.5 인스타 인앱에서 구글 버튼은 막다른 길일 가능성이 높다 `[외부 근거, 실기기 미검증]`

구글은 2021년부터 임베디드 웹뷰에서의 OAuth를 `403 disallowed_useragent`로 차단한다.
인스타 인앱 브라우저에서 같은 오류가 난다는 개발자 보고가 여럿 있다. 운영본은 인앱에서도
구글 버튼을 그대로 보여준다(`enabledProviders()`에 환경 분기 없음). 이 오류는 **구글
페이지에서** 나서 우리 콜백에 돌아오지 않으므로 `identity_link_failed`로도 안 잡힌다.
카카오는 인앱에서 동작하지만, 카톡 앱 세션이 없어 **아이디·비밀번호를 직접 쳐야** 할 수 있다.

## 4. 바닥 진실 (더 쪼갤 수 없는 것)

1. 숏폼 시청자의 의도는 약하다. 링크를 연 순간의 호기심은 **몇 초**다.
2. 가치를 보기 전의 단계 하나하나가 사람을 깎는다. 가입·외부 로그인·설치는 각각 큰 단계다.
3. 사람은 **자기가 원하지 않은 일**("홈 화면에 놓기")을 위한 요청에 응하지 않는다.
4. 인앱 브라우저는 일반 브라우저가 아니다 — 구글 로그인 차단, 카카오 로그인 세션 없음.
5. 측정하지 않은 단계의 이탈은 원인을 모른다 — 지금은 시트 노출·닫기, 제공자별 결과가 없다.
6. GND의 가치(친구와 함께, 안 하면 GND 확정)는 **기록을 한 번 해 봐야** 체감된다.

## 5. 추론 사슬

```
숏폼 호기심(몇 초)
  → 첫 화면이 "로그인하세요 + 홈 화면 설치" 시트 (원하지 않은 요청, 버튼도 가려짐)
  → 닫아도 뭘 하는 앱인지 모른 채 카카오/구글 가입만 가능
  → 인스타 인앱에서는 구글이 막히고 카카오는 비밀번호 입력
  → 거의 전원이 누르기 전에 떠남 (사람 폰 ~50 중 클릭 3)
```

여기에 측정 착시가 겹쳤다: 쇼츠 링크는 사람이 못 누르는데 봇은 눌러서,
"유튜브 13명 전원 이탈"이라는 **존재하지 않는 코호트**가 생겼다.

## 6. 결론과 처방 (우선순위 순, **전부 승인 전 제안**)

### P0-1. 신규 익명 방문자에게 자동 시트를 띄우지 않는다
`decideGuide`에서 `!linked`이면 자동 노출은 `none`, 수동(내 정보 탭)에서만 `login-first`.
`/onboarding`·`/login`·`/auth/callback`에서는 어떤 자동 시트도 띄우지 않는다.
08-21의 원칙("앱을 못 본 사람은 안내를 안 듣는다")으로 되돌리는 것이다.
**가장 작고 되돌리기 쉬운 수정이고, 버튼을 가리는 문제를 바로 없앤다.**

### P0-2. "먼저 써 보고 나중에 가입" — 이미 있는 기반을 화면에 연결한다
익명 계정에게도 **닉네임 → 첫 운동 기록**을 허용하고, 카카오·구글 연결은
"기록을 지키려면" 시점(첫 운동 완료 화면, 초대·크루·챌린지 생성 시 0094 안내)으로 미룬다.
`linkIdentity`가 같은 UID를 승격하므로 기록은 그대로 따라간다.
⚠️ 위험: 익명으로 남은 채 브라우저를 지우면 기록을 잃는다 → 첫 운동 직후 연결 권유로 보완.
⚠️ 챌린지 초대 링크 흐름은 지금처럼 가입 우선을 유지할지 별도 판단.

### P0-3. 인앱 브라우저에서 구글 버튼을 숨기거나 바꾼다
인스타·스레드·페이스북 인앱에서는 카카오만 보이거나, 구글을 누르면 "사파리/크롬에서 열기"
안내로 보낸다. **실기기로 403 재현부터** 한다(계획서 S04).

### P1-1. 첫 화면이 "무엇을 하는 앱인지" 한 문장으로 말한다
예: "친구와 운동 인증하고, 안 하면 콕 찔려요." 실제 기록 화면 미리보기 1장.

### P1-2. 측정을 고친다
- 유입 링크를 **쇼츠 설명·댓글이 아니라** 채널 링크·프로필 링크·고정 장편 영상 설명 등
  클릭되는 곳에 두고, 쇼츠에는 **기억하기 쉬운 짧은 주소**(예: `/s`)를 화면 자막으로 넣어
  그 경로 자체가 출처가 되게 한다.
- `landing_opened`에 봇 필터(`Google-Safety`·같은 초 쌍·데스크톱)를 집계 단계에서 적용.
- 시트 노출/닫기, 제공자별 클릭·콜백 결과(허용 목록의 짧은 코드만)를 기록.

## 7. 아직 모르는 것 `[미검증]`

- 인스타 iOS 인앱에서 구글 OAuth가 실제로 403으로 막히는지 (실기기 S04)
- 인스타 인앱에서 카카오가 끝까지 되는지, 콜백 후 세션이 유지되는지 (S03)
- 9/20 인스타 클릭 1건이 어느 제공자였고 어디서 끊겼는지 (로그 보존 기간 지남)
- Windows 크롬 쌍 10건의 정체 (봇 추정 근거는 같은 초 쌍·버전 난수·PC — 확정 아님)
- 쇼츠 설명 링크가 2026-10 현재도 클릭 불가인지 (실물 확인 필요)

## 8. 이 분석이 남긴 흔적

운영 화면을 모바일로 열어 확인하면서 **익명 계정 1개와 `landing_opened`·`onboarding_started`
이벤트(출처 없음, 안드로이드 크롬)** 가 운영 DB에 1건씩 생겼다. 그 과정에서 `login-first`
시트의 버튼을 눌러 해당 브라우저에 닫기 이력 1회가 남았다. 다른 데이터는 건드리지 않았다.
