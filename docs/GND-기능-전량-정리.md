# 1부 · 사업 판단에 필요한 것

## 1.1 지난 5일에 제품의 성격이 바뀌었다

초판(8/12) 시점의 GND는 **기록 도구 + 소셜 챌린지**였다. 8/12~8/16 사이에 다음이 들어오면서 **처방하는 코치**로 이동했다.

| 들어온 것 | 전략적 의미 |
|---|---|
| 공식 6주 프로그램 6종 (18회차 달력 일괄 등록) | "무엇을 할지"를 앱이 정해 준다 — 기록 앱의 최대 이탈 지점(빈 화면) 제거 |
| 자동 무게 추천 + 노력 피드백 + 자동 증량 | 회차가 지날수록 개인화된다 — **사용할수록 갈아타기 비용이 오르는 구조** |
| 계획 없는 날 운동 제안 (알림 → 원탭 시작) | 앱을 열 이유를 앱이 만든다. 리텐션 장치 |
| 알림 시각 개인화 (평소 운동 30분 전) | 전원 09시 → 개인별. 푸시 반응률의 직접 변수 |
| 홈 통합 카드 · 챌린지 CTA 재배치 | 운동할 이유와 수단 사이의 카드 5개 제거 |

**사업적으로 왜 중요한가.** 운동 기록 앱은 기능 차별화가 거의 불가능하다(모두가 세트·무게·달력을 갖고 있다). 반면 **처방과 코칭은 유료화가 성립하는 가치**다. 이 5일의 작업으로 GND는 유료화 가능한 축을 하나 확보했다.

## 1.2 제품 한 줄과 포지셔닝

> **소규모 친구 그룹이 6주 프로그램을 같이 돌고, 서로의 기록이 보이는 상태에서 순위를 겨루는 앱.**

| 축 | GND의 선택 | 흔한 대안 |
|---|---|---|
| 사회적 범위 | **상호 수락한 소수 친구** (폐쇄형) | 공개 피드 / 팔로우 |
| 정보 공개 | **진행 중엔 남의 성과가 잠긴다.** 5일 연속 운동해야 열람권 | 항상 전체 공개 |
| 동기 부여 | 캐릭터 7단계 진화 + 배지 30종 + 스트릭 소멸 | 숫자 그래프 |
| 운동 처방 | **6주 프로그램이 달력에 통째로 꽂힌다** | 종목 검색만 |
| 톤 | 유머·자조 ("개노답 → 전설이개") | 진지한 피트니스 |

**핵심 차별점은 "정보 희소성"이다.** 남의 성과를 보려면 내가 5일을 채워야 한다. 이건 운동 앱에서 거의 안 쓰이는 장치이고, 소셜 기능이 있는 앱들이 겪는 "관음만 하고 운동은 안 하는 사용자" 문제를 구조적으로 막는다.

## 1.3 리텐션 엔진 — 사람을 붙잡는 장치 8개

사업 기획에서 가장 중요한 절이다. 각 장치가 **어느 이탈 지점을 막는지**로 정리했다.

| # | 장치 | 막는 이탈 | 구현 |
|---|---|---|---|
| 1 | **스트릭 소멸 카운트다운** (5일) | "며칠 쉬었더니 그만두게 됨" | ✅ D-4~D-1 경고 + 문구 로테이션 |
| 2 | **개인화 알림** (평소 운동 30분 전) | 앱을 열 계기 없음 | ✅ pg_cron 30분 슬롯 |
| 3 | **계획 없는 날 제안** (원탭 시작) | 빈 화면 앞에서 멈춤 | ✅ 걷기/지난 운동/인터벌 3분기 |
| 4 | **6주 프로그램** (18회 달력 등록) | "뭘 해야 할지 모름" | ✅ 6종 |
| 5 | **자동 증량** (노력 피드백 기반) | 정체감 | ✅ 첫·마지막 세트 피드백 |

# 2부 · 기능 전량

## 2.1 계정 · 신원

| 방식 | 상태 | 비고 |
|---|---|---|
| 익명 인증 | ✅ | 앱을 켜면 즉시 계정 생성 — **가입 마찰 0** |
| 카카오 · 구글 | ✅ | 익명 계정에 **신원을 덧붙인다**. 기록·XP·배지 유지 |
| 이메일 + 비밀번호 | ✅ | 소셜이 막혔을 때의 탈출구 |

- 제공자는 환경변수로 on/off — **fail-closed** (값이 없으면 버튼이 사라진다)
- **로그아웃은 신원이 붙은 계정만.** 익명이 나가면 계정을 영영 못 찾으므로 문 자체를 잠근다
- 닉네임 유니크 제약 · 이모지 아바타 9종 · 주간 목표

> **사업 시사점:** 가입 마찰 0은 초기 획득에 유리하지만, **익명 계정은 재방문 측정과 마케팅 어트리뷰션이 불가능하다.** 유료화 시점에는 소셜 연결을 온보딩에서 강제해야 한다 (이미 첫 화면이 소셜 두 버튼이므로 구조는 준비됨).

**상태: ✅ 운영 중**

## 2.3 공식 6주 프로그램 ⭐ 신규

이번 개정의 핵심이다.

### 프로그램 6종

| 키 | 부제 | 제목 | 시간 |
|---|---|---|---|
| `shoulder-frame-6w` | 시선이 머무는 어깨 | 상체의 틀을 넓히는 6주 | 50~65분 |
| `chest-frame-6w` | 티셔츠 핏을 살리는 가슴 | 두껍고 탄탄한 상체를 만드는 6주 | 50~65분 |
| `arm-outline-6w` | 반팔이 달라지는 팔 | 두께와 윤곽을 동시에 만드는 6주 | 50~65분 |
| `lower-balance-6w` | 몸의 기반을 만드는 하체 | 강하고 균형 잡힌 하체를 만드는 6주 | 50~65분 |
| `lean-body-6w` | 살은 빼고, 몸은 선명하게 | 근육은 지키면서 체지방을 낮추는 6주 | 50~65분 |
| `interval-burn-6w` | 짧고 굵게 태우는 전신 | 기구 없이 4분부터 시작하는 6주 | 4~16분 |

- 각 프로그램은 **A·B·C 세 회차**를 6주간 순환 → **총 18회차**
- 근력 5종 합계: **15회차 · 77개 처방 · 27개 고유 종목** (전부 테스트·스냅샷으로 고정)
- 처방에 담기는 값: 종목 순서 · 세트 · 반복 · **RIR** · 휴식 · 증량 단위
- **전신 기본 운동은 유지하고 목표 부위 비중을 높이는** 구조 (3분할이 아닌 이유는 §4.3)

| **주차** (1~6주) | **길이**를 정한다 |

| 난이도 | 주차별 길이(분) |
|---|---|

| 보통 | 4 · 4 · 8 · 8 · 16 · 16 |

### 일정 등록

- 3단계: **시작일 → 요일·시간 → 18회 미리보기**
- **주당 횟수 2~5회 선택** (0073). 총 18회는 고정이고 기간이 늘거나 준다 (주 2회 ≈ 9주 / 주 5회 ≈ 4주)
- 기존 계획을 **덮지 않고** 대체안을 제안. 최종 확인 전에는 DB 변경 없음

- **프로그램 그만두기** (0071·0072)
- 등록 스냅샷은 `program_enrollments`에 남는다 — 프로그램 정의가 바뀌어도 등록 당시 처방이 보존된다 (`title_snapshot`, `program_version`)

## 2.4 프로그램 가이드 운동 ⭐ 신규

프로그램 회차를 실행할 때만 작동하는 층이다 (0067).

| 기능 | 내용 |
|---|---|
| **자동 무게 추천** | 지난 성공 기록에서 첫 세트 무게를 자동 입력. 수정 가능 |
| **무기록 종목** | 무게를 추측하지 않고 `목표 횟수 + 1~2회 여유`로 안내 |
| **노력 피드백** | **첫 세트와 마지막 세트에만** 묻는다 — `너무 가벼움 / 적당함·1~2회 여유 / 너무 무거움·자세 무너짐` |
| **피드백의 쓰임** | 첫 세트 답 → 오늘 남은 세트 무게 / 마지막 세트 답 → **다음 회차 추천** |
| **통증은 별도 경로** | `너무 무거움`으로 저장하지 않는다. 통증은 멈출 신호이지 "무게를 조금 낮추면 되는 일"이 아니다 |
| **닫기 = 모름** | 시트를 닫으면 값을 넣지 않는다. 사용자가 말한 적 없는 근거로 무게가 오르지 않게 |
| **진행률 보존** | 완료 시 프로그램 메타를 세션에 **복사**한다 — 계획 행을 지워도 "몇 회차까지 했는지"가 남는다 |
| **종목 안내** | 프로그램 상세의 회차 표에 짧은 설명 (26종). 외부 콘텐츠 복사·iframe 없음 |

> **사업 시사점:** 이 층이 GND의 **가장 유료화하기 좋은 자산**이다. 회차가 지날수록 개인 데이터가 쌓여 추천이 정확해지고, 갈아타면 그 축적이 사라진다. 무료-유료 경계선의 1순위 후보다.

**상태: ✅ 운영 중**

## 2.5 운동 기록 — 핵심 루프

### 진입 허브 4경로

운동 추가의 첫 결정을 4개로 줄였다.

| 경로 | 내용 |
|---|---|
| **프로그램으로 시작하기** | 공식 6주 프로그램 카탈로그 (인터벌 포함) |
| **운동 직접 고르기** | 검색 · 부위별 · 상황별 추천 |
| **지난 운동** | 과거 세션 통째로 복사 |
| **내 루틴** | 저장한 종목 묶음 (인터벌 코스도 기억, 0074) |

- 상황별 추천 — `처음 운동해요`는 **걷기 → 맨몸 스쿼트 → 푸시업 → 기구 2종** 순서. 기구가 없거나 헬스장에 등록 안 한 사람이 첫 칸에서 막히지 않게 (2026-08-14 수정)
- **자주 한 운동** 개인별 빈도 집계
- **직접 만들기** — 카탈로그에 없는 종목 생성
- 카탈로그 시드 **98종** (웨이트/유산소/맨몸 × reps/time 메타)
- **"이 운동은 챌린지에 안 잡혀요"** 사전 경고

### 세트 입력

- 유형별: 무게×횟수 / 거리(0.1km 단위) / 시간 / 맨몸 횟수
- 직전 기록 프리필 · 추천 세트 · 직전 값 복사
- **0kg 되묻기** — 맨몸운동 전환 제안
- **값 전파** — 1세트를 바꾸면 뒤의 **미완료** 세트에 전부 반영. 완료 세트는 안 건드린다

### 운동 중 화면

- 시작하면 **지금 세트 하나만 크게** 보여주는 전체화면
- `⇄ 운동 바꾸기` (세트 수 유지) · `↷ 이 종목 빼기` (완료분 있으면 확인) · 순서 변경
- `▾ 최소화 / 다시 열기` · 마지막 세트 응원 문구 · iOS safe-area 대응

### 타이머 3종

| 타이머 | 내용 |
|---|---|
| 휴식 | 사전설정 + **운동 중 ±10초**. 벽시계 기준. **5초 전 비프음** |
| 경과 | 총 운동 시간 |

## 2.7 계획 없는 날 운동 제안 ⭐ 신규

오늘 계획도 없고 운동도 안 한 사람에게, **각자의 알림 시각에 무엇을 할지 하나**를 보낸다.

| 조건 | 제안 |
|---|---|
| 이력 없음 + 가입 7일 이내 + 챌린지 밖 | **10분 걷기** |
| 이력 있음 | **지난 운동 그대로** |
| 지난 운동이 인터벌 / 챌린지 참가자 | **4분 인터벌** |

- 알림을 누르면 기록 탭이 **이미 담긴 채로** 열린다 (`/record?suggest=1`)
- 빈 화면에도 같은 제안을 **카드로** 낸다 (앱 아이콘으로 들어온 사람도 보게)
- 제안은 자정이 지나면 사라지고 **달력에 `예정`으로 남지 않는다**. 사용자가 직접 담은 것은 안 지운다
- **가입 7일 유예 창** — 이 창이 없으면 기록 0건 계정 전부가 매일 알림을 받는다. 가입만 하고 잊은 사람에게 영원히 가는 알림은 차단이나 삭제로 이어진다

> **사업 시사점:** 획득한 사용자를 **첫 운동까지 끌고 가는** 장치다. 활성화 퍼널의 최대 누수 지점(가입 → 첫 운동)에 직접 작용한다. 효과 측정 지표를 붙일 1순위.

**상태: ✅ 운영 중** (0078) · **[미검증]** `walk` 분기 실화면, 실기기 푸시 클릭

## 2.14 챌린지

### 방 · 참가

- **여러 개 동시 진행** · 닉네임 초대 또는 초대 링크
- 방 상태: `setup → active → ended` (또는 `cancelled`)

### ⭐ 세팅 시트 개편 (2026-08-14)

한 화면에 `주 N일`이 **두 개** 있어서 사람도 코드도 혼동했다. 섹션을 갈랐다:

| 섹션 | 무엇 | 점수 비중 |
|---|---|---|
| ① **내 운동 목표** | 종목 · 지표 · 기간 총 목표 · **하루 기준 계산기** | 달성률 **80%** |
| ② **참여 계획** | `주 N일` 하나. 종목과 무관한 '운동한 날' | 참여율 **20%** |
| ③ **현재 설정 요약** | `웨이트 480회` / `하루 40회 × 주 3일` | — |

- 계산기가 **기본 펼침**, 총 목표와 양방향 연동
- **목표 최대 3개** · `+ 목표 추가`가 안 쓴 분류부터 고른다
- 기간을 바꾸면 **하루 기준을 기준점으로** 총 목표가 재계산된다 (배포 직후 신고 1건으로 수정)

### 목표 유형 9종

웨이트 횟수 / 웨이트 운동일 / 유산소 거리 / 유산소 시간 / 맨몸 횟수 / 맨몸 시간 / 맨몸 운동일 / 타바타 횟수 / (레거시)총볼륨

### 랭킹 산식

```
각 목표 rate  = 실적 / 목표
achievement   = Σ min(rate, 1) × 100 / 목표개수   ← 평균(합 아님) + 100% 상한
participation = min(운동일 / 계획일, 1) × 100
overall       = achievement × 0.8 + participation × 0.2
```

- **평균**: 목표를 많이 잡은 사람이 유리해지지 않게 (개수 중립)
- **100% 상한**: 한 목표 300%로 다른 미달을 덮는 어뷰징 차단
- **동점 5단계**: ①달성률 ②참여율 ③선착 ④완료 목표 수 ⑤공동순위

### ⭐ 자동 시작 · 예고 · 탈락 통보 (2026-08-14)

- 챌린지는 **시작일에 자동으로 열린다** (동의 대기 없음). 화면이 이 사실을 숨기고 자물쇠를 그리던 것을 고쳤다 → `N월 N일에 자동으로 시작돼요 · 그때까지 목표를 세우지 않으면 이번 챌린지에선 빠져요`
- **시작 전날 예고** 신설 — 목표 유무로 문구가 갈린다
- **탈락 통보** 신설 — 옛 로직은 `dropped`로 바꾼 **뒤** `joined`에게만 알림을 보내, **목표를 안 세워 빠진 사람은 통보조차 못 받았다**
- 수동 `지금 바로 시작하기`는 남겼다 (시작일을 앞당기는 지름길)

### ❌ 바이럴 계수 — 지금 데이터로는 계산할 수 없다

`crew_links(user_a, user_b, created_at)`에 **출처 컬럼이 없다.** 검색으로 맺었는지,
초대 링크를 타고 왔는지, 챌린지 신입 자동 연결인지 **구분이 안 된다.**
`profiles.invite_code`는 발급만 기록하고 그 코드로 누가 왔는지는 남기지 않는다.

가짜 숫자를 만드는 대신, 대시보드는 **셀 수 있는 것만** 내고(연결 수 · 보유율 ·
1인 평균 · 발급률) **&ldquo;측정할 수 없다&rdquo;를 화면에 명시**한다.

**붙이려면:** `crew_links.origin`(`search|invite_link|challenge`) 컬럼 +
`accept_crew_request` · `accept_friend_invite` · `accept_challenge_invite`
**RPC 3곳**이 채우게 한다. 마이그레이션이 필요해 별도 스프린트다.

### ⚠️ 푸시 클릭도 계측이 없다

앱이 푸시 **클릭 이벤트를 수집하지 않는다.** `read_at`은 알림함에서 열어 봤다는
뜻이지 푸시를 눌렀다는 뜻이 아니다. 그래서 대시보드는 &ldquo;받은 날 운동&rdquo;
(상관)까지만 말하고 **`전환율`·`클릭률`이라는 단어를 쓰지 않는다.**
