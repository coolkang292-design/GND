# 인터벌 음원 제작 가이드 (2026-11-05)

내가 만든 음원을 GND 인터벌(타바타)에 넣기 위한 가이드다. **Claude 채팅(Abocado AI MCP)에서 음원을 만들 때 §3 프롬프트를 붙여 넣고, 완성 파일을 받으면 §5로 앱에 넣는다.**

## 1. 현재 세팅 현황 (실측)

| 항목 | 값 |
|---|---|
| 파일 | `public/audio/tabata-4min-total-body.mp3` (250.02초), `tabata-8min-total-body-v2.mp3` (500.02초), `tabata-16min-total-body-v2.mp3` (1000.04초) |
| 형식 | mp3, 48kHz, 스테레오, 약 256~262kbps |
| 음량 | 4분 원본 통합 -8.3 LUFS, 트루피크 +2.8 dBFS. 꽤 크게 눌린 음원이다. |

| 재생 | `src/components/record/tabata-sheet.tsx`의 HTML5 `<audio>`. 사용자 제스처 안에서 `play()`, iOS 무음 스위치를 무시한다. |
| 화면 동기화 | `src/lib/domain/interval-cue.ts`가 `audio.currentTime`만 보고 지금이 준비/운동/휴식인지 계산한다. 앱은 음원 소리를 듣지 않는다. |
| 종료 | `<audio>`의 `ended` 이벤트가 곧 운동 완료다. 파일 끝 = 세션 끝. |
| 8·16분 | 4분 원본을 이어 붙인 파일이다. 블록마다 인트로(준비 구간)가 반복된다. |

### 음원의 시간 구조 (한 블록 = 250.02초)

앱이 믿는 상수는 `interval-cue.ts`에 있다. `INTERVAL_PREP_SECONDS = 13`, 운동 20초, 휴식 10초, 라운드 8, 블록 250초.

| 구간 | 시작(초) | 길이 | 내용 |
|---|---|---|---|
| 준비 | 0 | 13 | 마지막에 "3·2·1" 멘트. 기존 음원은 멘트가 10.6~14.4초에 깔려 있다. |
| 라운드 1 운동 | 13 | 20 | 고강도 |
| 라운드 1 휴식 | 33 | 10 | 낮은 강도, 호흡 |
| 라운드 2 운동 | 43 | 20 | |
| … | 13 + 30×(n-1) | | 라운드 n 운동 시작. 라운드 8까지 |
| 라운드 8 운동 | 223 | 20 | |
| 라운드 8 휴식 | 243 | 7.02 | **마지막 휴식은 파일 끝에서 잘린다**(33 > 250.02). 정상이다. |

종목 전환 신호(운동→휴식 약 30.9~34.1초, 휴식→운동 약 41.1~44.9초 구간에 기존 멘트)가 박혀 있다. 새 음원도 **전환 직전 3~4초에 카운트다운 신호**를 넣어야 사용자가 눈 없이 따라간다.

## 2. 반드시 지킬 제약

1. **시작 13초 뒤에 첫 운동이 시작되어야 한다.** 이 값은 귀로 맞춘 상수라 약간 어긋나도 `INTERVAL_PREP_SECONDS`로 보정할 수 있다. 단 보정은 4·8·16분 전체에 똑같이 적용된다.
2. **운동 20초 / 휴식 10초가 정확히 반복되어야 한다.** 화면은 시계로 계산하므로 음악이 박자를 어기면 화면과 어긋난다. 라운드 8번이면 누적 오차가 쌓인다.
3. **4분 파일 길이 = 250.02초.** 테스트가 `250`을 단언한다(`interval-cue.test.ts`). 길이가 다르면 `INTERVAL_BLOCK_SECONDS`와 테스트를 같이 바꿔야 한다.
4. **8분 = 블록 2번, 16분 = 블록 4번 이음매 손실 11ms 이하.** 이음매 손실이 있으면 두 번째 블록부터 화면이 음악보다 앞서간다(2026-08-13에 4.98초 어긋난 사고).
5. **비트레이트는 약 256~262kbps CBR.** 파일 길이 테스트가 초당 32,800바이트로 크기를 추정한다(오차 5%). 낮은 비트레이트로 만들면 테스트가 깨진다.
6. **파일 이름은 새 버전으로.** 같은 이름으로 덮으면 브라우저·CDN이 옛 파일을 쓴다. 지금이 `v2`이므로 `v3`부터.
7. **끝 처리.** 파일이 끝나면 곧바로 운동 완료로 기록된다. 끝에 긴 무음이나 페이드 아웃 꼬리를 두지 않는다(마지막 휴식 7초가 곧 종료).
8. **권리.** 코드 주석이 "권리 확인된 사용자 제작 음원만"이라고 못 박는다. 생성 서비스의 상업적 이용 약관을 먼저 확인한다.

## 3. 채팅(Abocado MCP)에 붙여 넣을 제작 프롬프트

```
나는 운동 앱의 인터벌(타바타)용 배경음악을 만들고 싶어. 아래 구조를 지켜서 제작해줘.

[곡 정보]
- 스타일: (여기에 내가 원하는 스타일. 예: 힘찬 일렉트로닉, 하우스, 로파이 등)
- 가사 없음(보컬 없음) 인스트루멘탈. 신호음/카운트다운 멘트는 내가 따로 얹을 수 있게 비워둬도 됨.
- BPM: 120 (고정, 템포 변화 금지. 1박 0.5초라 13초=26박, 20초=40박, 10초=20박으로 딱 떨어진다)

[시간 구조 — 이 길이가 정확히 맞아야 해]
- 도입 13초: 점점 올라가며 끝나는 지점(13초)에서 첫 드롭/강한 시작
- 운동 구간 20초: 에너지 높음, 드럼 풀 편성
- 휴식 구간 10초: 에너지 낮춤(드럼 빼고 패드·베이스 위주), 호흡하는 느낌
- 운동 20초 + 휴식 10초를 8번 반복. 각 운동 구간이 시작할 때 박자가 정확히 떨어져야 해
- 전체 길이 250초. 마지막 휴식은 7초만 있고 끝나도 됨(자연스럽게 끝내지 말고 그냥 끝)
- 각 전환(운동→휴식, 휴식→운동) 3초 전에 짧은 상승음이나 필 인으로 곧 바뀐다는 신호를 줘

[요청]
1. 먼저 이 구조를 한 번에 만들 수 있는지, 길이와 BPM을 정확히 지정할 수 있는지 알려줘.
2. 한 번에 안 되면 구간별로 따로 만들어서 내가 ffmpeg로 이어 붙일 수 있게 쪼개줘:
   - (A) 도입 13초 1개
   - (B) 운동 20초 루프 1개
   - (C) 휴식 10초 루프 1개
   - 모두 같은 키, 같은 BPM, 앞뒤가 끊기지 않는 루프로
3. 크레딧이 드는 생성은 실행 전에 예상 크레딧을 알려주고 내 확인을 받아줘.
4. 완성한 파일은 mp3 또는 wav로 내려받을 수 있는 링크를 줘.
```

**권장: 구간별 생성(조립식)이다.** AI 음악 생성기는 250초를 박자 정확하게 한 번에 만들기 어렵다. 도입 13초, 운동 20초, 휴식 10초를 따로 만들어서 ffmpeg로 정확히 이어 붙이면 길이가 오차 없이 맞는다. **BPM은 120을 권장한다.** 1박이 0.5초라 13초=26박, 20초=40박, 10초=20박으로 구간이 박자에 정확히 맞는다. 128 같은 BPM은 20초가 42.67박이라 구간 경계에서 박자가 어긋난다.

## 4. 받은 파일을 4·8·16분으로 조립 (ffmpeg)

ffmpeg는 이 컴퓨터에 설치돼 있다.

### 4-1. 구간 파일로 4분 블록을 만들 때

파일 이름이 `intro.wav`(13초), `work.wav`(20초), `rest.wav`(10초)라고 하자. 먼저 길이를 정확히 자른다.

```bash
ffmpeg -i intro.wav -t 13 -ar 48000 -ac 2 intro13.wav
ffmpeg -i work.wav  -t 20 -ar 48000 -ac 2 work20.wav
ffmpeg -i rest.wav  -t 10 -ar 48000 -ac 2 rest10.wav
```

이어 붙일 목록을 만든다(운동+휴식 8번, 마지막 휴식은 뒤에서 7.02초로 자름).

```bash
{
  echo "file 'intro13.wav'"
  for i in 1 2 3 4 5 6 7 8; do echo "file 'work20.wav'"; echo "file 'rest10.wav'"; done
} > list.txt
ffmpeg -f concat -safe 0 -i list.txt -t 250.02 block.wav
```

### 4-2. 8분·16분으로 이어 붙이기

**mp3를 이어 붙이지 말고, wav 상태에서 이어 붙인 뒤 마지막에 한 번만 mp3로 인코딩한다.** mp3를 그대로 이으면 인코더 지연 때문에 이음매마다 시간이 빠진다.

```bash
# 8분 = 블록 2번
printf "file 'block.wav'\nfile 'block.wav'\n" > list8.txt
ffmpeg -f concat -safe 0 -i list8.txt -t 500.04 body8.wav

# 16분 = 블록 4번
printf "file 'block.wav'\nfile 'block.wav'\nfile 'block.wav'\nfile 'block.wav'\n" > list16.txt
ffmpeg -f concat -safe 0 -i list16.txt -t 1000.08 body16.wav
```

### 4-3. 음량 맞추고 mp3로 (CBR 256kbps)

기존 음원이 -8.3 LUFS였다. 새 음원이 너무 작거나 크면 운동 중 들리는 크기가 달라진다. 클리핑이 없게 -9 LUFS 근처, 트루피크 -1 dBTP 이하를 권한다.

```bash
ffmpeg -i block.wav -af loudnorm=I=-9:TP=-1:LRA=7 -ar 48000 -ac 2 -c:a libmp3lame -b:a 256k tabata-4min-total-body-v3.mp3
```

8분·16분도 같은 방식으로 인코딩한다. **음량 보정(loudnorm)은 블록 하나에 한 번만 적용해야 한다.** 이어 붙인 파일에 따로 적용하면 블록마다 다르게 보정될 수 있어서, 4분 블록의 wav를 먼저 음량 보정한 뒤 그 wav를 이어 붙이고 mp3로만 인코딩한다.

### 4-4. 만든 파일 검증

```bash
ffprobe -v error -show_entries format=duration,bit_rate -of default=nw=1 tabata-4min-total-body-v3.mp3
```

| 파일 | 기대 길이 |
|---|---|
| 4분 | 250.02초 (±0.05) |
| 8분 | 500.04초 |
| 16분 | 1000.08초 |

이음매 어긋남도 확인한다. 8분 파일의 250.02초 지점이 4분 파일의 시작(도입)과 같은 소리인지 귀로 듣는다.

## 5. 앱에 넣기

1. 새 파일을 `public/audio/`에 `-v3` 이름으로 넣는다.
   - `tabata-4min-total-body-v3.mp3`
   - `tabata-8min-total-body-v3.mp3`
   - `tabata-16min-total-body-v3.mp3`
2. `src/lib/domain/tabata.ts`의 `TABATA_TRACKS`에서 세 개의 `src`를 새 이름으로 바꾼다. 곡을 고를 수 있게 하려면 트랙을 추가하는 별도 작업이 필요하다(현재는 분수별로 트랙이 하나뿐이다).
3. 구조를 기존과 다르게 만들었다면 `interval-cue.ts`의 상수와 `interval-cue.test.ts`를 같이 고친다.
4. `pnpm dev`로 띄워서 4·8·16분 각각 끝까지 재생한다. 아래를 직접 본다.
   - 준비 카운트다운이 끝나는 순간 화면이 첫 종목을 시작하는가
   - 운동→휴식, 휴식→운동 전환이 음악 변화와 맞는가
   - 8분·16분의 두 번째·네 번째 블록에서도 어긋나지 않는가(블록 끝에서 특히)
   - 음원 끝에서 운동 완료로 이어지는가
5. `lint`, `typecheck`, 전체 `test`, `build`.
6. 사용자 승인 → 커밋 → 푸시 → 배포(`--scope gnd4`) → 프로덕션에서 파일 확인.
