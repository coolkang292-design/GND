# GND 인플루언서 데모 영상 도구

운영 중인 GND를 **픽스처 계정 두 개로 실제로 조작하며** 휴대폰 세로 화면(1080×1920)으로 녹화하고,
장면 표시대로 잘라 붙여 1분짜리 데모 영상을 만든다. **앱 코드는 한 줄도 바꾸지 않는다.**

> 원칙 (사용자 지시): 실제 GND 화면만 쓴다. 가짜 UI·목업·AI 생성 장면·과한 전환 효과는 쓰지 않는다.
> 편집은 컷과 짧은 자막, 마지막 문구뿐이다.

**자막을 기획안에서 바꾼 곳 두 군데**
- 1~3번 장면의 "친구와 챌린지를 만들고": 챌린지 만들기 장면을 추가하면서 넣었다.
- 12번 "운동하면 **기록**이 쌓이고"(원문: XP가 쌓이고): B가 2세트만 해서 XP가 지급되지 않았다(아래 §XP).

**영상에 넣지 않은 것**
- 새 챌린지의 "지금 바로 시작하기": 눌러도 오늘 운동이 집계되지 않는 문제가 있어(§발견한 문제 1) 누르지 않았다. 챌린지는 9월 15일 자동 시작.
- A의 오후 기록(침실·기내 사진, AI 연출 이미지로 보임)은 피드에서 스크롤하지 않아 화면에 거의 나오지 않는다.

## XP — 이번 녹화에서 안 나온 이유

XP는 **그날 첫 "유효" 운동**에만 준다(`complete_workout_v2` → `is_valid_workout`).
웨이트는 **완료 세트 3개 이상**, 유산소는 거리·시간 기록 1세트 이상이어야 유효하다.
B는 2세트만 해서 무효 → XP 0 → XP 창이 뜨지 않았다(버그 아님, 악용 방지 규칙).
**무효 운동은 그날 XP 기회를 쓰지 않는다** — `record.mjs`는 이제 3세트로 준비한다.

## 발견한 문제

1. **"지금 바로 시작하기"를 눌러도 오늘 운동이 집계되지 않는다** [미검증 — 코드·DB 기준, 화면 재현 안 함]
   - 증상: 챌린지 시작일은 내일부터만 고를 수 있다. 방장이 "지금 바로 시작하기"를 누르면 토스트가
     "🏁 챌린지 시작! 오늘부터 기록이 반영돼요"라고 하지만, 오늘 한 운동은 반영되지 않는다.
   - 근거: 운영 DB `start_challenge`는 `status`만 `active`로 바꾸고 `start_date`는 그대로 둔다.
     `src/lib/challenge.ts:962`가 시작일 이전 날짜를 버린다. `src/lib/domain/challenge-invite.ts`의 주석
     ("날짜와 무관하게 오늘 시작한다")도 실제와 다르다.
   - 재현: 챌린지를 만들고(시작일 내일) 전원 목표·동의 → 지금 바로 시작하기 → 오늘 운동 완료 → 진행률 0%.
   - 영향: 일찍 시작한 챌린지의 첫날 기록이 빠지고, 안내 문구와 실제가 다르다.
   - 수정: **안 함**(기획안이 DB 변경·기능 수정을 금지).
2. **알림 본문에 내부 코드값이 그대로 보인다** (화면 확인)
   - 증상: 알림함에 "근육은퇴근중님이 내 운동에 반응했어요 / **like**", "응원 📣 / **fire**·**power**".
   - 영향: 사용자에게 영어 코드가 노출된다(영상 14번 장면에도 보인다).
   - 수정: 안 함.
3. **운동을 시작·완료하면 크루 전원에게 자동 알림이 간다** — 픽스처가 실사용자와 크루로 연결돼 있으면
   데모 촬영이 실사용자 알림을 만든다. 버그라기보다 픽스처 구성 문제다.
4. (참고) 모든 화면에서 `analytics_events` POST가 **409**를 낸다. 화면에는 영향 없음 [미검증 — 원인 미조사].

## 다시 녹화하는 방법

```bash
cd tools/demo-video
npm install                      # playwright-core 1.62.1 (브라우저는 ms-playwright의 chromium-1234 재사용)
node login.mjs A                 # 창에서 사람이 로그인 (창 아래 파란 띠)
node login.mjs B                 # 〃 (빨간 띠)
node record.mjs prep             # B의 오늘 계획을 벤치프레스 55·60·60kg × 10으로 준비
node record.mjs                  # 녹화 → work/rec/<시각>/
node bursts.mjs work/rec/<시각> B m01-home m02-feed-tap ...   # 장면별 화면 변화 구간 → edit-plan.json 오프셋 조정
node thumbs.mjs work/rec/<시각> B "m01-home+1,m12-challenge+1" work/sheet.png   # 대표 프레임 확인
node edit.mjs work/rec/<시각>              # 본편 2개 + 원본 2개 (원본은 수십 분 걸린다)
node edit.mjs work/rec/<시각> --no-raw     # 본편만
```

⚠️ **`record.mjs`는 [미검증]이다.** 2026-09-14 영상은 `driver.mjs`(브라우저를 띄워 둔 채 한 단계씩 명령)로
화면을 확인하며 찍었고, `record.mjs`는 그때 통과한 선택자·순서를 옮겨 적은 것이다. 한 번에 끝까지 돌려 본
적은 없다. 처음엔 조종기로 단계를 확인하며 돌려라:

```bash
RUN=myrun node driver.mjs                      # 백그라운드로 켜 둔다 (A·B 1080×1920 헤드리스)
node drive.mjs A '[{"rec":"start"},{"goto":"/challenge"},{"mark":"c02-a-add-tap"},{"shot":"x"},{"snap":true}]'
```

재녹화 전 확인할 것
- **B가 그날 운동하지 않았는지**(XP 창은 첫 유효 운동에만), 새 챌린지 이름이 이미 있지 않은지.
- 진행률 장면용 챌린지(`DEMO_PROGRESS_CHALLENGE`, 기본 "9월 4주 챌린지")가 아직 진행 중인지 — 9월 26일에 끝난다.
- 피드 맨 아래·크루 목록에 실사용자가 비치지 않는지(`thumbs.mjs`로 전 장면 확인).

## 만들면서 겪은 함정 (다시 밟지 말 것)

- 헤드리스 screencast는 기기 배율 에뮬레이션만으로 **405×720**을 준다 → `--force-device-scale-factor`를 같이 준다(`lib.mjs`).
- screencast 프레임 간격(0.014~0.43초)을 ffmpeg concat에 그대로 넘기면 클립 길이가 ±2.7초 어긋나고,
  긴 정지 프레임을 한 줄 `duration`으로 두면 **fps 필터가 맨 앞 프레임을 버린다** → 1/30초마다 한 줄씩 풀어 쓴다(`screencast.mjs`).
- A·B 로그인 창을 같은 자리에 띄우면 겹쳐서 **B 프로필에 A가 로그인**된다 → 위치를 가르고 이름표를 단다(`login.mjs`).
- 이 폴더의 `.profiles/`·`work/`가 gitignore에서 빠지면 **Tailwind가 그 파일들을 훑어 CSS가 깨진다**(2026-09-14 `.next` 백업으로 실제로 겪음).
- Git Bash에서 `/home` 같은 인자는 윈도우 경로로 바뀐다 → `MSYS_NO_PATHCONV=1`.
